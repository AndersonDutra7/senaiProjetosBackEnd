01

Arquitetura REST: Recursos, Verbos HTTP, Status Codes e Boas Práticas

⏱️ Duração Estimada: 60 min

O REST (Representational State Transfer) é um estilo arquitetural para sistemas distribuídos que utiliza o protocolo HTTP para permitir a comunicação padronizada entre aplicações. Numa API RESTful, tudo é tratado como um recurso acessível via URIs claras e previsíveis.

1. Recursos e Nomeação de URIs

URIs devem utilizar substantivos no plural para representar coleções de dados, evitando verbos na rota (pois o verbo já é definido pelo método HTTP).

Prática Exemplo Incorreto (Anti-pattern) Exemplo Correto (RESTful)
Buscar lista de usuários /getUsuarios ou /listar_usuarios GET /api/v1/usuarios
Buscar usuário específico /buscarUsuario?id=12 GET /api/v1/usuarios/12
Buscar pedidos do usuário /getPedidosDoUsuario/12 GET /api/v1/usuarios/12/pedidos
Criar novo produto /cadastrarProduto POST /api/v1/produtos

2. Os Verbos HTTP e Operações CRUD

GET Leitura de Dados

Utilizado para consultar recursos. É seguro e idempotente (múltiplas requisições iguais geram o mesmo resultado sem alterar o servidor).

POST Criação de Recurso

Envia dados no corpo (payload) para criar um novo registro. Não é idempotente (múltiplas chamadas criam múltiplos registros).

PUT Substituição Total

Atualiza o recurso por completo. Caso o recurso não exista, pode criá-lo. É idempotente.

PATCH Atualização Parcial

Modifica apenas campos específicos de um recurso existente (ex.: alterar somente o e-mail do usuário).

DELETE Remoção

Exclui o recurso especificado pelo ID. É idempotente (deletar algo já deletado continua resultando na ausência do item).

3. Famílias de Status Codes HTTP

Classe Código & Nome Significado e Aplicação no Back-End
2xx Sucesso 200 OK / 201 Created / 204 No Content 200: Busca/Atualização concluída com sucesso.
201: Novo recurso criado via POST.
204: Operação realizada sem corpo de resposta (ex.: DELETE com sucesso).
3xx Redirecionamento 301 Moved Permanently / 304 Not Modified Indica que o recurso mudou de endereço ou que a versão em cache do cliente ainda é válida.
4xx Erro do Cliente 400 Bad Request / 401 Unauthorized
403 Forbidden / 404 Not Found / 422 Unprocessable Entity		 400: Sintaxe/JSON inválido.
401: Falta token de autenticação.
403: Usuário autenticado, mas sem permissão.
404: Rota ou ID não encontrado.
422: Falha nas validações de negócio/campos obrigatorios.
5xx Erro do Servidor 500 Internal Server Error / 502 Bad Gateway / 503 Unavailable Exceção não tratada no código Back-End, falha de comunicação com o banco de dados ou servidor sobrecarregado.
✨ Regra de Ouro do Design de APIs: Retorne respostas previsíveis e padronizadas em JSON contendo códigos de status semânticos. Nunca retorne 200 OK com uma mensagem no corpo contendo {"erro": "Usuário não encontrado"}!
02

Padrão MVC (Model-View-Controller) no Back-End

⏱️ Duração Estimada: 60 min

O MVC é um padrão de arquitetura de software que promove a Separação de Responsabilidades (Separation of Concerns - SoC), dividindo a aplicação em três camadas fundamentais. Isso evita o surgimento de "arquivos gigantes" onde rotas, regras de negócio e consultas ao banco ficam misturados.

📦 Model (Modelo)

A Camada de Dados e Regras de Negócio

  • Representa a estrutura de dados (tabelas/entidades).
  • Executa validações rígidas de dados.
  • Realiza consultas e persistência no banco (Queries SQL / ORM).
  • Independente da interface do usuário.
🎮 Controller (Controlador)

O Cérebro e Intermediário da Aplicação

  • Recebe a requisição HTTP enviada pelas Rotas.
  • Extrai parâmetros da requisição (query, params, body).
  • Chama os métodos do Model necessários.
  • Decide qual código de status e dados enviar de volta.
👁️ View (Visão)

A Camada de Apresentação de Dados

  • Em aplicações tradicionais: arquivos HTML/Templates (EJS, Handlebars).
  • Em APIs RESTful modernas: a View é a formatação do Payload JSON/XML devolvido ao cliente.

Fluxo Prático de uma Requisição no MVC:

1

Requisição do Cliente

O navegador/Mobile envia um POST /api/v1/produtos com dados de um novo produto no corpo em JSON.

2

Roteamento ➔ Controller

O roteador da aplicação intercepta a URL e direciona a execução para o método ProdutoController.criar().

3

Controller ➔ Model

O Controller aciona o ProdutoModel.salvar(dados), que valida as regras e insere a linha na tabela do banco de dados.

4

Resposta via View / JSON

O Controller recebe o objeto criado pelo Model e responde ao cliente com 201 Created e o JSON formatado.

💡 Vantagens do MVC: Manutenibilidade (alterar o banco não quebra a interface), reuso de código, facilidade na escrita de testes automatizados e trabalho em equipe simplificado (um dev ajusta o Model enquanto outro altera os Controllers).
03

Protocolos e Padrões de Comunicação Client-Side / Server-Side

⏱️ Duração Estimada: 60 min

A comunicação web é regida por protocolos bem definidos que determinam como mensagens trocadas na rede devem ser empacotadas, transmitidas e interpretadas entre o cliente (navegador, aplicativo móvel, sensores IoT) e o servidor Back-End.

🌐 Protocolo HTTP/HTTPS

Protocolo sem estado (stateless) baseado em requisição e resposta. O cliente inicia a comunicação e o servidor responde. A versão HTTPS adiciona uma camada de criptografia (TLS/SSL) protegendo dados sensíveis em trânsito.

⚡ Síncrono vs. Assíncrono

Síncrono (HTTP Request-Response): O cliente espera bloqueado até a resposta chegar.
Assíncrono (WebSockets / Mensageria): Comunicação bidirecional contínua em tempo real (ex.: chats, dashboards financeiros).

📦 JSON (JavaScript Object Notation)

O padrão soberano para troca de dados em APIs modernas por ser leve, legível por humanos e nativamente suportado por quase todas as linguagens de programação.

🔒 Segurança & CORS

CORS (Cross-Origin Resource Sharing): Mecanismo de segurança dos navegadores que bloqueia requisições vindas de domínios diferentes, a menos que o Back-End libere via headers HTTP específicos.

⚠️ Anatomia de uma Mensagem HTTP: Toda requisição/resposta possui Headers (metadados como Content-Type: application/json, Authorization: Bearer ) e Body (conteúdo real trafegado).
