01

Configuração do Ambiente Node.js, npm e Estrutura de Projeto MVC

⏱️ Duração Estimada: 60 min

O Node.js é um ambiente de execução JavaScript no servidor construído sobre o motor V8 do Chrome. Ele utiliza um modelo de E/S (Entrada/Saída) não-bloqueante e orientado a eventos, sendo ideal para construir APIs REST escaláveis e de alta performance.

1. Gerenciamento de Pacotes com npm

O npm (Node Package Manager) é o ecossistema de bibliotecas e o gerenciador de dependências nativo do Node.js.

1

Inicialização do Projeto

Comando: npm init -y
Gera o arquivo package.json, que atua como o "RG" do projeto, armazenando metadados, scripts e a lista de pacotes instalados.

2

Instalação de Dependências de Produção

Comando: npm install express dotenv pg
Bibliotecas necessárias para o funcionamento do sistema em ambiente final (ex: frameworks web, conectores de banco).

3

Instalação de Dependências de Desenvolvimento

Comando: npm install -D nodemon
Ferramentas utilizadas apenas durante a codificação (ex: leitores de auto-reload, formatadores), salvas na seção devDependencies.

2. Estrutura Profissional de Pastas MVC

Para manter o código limpo e escalável, organizamos a aplicação em uma estrutura física modularizada baseada no padrão MVC: 

meu-projeto-backend/
├── node_modules/         # Pacotes instalados (NUNCA versionar)
├── src/                  # Código fonte da aplicação
│   ├── config/           # Conexões de banco de dados e variáveis de ambiente
│   │   └── database.js
│   ├── controllers/      # Regras de fluxo da requisição e resposta
│   │   └── usuarioController.js
│   ├── models/           # Abstração de dados e consultas SQL
│   │   └── usuarioModel.js
│   ├── routes/           # Definição dos endpoints REST
│   │   └── usuarioRoutes.js
│   └── app.js            # Instância do servidor Express e Middlewares
├── .env                  # Segredos e variáveis de ambiente locais (NUNCA versionar)
├── .env.example          # Modelo público das variáveis sem valores sensíveis
├── .gitignore            # Arquivos ignorados pelo Git
├── package.json          # Configuração de dependências e scripts
└── server.js             # Ponto de entrada (Bootstrapping) da aplicação
💡 Boas Práticas de Bootstrap: Separe o app.js (onde os middlewares e rotas são registrados) do server.js (onde o servidor efetivamente escuta na porta Ex: app.listen(3000)). Isso facilita a escrita de testes automatizados sem ter que subir a porta do servidor.
02

Técnicas de Versionamento de Software — Git Colaborativo em Equipe

⏱️ Duração Estimada: 60 min

Em ambientes corporativos, múltiplos desenvolvedores trabalham simultaneamente na mesma base de código. O uso de **estratégia de ramificação (*branching model*)** garante que o código principal em produção permaneça sempre estável.

1. Modelo de Branches para Equipes (Git Workflow)

🚀 branch `main`

Código oficial em produção. Recebe apenas atualizações consolidadas e testadas. Deve ser protegida contra commits diretos.

🛠️ branch `develop`

Ambiente de homologação e integração contínua. É para onde todas as novas funcionalidades convergem antes de ir para produção.

✨ branches `feature/*`

Branches temporárias criadas a partir de develop para isolar o desenvolvimento de uma única funcionalidade (ex: feature/login-jwt).

2. Fluxo Colaborativo: Do Desenvolvimento ao Pull Request

1

Atualizar o repositório local

Sempre baixe as alterações mais recentes antes de iniciar: git checkout develop && git pull origin develop

2

Criar a branch de trabalho

Crie uma ramificação nomeada e específica: git checkout -b feature/cadastro-produtos

3

Commits atômicos & Push

Desenvolva em pequenas etapas, commite e envie para o repositório remoto: git push origin feature/cadastro-produtos

4

Abertura de Pull Request (PR) & Code Review

Abra um PR direcionando sua branch para a develop. Outro colega de equipe revisa o código, sugere melhorias e aprova o merge.

03

Boas Práticas de Organização do Repositório e Rastreabilidade

⏱️ Duração Estimada: 60 min

Um repositório profissional deve ser autoconsistente, seguro e de fácil navegação para qualquer novo desenvolvedor que entre na equipe.

1. Higiene do Repositório e `.gitignore`

Arquivos gerados automaticamente, senhas e módulos nunca devem ser enviados ao servidor Git:

🚫 Exemplo do arquivo `.gitignore` obrigatório: 

# Dependências
node_modules/

# Variáveis de ambiente e segredos
.env
*.pem

# Logs de execução
npm-debug.log*
logs/

# Arquivos de sistema/IDE
.DS_Store
.vscode/

2. Padronização de Commits (Conventional Commits)

Prefixo Finalidade Exemplo Prático
feat: Nova funcionalidade adicionada feat: adiciona rota POST /produtos para cadastro
fix: Correção de bug/erro existente fix: corrige erro 500 no login com email inexistente
docs: Alteração na documentação docs: atualiza instructions do README com comandos de setup
refactor: Mudança de código sem alterar regra/comportamento refactor: isola conexao do PostgreSQL no modulo database.js

3. Rastreabilidade com `.env.example` e `README.md`

O arquivo README.md é o cartão de visitas do projeto. Ele deve conter a instrução de instalação, pré-requisitos, variáveis necessárias (listadas sem senhas reais no .env.example) e passos para rodar o projeto.

🛠️ Atividade Prática Integrada — Setup do Repositório do Projeto (Em Duplas)

Cenário: Cada dupla/equipe fará o setup oficial do ambiente Node.js e a inicialização do repositório Git colaborativo para o projeto do curso.

Passo a Passo do Exercício:

  1. Setup do Node.js: Crie a pasta do projeto, execute npm init -y, instale o express e o nodemon (como dev).
  2. Estruturação MVC: Crie a estrutura de pastas física (src/controllers, src/models, src/routes, src/config).
  3. Higiene & Proteção: Crie o arquivo .gitignore ignorando node_modules/ e .env. Crie um arquivo .env.example.
  4. Git Colaborativo: Inicialize o Git (`git init`), crie a branch `develop`, e a partir dela crie uma branch `feature/setup-inicial`. Faça o primeiro commit no padrão Conventional Commits (`feat: setup inicial da estrutura mvc e dependencias`).
