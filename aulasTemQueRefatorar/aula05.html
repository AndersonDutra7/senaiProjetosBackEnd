Node.js: Runtime, Módulos e Event Loop Aplicados ao Back-End

⏱️ Duração Estimada: 60 min

O Node.js permite executar JavaScript no lado do servidor. Diferente de servidores web tradicionais (como Apache ou IIS), que criam uma nova thread de memória para cada requisição recebida, o Node.js utiliza uma arquitetura baseada em thread única (Single-Thread) não-bloqueante orientada a eventos.

⚡ V8 Engine & Libuv

O Node.js combina o motor de execução V8 (Google Chrome) para compilar JS em código de máquina super-rápido com a biblioteca Libuv para gerenciar operações assíncronas de I/O de sistema.

🔄 Event Loop (Laço de Eventos)

Mecanismo central que monitora a fila de tarefas assíncronas. Quando uma operação pesada (leitura de arquivo, query SQL) é acionada, ela é delegada em segundo plano e seu retorno entra no Event Loop sem travar o servidor.

📦 Sistema de Módulos

Organização de código modularizada.
CommonJS (Padrão histórico): require() e module.exports.
ES Modules (Moderno): import e export.

🛠️ Módulos Nativos

Recursos embutidos essenciais do Node.js:
fs (File System), path (manipulação de caminhos), http (criação básica de servidores web) e crypto (criptografia).

Exemplo Comparativo: Código Bloqueante (Síncrono) vs. Não-Bloqueante (Assíncrono)

❌ Bloqueante (Evitar no Back-End): 

const fs = require('fs');

// Trava a execução do Node.js até terminar de ler o arquivo de 2GB
const data = fs.readFileSync('arquivo_gigante.txt');
console.log('Conteúdo lido!');
console.log('Próxima tarefa executada.');

✅ Não-Bloqueante (Assíncrono com Async/Await): 

const fs = require('fs/promises');

async function lerArquivo() {
  // Delega I/O para a Libuv e libera a thread do Node.js
  const data = await fs.readFile('arquivo_gigante.txt');
  console.log('Conteúdo lido!');
}

lerArquivo();
console.log('Próxima tarefa executada imediatamente!');
⚠️ A Regra do Event Loop: "Nunca bloqueie a Thread Principal!". Operações CPU-bound intensivas (como processamento de vídeo ou loops pesados de 10 bilhões de iterações) congelam o servidor para todos os outros usuários conectados.
02

Framework Express: Rotas, Middlewares e Servidor HTTP

⏱️ Duração Estimada: 60 min

O Express é o framework web minimalista, flexível e mais utilizado do ecossistema Node.js. Ele abstrai o módulo nativo http, fornecendo uma camada robusta para gerenciamento de Roteamento, Requisição (Request), Resposta (Response) e Middlewares.

1. O que é um Middleware no Express?

Middlewares são funções que têm acesso aos objetos de requisição (req), resposta (res) e à próxima função de middleware no ciclo de requisição-resposta (next). Eles funcionam como uma "linha de montagem".

1

Requisição HTTP de Entrada

O cliente envia uma requisição (ex: POST /api/v1/pedidos contendo dados em JSON e token no Header).

2

Middleware Global de Body Parser

app.use(express.json()) converte a string do corpo da requisição em um objeto JavaScript acessível via req.body e chama next().

3

Middleware de Autenticação / Segurança

Verifica se o token JWT é válido. Se incorreto, interrompe a execução retornando 401 Unauthorized. Se correto, anexa o usuário em req.usuario e chama next().

4

Controlador da Rota (Controller)

Recebe a requisição limpa e autenticada, chama a regra no Model, persiste no banco e retorna a resposta final res.status(201).json(...).

2. Tipos de Middlewares no Express

Categoria Sintaxe / Exemplo de Aplicação Propósito no Back-End
Global app.use(cors()) / app.use(express.json()) Executado em todas as requisições que chegam ao servidor. Configura CORS, parsers e logs.
Específico por Rota app.get('/admin', verificarAdmin, adminController) Executado apenas na rota indicada antes de chegar ao controller final (ex: validação de permissões).
Tratador de Erros app.use((err, req, res, next) => { ... }) Middleware especial contendo 4 parâmetros. Intercepta exceções lançadas na aplicação e padroniza respostas de erro 500.

3. Extração de Parâmetros de Entrada no Express

  • Route Params (`req.params`): Parâmetros obrigatórios na URL. Exemplo: GET /usuarios/:id ➔ const { id } = req.params;
  • Query Params (`req.query`): Filtros e paginação opcionais na URL. Exemplo: GET /produtos?categoria=tech&limit=10 ➔ const { categoria, limit } = req.query;
  • Request Body (`req.body`): Dados complexos enviados em formulários ou payloads JSON (POST/PUT/PATCH). Exemplo: const { nome, email } = req.body;

Recomendações Técnicas na Aplicação do Node.js e Express

⏱️ Duração Estimada: 60 min

Para construir uma aplicação Back-End pronta para ambiente de produção, certas práticas técnicas e de arquitetura de código são indispensáveis:

🛡️ 1. Segurança com Helmet & Rate Limit

Utilize o pacote helmet para configurar automaticamente headers HTTP de segurança (proteção contra Clickjacking, XSS) e o express-rate-limit para barrar ataques de força bruta.

⚡ 2. Tratamento de Exceções Assíncronas

Em rotas async/await, exceções não capturadas podem travar o servidor. Envolva os blocos em try/catch ou utilize bibliotecas como express-async-errors para repassar erros ao middleware central.

📂 3. Modularização de Rotas (`express.Router`)

Nunca concentre todas as rotas no app.js. Crie arquivos isolados na pasta src/routes/ e importe-os modularmente (ex: app.use('/api/v1/usuarios', usuarioRoutes)).

🌱 4. Isolamento de Variáveis de Ambiente

Portas de servidor, URLs de banco de dados e segredos JWT devem ser injetados via process.env.VAR_NAME carregados pelo pacote dotenv no início da aplicação.

✨ Exemplo de Middleware Central de Erros Profissional: 
// Deve ser registrado DEPOIS de todas as rotas no app.js
app.use((err, req, res, next) => {
  console.error(`[ERRO INTERNO]: ${err.stack}`);
  
  const statusCode = err.statusCode || 500;
  const message = err.message || 'Erro interno no servidor.';

  res.status(statusCode).json({
    sucesso: false,
    erro: message,
    timestamp: new Date().toISOString()
  });
});
🛠️ Atividade Prática Integrada — Servidor Express de Eventos com Middlewares (Em Duplas)

Cenário: Sua equipe deve construir um servidor Web em Express para um Sistema de Inscrições em Eventos de Tecnologia (`/api/v1/eventos`).

Requisitos Práticos da Atividade:

  1. Servidor e Middlewares Globais: Configure o servidor na porta 3000 com suporte a JSON (express.json()).
  2. Middleware Customizado de Log: Escreva um middleware global que imprima no console o método HTTP, a URL da requisição e o timestamp exato de cada chamada recebida.
  3. Middleware de Validação por Rota: Crie um middleware de validação para a rota POST /eventos que verifique se os campos titulo, data e vagas estão presentes no req.body. Caso falhe, retorne 400 Bad Request sem chamar o controller.
  4. Rotas e Respostas: Crie as rotas GET /eventos (retornando status 200 OK com array de eventos) e POST /eventos (retornando status 201 Created com o evento cadastrado).
  5. Tratamento de Erros: Configure o middleware centralizado de exceções para capturar erros e responder em padrão JSON.
