01

Instalação e Configuração do Banco de Dados PostgreSQL

⏱️ Duração Estimada: 60 min

O PostgreSQL é um dos SGBDs (Sistemas Gerenciadores de Banco de Dados) objeto-relacionais de código aberto mais avançados e confiáveis do mundo. Ele é conhecido por seu suporte completo às propriedades ACID, extenção de tipos (JSONB, GIS) e altíssima estabilidade para aplicações corporativas e industriais.

1. Passo a Passo de Instalação e Inicialização do Serviço

1

Instalação Local (Instalador Oficial ou Docker)

Option A (Nativo): Download do instalador oficial para Windows/Linux/macOS configurando a porta padrão 5432 e definindo a senha do superusuário postgres.
Option B (Docker Containers): Execução via linha de comando:
docker run --name pg-portal-b2b -e POSTGRES_PASSWORD=segredo123 -p 5432:5432 -d postgres:16-alpine

2

Arquivos Críticos de Configuração do Server

• postgresql.conf: Define a porta de escuta, conexões máximas (max_connections = 100), alocação de memória (shared_buffers) e nivel de log.
• pg_hba.conf (Host-Based Authentication): Controla as permissões de acesso por endereço IP, banco de dados e métodos de autenticação (ex: md5, scram-sha-256).

3

Criação do Banco de Dados e Usuário de Aplicação

Nunca utilize o superusuário postgres diretamente na sua aplicação Node.js. Crie um banco dedicado e um usuário de aplicação com permissões restritas.

⚠️ Boa Prática de Segurança (Princípio do Menor Privilégio): Crie roles/usuários separados para desenvolvimento e produção com privilégios apenas de SELECT, INSERT, UPDATE, DELETE nas tabelas do schema público, evitando conceder perfil de SUPERUSER para a API.
02

Tipos de Dados, Tabelas e Ferramentas de Administração (pgAdmin / psql)

⏱️ Duração Estimada: 60 min

Para administrar e interagir com o PostgreSQL, os desenvolvedores utilizam tanto interfaces gráficas (GUI) quanto ferramentas de linha de comando (CLI).

🖥️ pgAdmin IV (Interface Gráfica)

Ferramenta web-based rica para navegação visual em esquemas, criação visual de tabelas, execução de scripts com o Query Tool, importação/exportação de dados em CSV e monitoramento de sessões ativas do banco.

💻 CLI `psql` (Linha de Comando)

Utilitário nativo de terminal, extremamente leve e rápido. Essencial para automações, servidores sem interface gráfica (Headless Linux) e execuções em esteiras CI/CD de produção.

Comandos Essenciais da CLI `psql`

Comando psql Descrição e Utilidade Exemplo Prático
psql -U <user> -d <dbname> Conecta ao banco de dados pelo terminal psql -U admin_b2b -d portal_b2b_db -h localhost
\l Lista todos os bancos de dados do servidor \l
\c <dbname> Conecta a outro banco de dados (Change DB) \c portal_b2b_db
\dt Lista todas as tabelas do banco atual \dt
\d <nome_tabela> Descreve a estrutura e colunas da tabela (Describe) \d clientes_b2b
\i <caminho_arquivo.sql> Executa um arquivo de script SQL externo \i src/database/schema.sql

03

Determinação do Tipo de Banco de Dados de Acordo com o Projeto

⏱️ Duração Estimada: 60 min

A escolha entre um **Banco de Dados Relacional (SQL)** e um **Banco Não-Relacional (NoSQL)** deve ser orientada pela natureza dos dados, nível de consistência exigido e padrão de consulta da aplicação.

Critério de Comparação Bancos Relacionais (SQL / PostgreSQL) Bancos Não-Relacionais (NoSQL / MongoDB / Redis)
Estrutura dos Dados Rígida, tabelas relacionais predefinidas por Schema. Flexível, orientada a Documentos (JSON), Chave-Valor ou Grafos.
Garantia de Transação Garantia ACID total (Atomicidade, Consistência, Isolamento, Durabilidade). Modelo BASE (Eventual Consistency), foco em disponibilidade.
Relacionamentos Complexos Excelência em consultas com JOINs entre múltiplas tabelas. Desencorajado JOIN; prefere dados desnormalizados/aninhados.
Caso de Uso Ideal Sistemas Financeiros, Portais ERP, CRM, Portais B2B Comercial & Estoque. Feeds de Redes Sociais, Caches rápidos (Redis), Catálogos com dados altamente mutáveis.

🎯 Justificativa da Escolha do PostgreSQL para o Portal B2B:

O Portal Comercial B2B exige regras fiscais e financeiras rígidas onde um pedido de compra não pode ser faturado sem a garantia de saldo de estoque e integridade do cliente. A capacidade de transação ACID do PostgreSQL garante que se a reserva do inventário falhar, a criação do pedido seja desfeita (Rollback) automaticamente. Além disso, a presença do tipo nativo JSONB no PostgreSQL permite o melhor dos dois mundos: relacional estrito para tabelas core e suporte flexível a NoSQL para metadados e logs.

🛠️ Atividade Prática Integrada — Provisionamento e Configuração do PostgreSQL do Projeto (Em Duplas)

Cenário: Cada equipe irá criar o banco de dados do projeto B2B no PostgreSQL, configurar as credenciais de acesso locais e testar a comunicação via terminal e pgAdmin.

Roteiro Prático da Atividade:

  1. Provisionamento do Banco: Abra o pgAdmin ou terminal `psql` e execute o comando CREATE DATABASE portal_b2b_db;.
  2. Criação de Usuário e Privilégios: Crie um novo usuário chamado `app_b2b` com senha e conceda privilégios de conexão ao banco `portal_b2b_db`.
  3. Execução de DDL via Script `.sql`: Crie o arquivo src/config/schema.sql no seu projeto contendo as tabelas clientes_b2b e pedidos com restrições PK/FK e execute o script usando o comando `\i` do `psql` ou o Query Tool do pgAdmin.
  4. Configuração do arquivo `.env`: Atualize as variáveis de conexão no arquivo .env do projeto Node.js com o `DB_HOST`, `DB_USER`, `DB_PASS` e `DB_NAME` criados.
