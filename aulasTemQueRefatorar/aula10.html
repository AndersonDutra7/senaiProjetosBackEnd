01

Comandos DDL: CREATE, ALTER, DROP e Constraints (NOT NULL, UNIQUE, CHECK)

⏱️ Duração Estimada: 60 min

A Linguagem de Definição de Dados (DDL - Data Definition Language) é o subconjunto do SQL responsável por criar, alterar e excluir a estrutura física dos objetos no banco de dados (tabelas, esquemas, índices, visões e sequências).

1. Os Três Comandos Principais da DDL

CREATE

Instancia novos objetos no banco de dados (Ex: CREATE TABLE, CREATE DATABASE, CREATE INDEX).

ALTER

Modifica a estrutura existente de um objeto sem apagar seus dados (Ex: adicionar/remover colunas, alterar tipos de dados, adicionar restrições).

DROP

Remove permanentemente estruturas do banco de dados (Ex: DROP TABLE, DROP DATABASE). Operação irreversível!

2. Restrições de Integridade (Constraints) no Nível de Colunas e Tabelas

Constraints são regras aplicadas às colunas para garantir a consistência e qualidade dos dados inseridos no sistema.

Constraint Prefixo Padrão Finalidade e Comportamento Exemplo Prático DDL
NOT NULL - Impede que uma coluna aceite valores nulos/vazios. razao_social VARCHAR(150) NOT NULL
UNIQUE uq_ Garante que todos os valores de uma coluna (ou combinação de colunas) sejam distintos no banco. CONSTRAINT uq_clientes_cnpj UNIQUE (cnpj)
CHECK ck_ Valida uma expressão lógica antes de aceitar a inserção ou edição do registro. CONSTRAINT ck_produtos_preco CHECK (preco_base > 0)
DEFAULT - Atribui um valor padrão automático caso a coluna não seja informada no INSERT. status VARCHAR(20) DEFAULT 'RASCUNHO'

3. Exemplo Prático de Modificação com `ALTER TABLE`

-- Adicionando uma nova coluna com valor padrão
ALTER TABLE clientes_b2b 
ADD COLUMN limite_credito NUMERIC(12,2) DEFAULT 5000.00;

-- Adicionando uma constraint CHECK após a criação da tabela
ALTER TABLE clientes_b2b 
ADD CONSTRAINT ck_clientes_limite CHECK (limite_credito >= 0);

-- Modificando o tipo de dado de uma coluna existente
ALTER TABLE clientes_b2b 
ALTER COLUMN razao_social TYPE VARCHAR(200);

-- Removendo uma coluna não utilizada
ALTER TABLE clientes_b2b 
DROP COLUMN IF EXISTS observacoes_antigas;
⚠️ Cuidado ao Executar DROP TABLE: Utilizar DROP TABLE clientes_b2b CASCADE; remove a tabela e **apaga automaticamente todas as chaves estrangeiras, visões e dependências** vinculadas a ela. Em ambientes de produção, restrições DDL são gerenciadas estritamente via **Migrations**.
02

Chaves Primárias, Estrangeiras e Relacionamentos em SQL

⏱️ Duração Estimada: 60 min

A ligação física entre tabelas é declarada na DDL através de **Primary Keys (PK)** e **Foreign Keys (FK)**, especificando os comportamentos de integridade referencial para manutenção dos dados.

1. Declaração Formal de Chave Primária e Estrangeira com Nomenclatura Padronizada

1

Primary Key Simples e Composta

• PK Simples: CONSTRAINT pk_produtos PRIMARY KEY (id_produto)
• PK Composta (Tabela de Junção): CONSTRAINT pk_itens_pedido PRIMARY KEY (id_pedido, id_produto)

2

Foreign Key com Cláusulas de Ação (`ON DELETE / ON UPDATE`)

Especifica o que o banco de dados deve fazer com as linhas filhas quando a linha pai for alterada ou removida:

  • ON DELETE RESTRICT: Impede a exclusão da linha pai se houver filhos (Ideal para vendas e clientes).
  • ON DELETE CASCADE: Deleta automaticamente todos os filhos vinculados.
  • ON DELETE SET NULL: Mantém os filhos e define o campo da FK como NULO.

2. DDL com Transação Atômica Relacional (Exemplo de Tabela Associativa)

-- Tabela de Itens de Pedido (Relacionamento N:M entre Pedidos e Produtos)
CREATE TABLE itens_pedido (
    id_pedido BIGINT NOT NULL,
    id_produto BIGINT NOT NULL,
    quantidade INT NOT NULL,
    preco_unitario_momento NUMERIC(12,2) NOT NULL,
    
    -- Chave Primária Composta
    CONSTRAINT pk_itens_pedido PRIMARY KEY (id_pedido, id_produto),
    
    -- Chaves Estrangeiras com Constraints explicitamente nomeadas
    CONSTRAINT fk_itens_pedido_pedido FOREIGN KEY (id_pedido)
        REFERENCES pedidos (id_pedido)
        ON DELETE CASCADE
        ON UPDATE CASCADE,
        
    CONSTRAINT fk_itens_pedido_produto FOREIGN KEY (id_produto)
        REFERENCES produtos (id_produto)
        ON DELETE RESTRICT
        ON UPDATE CASCADE,
        
    -- Restrição CHECK de quantidade positiva
    CONSTRAINT ck_itens_pedido_quantidade CHECK (quantidade > 0)
);

Desafio Prático — Script SQL de Criação das Tabelas do Projeto (`schema.sql`)

⏱️ Duração Estimada: 60 min

Cada equipe deve consolidar o script DDL oficial que cria todo o esquema do banco de dados relacional PostgreSQL do Portal Comercial B2B.

Estrutura do Arquivo `src/config/schema.sql` Obrigatória:

-- =============================================================
-- PORTAL COMERCIAL B2B - SCRIPT DDL DE CRIAÇÃO DO BANCO DE DADOS
-- =============================================================

-- 1. LIMPEZA INICIAL DO ESQUEMA (DROPS EM ORDEM REVERSA DE DEPENDÊNCIA)
DROP TABLE IF EXISTS itens_pedido CASCADE;
DROP TABLE IF EXISTS inventario CASCADE;
DROP TABLE IF EXISTS pedidos CASCADE;
DROP TABLE IF EXISTS produtos CASCADE;
DROP TABLE IF EXISTS clientes_b2b CASCADE;

-- 2. TABELA: CLIENTES_B2B
CREATE TABLE clientes_b2b (
    id_cliente BIGSERIAL,
    cnpj VARCHAR(14) NOT NULL,
    razao_social VARCHAR(150) NOT NULL,
    email VARCHAR(100) NOT NULL,
    telefone VARCHAR(20),
    ativo BOOLEAN DEFAULT TRUE,
    criado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    CONSTRAINT pk_clientes_b2b PRIMARY KEY (id_cliente),
    CONSTRAINT uq_clientes_b2b_cnpj UNIQUE (cnpj),
    CONSTRAINT uq_clientes_b2b_email UNIQUE (email)
);

-- 3. TABELA: PRODUTOS
CREATE TABLE produtos (
    id_produto BIGSERIAL,
    codigo_sku VARCHAR(50) NOT NULL,
    nome_produto VARCHAR(120) NOT NULL,
    preco_base NUMERIC(12,2) NOT NULL,
    ativo BOOLEAN DEFAULT TRUE,
    
    CONSTRAINT pk_produtos PRIMARY KEY (id_produto),
    CONSTRAINT uq_produtos_sku UNIQUE (codigo_sku),
    CONSTRAINT ck_produtos_preco CHECK (preco_base >= 0)
);

-- 4. TABELA: INVENTARIO
CREATE TABLE inventario (
    id_inventario BIGSERIAL,
    id_produto BIGINT NOT NULL,
    quantidade_saldo INT NOT NULL DEFAULT 0,
    localizacao_deposito VARCHAR(50) DEFAULT 'GALPAO_PRINCIPAL',
    atualizado_em TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    
    CONSTRAINT pk_inventario PRIMARY KEY (id_inventario),
    CONSTRAINT uq_inventario_produto UNIQUE (id_produto),
    CONSTRAINT fk_inventario_produto FOREIGN KEY (id_produto)
        REFERENCES produtos (id_produto) ON DELETE CASCADE,
    CONSTRAINT ck_inventario_saldo CHECK (quantidade_saldo >= 0)
);

-- 5. TABELA: PEDIDOS
CREATE TABLE pedidos (
    id_pedido BIGSERIAL,
    id_cliente BIGINT NOT NULL,
    data_pedido TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    status_pedido VARCHAR(30) DEFAULT 'RASCUNHO',
    valor_total NUMERIC(12,2) DEFAULT 0.00,
    
    CONSTRAINT pk_pedidos PRIMARY KEY (id_pedido),
    CONSTRAINT fk_pedidos_cliente FOREIGN KEY (id_cliente)
        REFERENCES clientes_b2b (id_cliente) ON DELETE RESTRICT,
    CONSTRAINT ck_pedidos_status CHECK (status_pedido IN ('RASCUNHO', 'CONFIRMADO', 'FATURADO', 'CANCELADO'))
);

-- 6. TABELA: ITENS_PEDIDO (TABELA ASSOCIATIVA)
CREATE TABLE itens_pedido (
    id_pedido BIGINT NOT NULL,
    id_produto BIGINT NOT NULL,
    quantidade INT NOT NULL,
    preco_unitario_momento NUMERIC(12,2) NOT NULL,
    
    CONSTRAINT pk_itens_pedido PRIMARY KEY (id_pedido, id_produto),
    CONSTRAINT fk_itens_pedido_pedido FOREIGN KEY (id_pedido)
        REFERENCES pedidos (id_pedido) ON DELETE CASCADE,
    CONSTRAINT fk_itens_pedido_produto FOREIGN KEY (id_produto)
        REFERENCES produtos (id_produto) ON DELETE RESTRICT,
    CONSTRAINT ck_itens_quantidade CHECK (quantidade > 0)
);

Encerramento: Glossário da Aula + Quiz Final de Fixação

⏱️ Duração Estimada: 30 min

📚 Glossário Técnico da Aula

DDL (Data Definition Language)

Subconjunto de comandos SQL (CREATE, ALTER, DROP) focado em definir esquemas e objetos de banco de dados.

Constraint (Restrição)

Regra de validação imposta pelo banco de dados para garantir integridade e consistência dos dados.

CHECK Constraint

Restrição de validação lógica que aceita apenas linhas cuja condição Booleana seja verdadeira.

Cascade Action

Propriedade de integridade referencial que propaga automaticamente alterações ou exclusões para tabelas filhas.

❓ Quiz Final de Fixação

1. Qual comando DDL deve ser utilizado para alterar o tipo de dado de uma coluna existente sem apagar a tabela?
A) UPDATE TABLE
B) MODIFY TABLE
C) ALTER TABLE ... ALTER COLUMN ... TYPE
D) CHANGE TABLE
✅ Resposta Correta: C) ALTER TABLE ... ALTER COLUMN ... TYPE
Justificativa: O comando `ALTER TABLE` é o único comando DDL padronizado em SQL para modificar estruturas de colunas existentes.
2. O que acontece ao tentar inserir um produto com preço `-15.00` em uma tabela que possui a constraint `CONSTRAINT ck_preco CHECK (preco >= 0)`?
A) O valor é convertido automaticamente para `0.00`.
B) O banco de dados lança um erro de violação de constraint e rejeita o INSERT.
C) O valor é inserido com aviso (warning).
D) A tabela é bloqueada para leitura.
✅ Resposta Correta: B) O banco lança um erro de violação de constraint e rejeita o INSERT.
Justificativa: Restrições `CHECK` impõem validação estrita. Se a expressão retornar FALSA, a operação é abortada.
3. Qual cláusula de Foreign Key deve ser usada na tabela de Pedidos para IMPEDIR a exclusão acidental de um cliente que já possui compras registradas?
A) ON DELETE CASCADE
B) ON DELETE SET NULL
C) ON DELETE RESTRICT
D) ON DELETE TRUNCATE
✅ Resposta Correta: C) ON DELETE RESTRICT
Justificativa: A ação `ON DELETE RESTRICT` (ou `NO ACTION`) bloqueia ativamente a exclusão de qualquer registro pai que possua filhos dependentes no banco.
