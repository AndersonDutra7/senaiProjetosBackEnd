01

Organização de Rotas, Controllers e Models no Express

⏱️ Duração Estimada: 60 min

O padrão de arquitetura MVC (Model-View-Controller) divide uma aplicação em três componentes principais de software. Em APIs RESTful modernas desenvolvidas com Node.js e Express, a camada View é substituída pelas respostas estruturadas em formato JSON enviadas ao cliente HTTP.

1. As Três Camadas no Contexto de APIs RESTful

ROUTES (ROTAS)

Mapeia os verbos HTTP (GET, POST, PUT, DELETE) e URLs para funções específicas. É a porta de entrada da aplicação, sem conter lógica de negócio.

CONTROLLERS

Orquestra o fluxo da requisição. Recebe os dados de entrada (req.params, req.body, req.query), chama a camada Model, trata erros e envia a resposta HTTP (res.status().json()).

MODELS

Gerencia as regras de negócio e o acesso direto ao banco de dados. Executa instruções SQL (queries parametrizadas com `pg.Pool`) e retorna dados puros.

2. Por que Não Colocar Tudo em um Único Arquivo?

Abordagem monolítica em arquivo único (`server.js`) Arquitetura MVC Modularizada
❌ Alto acoplamento: SQL, rotas e validações misturados em centenas de linhas. ✅ Baixo acoplamento: cada arquivo possui uma responsabilidade única e clara (SRP).
❌ Impossível reusar rotinas de banco de dados em diferentes partes do sistema. ✅ Reutilização: funções da camada Model podem ser chamadas por múltiplos Controllers.
❌ Testes unitários e de integração extremamente complexos. ✅ Testabilidade simples: é possível testar Models isoladamente sem simular rotas Express.
⚠️ O Anti-Pattern "Fat Controller": Um erro comum em projetos iniciantes é colocar comandos SQL dentro dos Controllers. O Controller deve ser enxuto (Thin Controller) — sua função é apenas orquestrar, delegando todas as operações de banco para o Model.
02

Separação de Camadas — Da Rota à Consulta no Banco de Dados

⏱️ Duração Estimada: 60 min

Compreender o ciclo de vida e a rastreabilidade de uma requisição HTTP através das camadas da aplicação é essencial para o desenvolvimento seguro e depuração rápida.

1. O Ciclo de Vida Completo de uma Requisição (Fluxo Passo a Passo)

1

Cliente HTTP (Postman / Frontend)

O cliente envia a requisição POST /api/v1/clientes contendo o payload JSON com os dados do cliente B2B.

2

Camada de Rotas (`routes/clienteRoutes.js`)

O express.Router intercepta a requisição e a direciona para a função clienteController.criarCliente.

3

Camada Controller (`controllers/clienteController.js`)

Extrai os dados de req.body, valida o preenchimento de campos obrigatórios e invoca clienteModel.salvar(dados).

4

Camada Model (`models/clienteModel.js`)

Monta o comando SQL parametrizado (`INSERT INTO clientes_b2b ... RETURNING *`) e o executa através da conexão do Pool (`db.query`).

5

SGBD PostgreSQL & Retorno

O PostgreSQL persiste o registro e devolve a nova linha criada para o Model, que a repassa ao Controller. O Controller então devolve a resposta HTTP com status 201 Created e o JSON resultante ao cliente.

2. Implementação do Fluxo em Código Node.js (Exemplo Completo)

A. Camada Model (`src/models/clienteModel.js`):

import { query } from '../config/db.js';

export const clienteModel = {
  // Busca todos os clientes cadastrados
  buscarTodos: async () => {
    const text = 'SELECT id_cliente, cnpj, razao_social, email, telefone, ativo FROM clientes_b2b ORDER BY razao_social ASC';
    const result = await query(text);
    return result.rows;
  },

  // Busca um cliente pelo ID
  buscarPorId: async (id) => {
    const text = 'SELECT * FROM clientes_b2b WHERE id_cliente = $1';
    const result = await query(text, [id]);
    return result.rows[0];
  },

  // Cadastra um novo cliente com Prepared Statement
  criar: async (dados) => {
    const { cnpj, razao_social, email, telefone } = dados;
    const text = `
      INSERT INTO clientes_b2b (cnpj, razao_social, email, telefone)
      VALUES ($1, $2, $3, $4)
      RETURNING *
    `;
    const values = [cnpj, razao_social, email, telefone];
    const result = await query(text, values);
    return result.rows[0];
  }
};

B. Camada Controller (`src/controllers/clienteController.js`):

import { clienteModel } from '../models/clienteModel.js';

export const clienteController = {
  listarClientes: async (req, res) => {
    try {
      const clientes = await clienteModel.buscarTodos();
      return res.status(200).json({ success: true, count: clientes.length, data: clientes });
    } catch (error) {
      console.error('❌ Erro no clienteController.listarClientes:', error);
      return res.status(500).json({ success: false, message: 'Erro interno ao buscar clientes.' });
    }
  },

  cadastrarCliente: async (req, res) => {
    try {
      const { cnpj, razao_social, email, telefone } = req.body;

      // Validação básica de entrada de dados no Controller
      if (!cnpj || !razao_social || !email) {
        return res.status(400).json({ success: false, message: 'Os campos CNPJ, Razão Social e E-mail são obrigatórios.' });
      }

      const novoCliente = await clienteModel.criar({ cnpj, razao_social, email, telefone });
      return res.status(201).json({ success: true, message: 'Cliente cadastrado com sucesso!', data: novoCliente });
    } catch (error) {
      console.error('❌ Erro no clienteController.cadastrarCliente:', error);
      return res.status(500).json({ success: false, message: 'Erro interno ao cadastrar cliente.' });
    }
  }
};

C. Camada de Rotas (`src/routes/clienteRoutes.js`):

import { Router } from 'express';
import { clienteController } from '../controllers/clienteController.js';

const router = Router();

// Mapeamento dos Endpoints HTTP
router.get('/', clienteController.listarClientes);
router.post('/', clienteController.cadastrarCliente);

export default router;

import express from 'express';
import clienteRoutes from './routes/clienteRoutes.js';
import produtoRoutes from './routes/produtoRoutes.js';

const app = express();

// Middlewares Globais
app.use(express.json()); // Parser de JSON no body da requisição

// Prefixagem e Mapeamento de Módulos de Rota
app.use('/api/v1/clientes', clienteRoutes);
app.use('/api/v1/produtos', produtoRoutes);

// Rota de Healthcheck do Servidor
app.get('/health', (req, res) => {
  res.status(200).json({ status: 'OK', timestamp: new Date() });
});

export default app;

Encerramento: Glossário da Aula + Quiz Final de Fixação

⏱️ Duração Estimada: 30 min

📚 Glossário Técnico da Aula

Pattern MVC

Padrão arquitetural que divide a aplicação nas camadas de Modelo (Model), Visão (View) e Controle (Controller).

Express Router

Mapeador de rotas modular do Express.js que permite agrupar endpoints por recurso e exportá-los para o `app.js`.

Thin Controller

Boas práticas de arquitetura onde o Controller é enxuto, concentrando-se apenas na validação da requisição e delegação para o Model.

Data Access Object (DAO)

Padrão de projeto implementado dentro da camada Model para encapsular o acesso e execução de queries no banco de dados.

❓ Quiz Final de Fixação

1. Qual é a responsabilidade primária da camada Controller na arquitetura MVC para APIs RESTful?
A) Executar comandos DDL de criação de tabelas no PostgreSQL.
B) Receber a requisição HTTP, validar parâmetros básicos de entrada, acionar o Model e enviar a resposta ao cliente.
C) Renderizar telas em HTML e CSS diretamente no servidor.
D) Gerenciar a criptografia das senhas no arquivo `.env`.
✅ Resposta Correta: B) Receber a requisição HTTP, validar entradas, acionar o Model e responder ao cliente.
Justificativa: O Controller age como um orquestrador entre a requisição externa do cliente e a lógica de persistência do Model.
2. Por que a instrução SQL `db.query('SELECT * FROM clientes')` NUNCA deve ser escrita diretamente dentro de um arquivo de rotas (`clienteRoutes.js`)?
A) Porque os arquivos de rotas são bloqueados pelo navegador.
B) Porque viola a separação de responsabilidades (SRP), misturando mapeamento de rotas com acesso ao banco de dados e dificultando a manutenção.
C) Porque o Express.js proíbe o uso de funções assíncronas em rotas.
D) Porque obriga a reinicialização do PostgreSQL a cada requisição.
✅ Resposta Correta: B) Porque viola a separação de responsabilidades (SRP).
Justificativa: As rotas servem exclusivamente para direcionar endpoints aos Controllers. A lógica de banco deve residir estritamente nos Models.
3. No fluxo de criação de um registro (`POST`), qual componente é responsável por montar a instrução SQL parametrizada (`INSERT ... $1`)?
A) A camada Model (`clienteModel.js`).
B) A camada Router (`clienteRoutes.js`).
C) O middleware global `express.json()`.
D) O arquivo de inicialização do servidor (`server.js`).
✅ Resposta Correta: A) A camada Model (`clienteModel.js`).
Justificativa: A camada Model é a única camada autorizada a conter SQL e interagir diretamente com a abstração do banco de dados.
