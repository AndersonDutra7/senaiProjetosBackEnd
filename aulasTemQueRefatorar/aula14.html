01

Implementação dos Endpoints de Criação, Leitura, Atualização e Exclusão (CRUD)

⏱️ Duração Estimada: 60 min

Uma API RESTful expõe recursos (como produtos ou clientes) identificados por URIs e operados por meio de verbos padronizados do protocolo HTTP. O acrônimo CRUD representa as quatro operações fundamentais de qualquer sistema de informação: Create, Read, Update e Delete.

1. Mapeamento Semântico HTTP vs. Operações CRUD

Verbo HTTP Endpoint (URI) Ação CRUD Status HTTP Recomendado Uso da Payload / Parâmetros
POST /api/v1/produtos Create (Criar) 201 Created Dados enviados no req.body em formato JSON.
GET /api/v1/produtos Read (Listar) 200 OK Suporta filtros via Query Parameters (req.query).
GET /api/v1/produtos/:id Read (Buscar por ID) 200 OK / 404 Not Found ID capturado via URL Parameter (req.params.id).
PUT /api/v1/produtos/:id Update (Atualizar) 200 OK / 404 Not Found ID via req.params e novos dados via req.body.
DELETE /api/v1/produtos/:id Delete (Remover) 200 OK / 204 No Content ID capturado via URL Parameter (req.params.id).

2. Implementação Técnica Completa do Módulo de Produtos

A. Camada Model (`src/models/produtoModel.js`):

import { query } from '../config/db.js';

export const produtoModel = {
  // CREATE
  criar: async ({ codigo_sku, nome_produto, preco_base }) => {
    const text = `
      INSERT INTO produtos (codigo_sku, nome_produto, preco_base)
      VALUES ($1, $2, $3)
      RETURNING *
    `;
    const result = await query(text, [codigo_sku, nome_produto, preco_base]);
    return result.rows[0];
  },

  // READ (Listar com filtro opcional)
  buscarTodos: async (buscaTextual) => {
    let text = 'SELECT * FROM produtos WHERE ativo = TRUE';
    const params = [];

    if (buscaTextual) {
      text += ' AND (nome_produto ILIKE $1 OR codigo_sku ILIKE $1)';
      params.push(`%${buscaTextual}%`);
    }

    text += ' ORDER BY id_produto DESC';
    const result = await query(text, params);
    return result.rows;
  },

  // READ (Buscar por ID)
  buscarPorId: async (id) => {
    const text = 'SELECT * FROM produtos WHERE id_produto = $1 AND ativo = TRUE';
    const result = await query(text, [id]);
    return result.rows[0];
  },

  // UPDATE
  atualizar: async (id, { codigo_sku, nome_produto, preco_base }) => {
    const text = `
      UPDATE produtos
      SET codigo_sku = $1, nome_produto = $2, preco_base = $3
      WHERE id_produto = $4 AND ativo = TRUE
      RETURNING *
    `;
    const result = await query(text, [codigo_sku, nome_produto, preco_base, id]);
    return result.rows[0];
  },

  // DELETE (Soft Delete - Recomendado em B2B)
  inativar: async (id) => {
    const text = `
      UPDATE produtos
      SET ativo = FALSE
      WHERE id_produto = $1 AND ativo = TRUE
      RETURNING *
    `;
    const result = await query(text, [id]);
    return result.rows[0];
  }
};

B. Camada Controller (`src/controllers/produtoController.js`): 

import { produtoModel } from '../models/produtoModel.js';

export const produtoController = {
  criarProduto: async (req, res) => {
    try {
      const { codigo_sku, nome_produto, preco_base } = req.body;

      if (!codigo_sku || !nome_produto || preco_base === undefined) {
        return res.status(400).json({ success: false, message: 'SKU, Nome e Preço Base são obrigatórios.' });
      }

      const novoProduto = await produtoModel.criar({ codigo_sku, nome_produto, preco_base });
      return res.status(201).json({ success: true, message: 'Produto cadastrado!', data: novoProduto });
    } catch (error) {
      console.error('❌ Erro produtoController.criarProduto:', error);
      return res.status(500).json({ success: false, message: 'Erro ao cadastrar produto.' });
    }
  },

  listarProdutos: async (req, res) => {
    try {
      const { busca } = req.query;
      const produtos = await produtoModel.buscarTodos(busca);
      return res.status(200).json({ success: true, count: produtos.length, data: produtos });
    } catch (error) {
      console.error('❌ Erro produtoController.listarProdutos:', error);
      return res.status(500).json({ success: false, message: 'Erro ao listar produtos.' });
    }
  },

  obterProdutoPorId: async (req, res) => {
    try {
      const { id } = req.params;
      const produto = await produtoModel.buscarPorId(id);

      if (!produto) {
        return res.status(404).json({ success: false, message: 'Produto não encontrado.' });
      }

      return res.status(200).json({ success: true, data: produto });
    } catch (error) {
      console.error('❌ Erro produtoController.obterProdutoPorId:', error);
      return res.status(500).json({ success: false, message: 'Erro ao obter produto.' });
    }
  },

  atualizarProduto: async (req, res) => {
    try {
      const { id } = req.params;
      const { codigo_sku, nome_produto, preco_base } = req.body;

      const produtoAtualizado = await produtoModel.atualizar(id, { codigo_sku, nome_produto, preco_base });

      if (!produtoAtualizado) {
        return res.status(404).json({ success: false, message: 'Produto não encontrado para atualização.' });
      }

      return res.status(200).json({ success: true, message: 'Produto atualizado!', data: produtoAtualizado });
    } catch (error) {
      console.error('❌ Erro produtoController.atualizarProduto:', error);
      return res.status(500).json({ success: false, message: 'Erro ao atualizar produto.' });
    }
  },

  excluirProduto: async (req, res) => {
    try {
      const { id } = req.params;
      const produtoInativado = await produtoModel.inativar(id);

      if (!produtoInativado) {
        return res.status(404).json({ success: false, message: 'Produto não encontrado para exclusão.' });
      }

      return res.status(200).json({ success: true, message: 'Produto inativado com sucesso!' });
    } catch (error) {
      console.error('❌ Erro produtoController.excluirProduto:', error);
      return res.status(500).json({ success: false, message: 'Erro ao excluir produto.' });
    }
  }
};

Aplicação de Técnicas de Levantamento de Demandas do Cliente na Definição dos Endpoints

⏱️ Duração Estimada: 60 min

Um erro frequente no desenvolvimento de software é projetar APIs baseando-se apenas na estrutura das tabelas do banco de dados, sem ouvir as **necessidades reais de negócio dos usuários e clientes B2B**.

1. Mapeamento de Demandas de Negócio B2B em Contratos REST

1

Demanda do Cliente: "A equipe comercial precisa buscar insumos pelo código SKU ou palavra-chave sem case sensitivity."

Solução REST: Utilização de Query Parameters na rota de listagem (`GET /api/v1/produtos?busca=sensor`) traduzido no SQL com `ILIKE`.

2

Demanda do Cliente: "Produtos com histórico de vendas antigas NUNCA podem ser apagados fisicamente do sistema."

Solução REST: Implementação de Soft Delete (Exclusão Lógica). O verb DELETE /api/v1/produtos/:id altera a flag `ativo = FALSE`, preservando a integridade histórica dos relatórios do banco de dados.

3

Demanda do Cliente: "Desejamos receber mensagens de erro claras quando um SKU duplicado for inserido."

Solução REST: Captura de exceções de integridade no Controller (Erro PostgreSQL `23505` de violação de `UNIQUE`) retornando `409 Conflict` com mensagem descritiva em JSON.

💡 O Contrato JSON Padronizado: Todas as respostas da API devem seguir um envelope JSON uniforme contendo success (Booleano), message (String explicativa) e data (Objeto ou Array de resultados).

⏱️ Duração Estimada: 60 min

1. Roteador de Produtos (`src/routes/produtoRoutes.js`) 

import { Router } from 'express';
import { produtoController } from '../controllers/produtoController.js';

const router = Router();

// Mapeamento das 5 rotas fundamentais do CRUD RESTful
router.post('/', produtoController.criarProduto);
router.get('/', produtoController.listarProdutos);
router.get('/:id', produtoController.obterProdutoPorId);
router.put('/:id', produtoController.atualizarProduto);
router.delete('/:id', produtoController.excluirProduto);

export default router;

Encerramento: Glossário da Aula + Quiz Final de Fixação

⏱️ Duração Estimada: 30 min

📚 Glossário Técnico da Aula

REST (Representational State Transfer)

Estilo arquitetural para sistemas distribuídos baseado em recursos sem estado (stateless) identificados por URIs.

Soft Delete (Exclusão Lógica)

Prática de marcar um registro como inativo no banco (`ativo = FALSE`) em vez de apagá-lo fisicamente via SQL.

Query Parameters

Parâmetros opcionais chave-valor passados na URL após o símbolo `?` para ordenação, filtragem e paginação (`?busca=alfa`).

Status Code HTTP

Código numérico de 3 dígitos retornado pelo servidor indicando o resultado do processamento da requisição (Ex: 200, 201, 400, 404, 500).

❓ Quiz Final de Fixação

1. Qual é o código de status HTTP recomendado para ser devolvido por uma API RESTful após a criação BEM-SUCEDIDA de um novo registro via verbo POST?
A) 200 OK
B) 201 Created
C) 204 No Content
D) 302 Found
✅ Resposta Correta: B) 201 Created
Justificativa: O código `201 Created` é a resposta padrão em APIs REST para confirmar a criação física bem-sucedida de um novo recurso no servidor.
2. Por que a técnica de Soft Delete (exclusão lógica) é altamente recomendada em aplicações comerciais e ERPs B2B?
A) Porque reduz o consumo de memória RAM do Node.js.
B) Porque impede a perda irrecuperável de histórico de vendas e relatórios auditáveis caso um produto associado a pedidos antigos fosse apagado fisicamente.
C) Porque é o único método aceito pelo driver `pg` do PostgreSQL.
D) Porque elimina a necessidade de utilizar o comando `ALTER TABLE`.
✅ Resposta Correta: B) Porque impede a perda de histórico e auditabilidade.
Justificativa: Apagar uma linha fisicamente (`DELETE FROM`) pode quebrar relacionamentos e corromper relatórios financeiros históricos. O Soft Delete inativa o registro mantendo sua rastreabilidade.
3. Para realizar a busca por palavra-chave em uma API (`GET /api/v1/produtos?busca=sensor`), como o parâmetro `busca` é acessado no Express.js?
A) Através de `req.body.busca`
B) Através de `req.params.busca`
C) Através de `req.query.busca`
D) Através de `req.headers.busca`
✅ Resposta Correta: C) Através de `req.query.busca`
Justificativa: Parâmetros de consulta passados na URL após a interrogação (`?chave=valor`) são automaticamente parseados pelo Express no objeto `req.query`.
