01

Consumo de API REST no Front-End com Fetch / AJAX

⏱️ Duração Estimada: 60 min

A comunicação assíncrona entre o navegador web (client-side) e a API REST (server-side) permite atualizar o conteúdo da página **sem a necessidade de recarregá-la inteiramente (Page Reload)**. Esse padrão, conhecido historicamente como **AJAX (Asynchronous JavaScript and XML)**, é implementado nativamente nos navegadores modernos via Fetch API com sintaxe async/await.

1. O Ciclo da Requisição Assíncrona com `fetch()`

1

Disparo do Evento (Event Handler)

O usuário clica em um botão de consulta ou submete um formulário (ex: form.addEventListener('submit', ...)).

2

Chamada Assíncrona (`fetch(url, config)`)

O navegador dispara uma requisição HTTP via soquete para a API Node.js rodando em http://localhost:3000/api/v1/... de forma não bloqueante.

3

Parsing da Resposta JSON (`await response.json()`)

A resposta do servidor é recebida. O corpo em formato string JSON é convertido em um objeto JavaScript manipulável.

4

Renderização Dinâmica da DOM

Os elementos da interface visual (tabelas, cards, alertas) são atualizados via manipulação de DOM (element.innerHTML ou document.createElement).

2. Exemplo 1: Requisição `GET` com Injeção de Bearer Token

Buscando a lista de produtos B2B cadastrados e injetando o Token JWT salvo no localStorage:

async function carregarProdutosB2B() {
  const token = localStorage.getItem('token_b2b');

  // Redireciona para o login se o usuário não possuir token salvo
  if (!token) {
    window.location.href = '/login.html';
    return;
  }

  try {
    const response = await fetch('http://localhost:3000/api/v1/produtos', {
      method: 'GET',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${token}` // Envio do Bearer Token
      }
    });

    const resultado = await response.json();

    if (!response.ok) {
      throw new Error(resultado.message || 'Falha ao buscar produtos.');
    }

    // Renderiza a lista na tabela HTML da interface
    renderizarTabelaProdutos(resultado.data);

  } catch (error) {
    console.error('❌ Erro no front-end ao listar produtos:', error);
    alert(`Erro: ${error.message}`);
  }
}

3. Exemplo 2: Requisição `POST` com Envio de Payload JSON

Submetendo um novo cadastro de produto B2B a partir de um formulário da interface:

const formCadastro = document.getElementById('form-novo-produto');

formCadastro.addEventListener('submit', async (event) => {
  event.preventDefault(); // Impede o comportamento padrão de reload da página!

  const token = localStorage.getItem('token_b2b');
  
  // Extração dos valores digitados nos inputs
  const payload = {
    codigo_sku: document.getElementById('sku').value,
    nome_produto: document.getElementById('nome').value,
    preco_base: parseFloat(document.getElementById('preco').value)
  };

  try {
    const response = await fetch('http://localhost:3000/api/v1/produtos', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json', // Informa o formato da payload
        'Authorization': `Bearer ${token}`
      },
      body: JSON.stringify(payload) // Converte objeto JS para String JSON
    });

    const resultado = await response.json();

    if (!response.ok) {
      // Exibe erros de validação retornados pela API (Zod / AppError)
      if (resultado.errors) {
        const msgs = resultado.errors.map(e => e.mensagem).join('\n');
        alert(`Atenção:\n${msgs}`);
      } else {
        alert(`Erro: ${resultado.message}`);
      }
      return;
    }

    alert('✅ Produto cadastrado com sucesso!');
    formCadastro.reset();
    carregarProdutosB2B(); // Recarrega a tabela automaticamente!

  } catch (error) {
    console.error('❌ Erro na comunicação com a API:', error);
    alert('Não foi possível conectar ao servidor. Verifique sua conexão.');
  }
});
02

Protocolos e Padrões de Comunicação Client-Side / Server-Side

⏱️ Duração Estimada: 60 min

Para que a comunicação entre o front-end (executado pelo motor JavaScript do navegador) e o back-end (Node.js) ocorra sem falhas, diversos protocolos e padrões da Web entram em ação simultaneamente.

1. Pilares da Comunicação Client-Server

HTTP / HTTPS

Protocolo de aplicação sem estado (stateless) para transporte de requisições e respostas entre navegadores e servidores.

HTTP Headers

Metadados chave-valor que definem o comportamento da comunicação (Ex: Content-Type, Authorization, Accept).

Formatos JSON

Padrão universal de intercâmbio de dados de texto leve. Convertido com JSON.stringify() no envio e JSON.parse() ou .json() no recebimento.

Armazenamento Local

Uso de localStorage (persistência longa) ou sessionStorage (durante a aba) para manter o Token JWT de sessão do usuário no navegador.

2. Entendendo a Requisição Preflight (`OPTIONS` CORS)

Quando o JavaScript executa uma chamada `fetch()` contendo um cabeçalho customizado (como `Authorization`) ou envia dados em `application/json` para um domínio/porta diferente, o navegador dispara automaticamente uma requisição preliminar invisível do tipo `OPTIONS` (Preflight Request) para verificar se a API aceita esses cabeçalhos.

⚠️ Por que configurar o CORS no Back-End? Se o middleware cors() não estiver devidamente registrado no `app.js` do Express, o navegador bloqueará o `fetch()` no front-end com o erro clássico: "Access-Control-Allow-Origin header is missing".

3. Resumo dos Cabeçalhos Essenciais na Comunicação B2B

Cabeçalho HTTP Origem Propósito no Sistema B2B
Content-Type: application/json Cliente & Servidor Informa que o corpo da requisição/resposta é uma string formatada em JSON.
Authorization: Bearer <token> Cliente Envia o Token JWT para autenticar e autorizar a requisição nas rotas privadas.
Access-Control-Allow-Origin Servidor Informa ao navegador quais domínios (ex: `http://localhost:5173`) têm permissão para ler as respostas.

Desafio Prático — Integração Completa das Telas Front-End com a API Node.js

⏱️ Duração Estimada: 60 min

Neste desafio, as equipes realizarão a integração real entre a tela de **Login (`login.html`)**, a tela de **Catálogo de Produtos (`produtos.html`)** e a API Express desenvolvida nas aulas anteriores.

1. Script de Login Front-End (`public/js/login.js`)

document.getElementById('form-login').addEventListener('submit', async (e) => {
  e.preventDefault();

  const email = document.getElementById('input-email').value;
  const senha = document.getElementById('input-senha').value;

  try {
    const response = await fetch('http://localhost:3000/api/v1/auth/login', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email, senha })
    });

    const data = await response.json();

    if (!response.ok) {
      alert(`Falha no login: ${data.message}`);
      return;
    }

    // 1. Armazena o Token JWT no LocalStorage do navegador
    localStorage.setItem('token_b2b', data.token);
    localStorage.setItem('usuario_b2b', JSON.stringify(data.usuario));

    alert(`Bem-vindo, ${data.usuario.nome}!`);

    // 2. Redireciona para o painel principal de produtos
    window.location.href = '/produtos.html';

  } catch (error) {
    console.error('❌ Erro na autenticação:', error);
    alert('Erro de conexão com o servidor de autenticação.');
  }
});

2. Script de Listagem e Renderização da DOM (`public/js/produtos.js`)

// Função para renderizar os cards de produtos dinamicamente na DOM
function renderizarTabelaProdutos(produtos) {
  const container = document.getElementById('grid-produtos');
  container.innerHTML = ''; // Limpa o conteúdo anterior

  if (produtos.length === 0) {
    container.innerHTML = '
Nenhum produto cadastrado no momento.
';
    return;
  }

  produtos.forEach((prod) => {
    const card = document.createElement('div');
    card.className = 'sub-card';
    card.style.marginBottom = '1rem';
    
    card.innerHTML = `
      
${prod.nome_produto}

      
SKU: ${prod.codigo_sku}

      
Preço Base: R$ ${Number(prod.preco_base).toFixed(2)}

      
    `;

    container.appendChild(card);
  });
}

// Função para inativar um produto (Soft Delete via API)
async function inativarProduto(id) {
  if (!confirm('Deseja realmente inativar este produto?')) return;

  const token = localStorage.getItem('token_b2b');

  try {
    const response = await fetch(`http://localhost:3000/api/v1/produtos/${id}`, {
      method: 'DELETE',
      headers: {
        'Authorization': `Bearer ${token}`
      }
    });

    const data = await response.json();

    if (!response.ok) {
      alert(`Erro: ${data.message}`);
      return;
    }

    alert('Produto inativado com sucesso!');
    carregarProdutosB2B(); // Atualiza a lista exibida!
  } catch (error) {
    alert('Erro ao processar inativação do produto.');
  }
}

Encerramento: Glossário da Aula + Quiz Final de Fixação

📚 Glossário Técnico da Aula

Fetch API

Interface moderna do JavaScript para realizar requisições HTTP assíncronas baseada em Promises e `async/await`.

LocalStorage

Mecanismo de armazenamento chave-valor no navegador que persiste dados mesmo após o fechamento da janela.

Preflight Request (OPTIONS)

Requisição preliminar enviada automaticamente pelo navegador para verificar permissões de CORS antes de enviar chamadas complexas.

Manipulação de DOM

Alteração dinâmica da estrutura da página Web (HTML) em tempo de execução via JavaScript em resposta aos dados retornados pela API.

❓ Quiz Final de Fixação

1. Ao enviar um payload em formato JSON para uma API REST através do comando `fetch()`, qual é o papel da instrução `JSON.stringify(payload)`?
A) Criptografar a senha do usuário com a biblioteca bcrypt.
B) Converter o objeto JavaScript em uma string de texto formatada em JSON exigida no corpo (`body`) da requisição HTTP.
C) Salvar os dados automaticamente no LocalStorage.
D) Converter a requisição POST em um comando SQL INSERT.
✅ Resposta Correta: B) Converter o objeto JS em string JSON.
Justificativa: O protocolo HTTP trafega apenas texto puro. `JSON.stringify()` serializa objetos JS para a representação textual JSON enviada no `body`.
2. Onde o front-end deve armazenar o Token JWT retornado pela API após o login bem-sucedido para garantir que o usuário continue autenticado nas páginas seguintes?
A) Em um arquivo `.env` localizado na pasta do navegador.
B) No `localStorage` ou `sessionStorage` do navegador, injetando-o no cabeçalho `Authorization: Bearer ` a cada requisição privada.
C) Em um comentário no HTML da página `index.html`.
D) Diretamente na tabela do PostgreSQL no cliente.
✅ Resposta Correta: B) No localStorage ou sessionStorage do navegador.
Justificativa: O armazenamento local permite recuperar o token e enviá-lo nos cabeçalhos HTTP para validar o acesso a rotas privadas da API.
3. O que acontece se o front-end esquecer de incluir o evento `event.preventDefault()` no listener de submissão do formulário (`form.addEventListener('submit', ...)`?
A) A API Node.js desliga automaticamente.
B) O navegador executa a submissão nativa síncrona do formulário, recarregando a página e interrompendo a chamada assíncrona do `fetch()`.
C) O banco de dados bloqueia a entrada do usuário.
D) O token JWT expira imediatamente.
✅ Resposta Correta: B) O navegador executa a submissão nativa e recarrega a página.
Justificativa: O método `preventDefault()` cancela a ação padrão de reload da página do formulário HTML, permitindo que o JavaScript assuma o controle assíncrono via Fetch API.
