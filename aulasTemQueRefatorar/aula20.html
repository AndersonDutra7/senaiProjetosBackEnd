01

Planos de Teste — Composição, Atribuições e Relatórios

⏱️ Duração Estimada: 45 min

Um Plano de Testes (Test Plan) é o documento formal que orienta e disciplina todo o processo de garantia da qualidade (QA) de um sistema de software. Ele especifica o escopo, os objetivos, a estratégia, os recursos necessários, o cronograma e os critérios de aceitação que serão aplicados para validar a aplicação antes de seu envio para homologação e produção.

1. Componentes Essenciais de um Plano de Testes de Back-End

Seção do Plano Descrição e Conteúdo Aplicação Prática no Projeto Node.js
🎯 Escopo & Objetivos Define quais módulos, rotas e regras de negócio serão validados e o que está fora do escopo. Inclusão dos endpoints de login/autenticação JWT e CRUD B2B; exclusão de serviços externos simulados por mocks.
💻 Ambiente de Testes Especifica as configurações de hardware, software, variáveis e banco de dados isolado. Banco PostgreSQL de testes (b2b_db_test), Node.js v20 LTS, variáveis configuradas via .env.test.
👥 Atribuições da Equipe Mapeia os papéis e responsabilidades dos membros do time no ciclo de execução dos testes. Desenvolvedores criam testes unitários de Models; QA/Líder executa testes de integração das rotas HTTP.
🛑 Critérios de Parada / Aceite Métricas necessárias para aprovar a entrega parcial ou final (ex.: taxa de cobertura de código). 100% de sucesso nos fluxos críticos do CRUD e cobertura de código mínima (Code Coverage) de 75%.

2. Matriz de Rastreabilidade e Estrutura de um Caso de Teste

Cada **Caso de Teste (Test Case)** deve estar associado diretamente a um requisito funcional ou não funcional mapeado na fase de planejamento do software, garantindo a rastreabilidade total do sistema.

ESTRUTURA DO CASO DE TESTE

• ID do Teste: CT-001
• Requisito Associado: RF-01 (Autenticação JWT)
• Pré-condição: Usuário ativo no banco com e-mail cadastrado.
• Passos: Enviar requisição POST /api/auth/login com credenciais válidas.
• Resultado Esperado: Retorno HTTP Status 200 com token JWT válido na resposta JSON.

RELATÓRIO DE EXECUÇÃO

Documento ou saída consolidada que registra a data de execução, a quantidade de cenários testados, a taxa de sucesso/falha, os bugs encontrados (issues) e o status final de aprovação da suíte de testes.

💡 Por que criar um banco de testes separado? Executar testes diretamente no banco de desenvolvimento ou produção pode corromper ou apagar dados reais. O Plano de Testes deve definir o uso de scripts de automatização para criar, povoar e limpar a base de dados de teste (beforeEach e afterAll) a cada execução da suíte.
02

Tipos e Camadas de Teste Aplicados a APIs Node.js

⏱️ Duração Estimada: 60 min

Na engenharia de software de back-end, os testes são categorizados em diferentes níveis e responsabilidades, normalmente representados pelo conceito da Pirâmide de Testes.

1. TESTES UNITÁRIOS

Validam a menor unidade lógica do sistema de forma totalmente isolada (ex.: funções de cálculo de desconto, utilitários, validação de schemas com Zod). Não acessam banco de dados real nem fazem requisições de rede.

2. TESTES DE INTEGRAÇÃO

Verificam como múltiplos componentes funcionam juntas (ex.: rota do Express + Controller + repositório + banco PostgreSQL). Garantem que as requisições HTTP retornem os status e payloads corretos.

3. TESTES FUNCIONAIS / E2E

Simulam a jornada do usuário do início ao fim (End-to-End), integrando o Front-End HTML/CSS/JS com a API REST e o Banco de Dados, validando o comportamento real do produto sob o ponto de vista do cliente.

Exemplo de Caso de Teste de Integração (Express + Supertest)

Em uma aplicação Node.js com Express e Jest/Supertest, um caso de teste de integração avalia a rota REST e o banco de dados simultaneamente: 

// __tests__/produtos.test.js
const request = require('supertest');
const app = require('../src/app');
const { pool } = require('../src/config/database');

describe('POST /api/produtos - Cadastro de Produtos B2B', () => {
  
  // Limpeza dos dados de teste antes dos testes
  beforeAll(async () => {
    await pool.query('DELETE FROM produtos WHERE codigo_sku = $1', ['SKU-TEST-01']);
  });

  it('Deve cadastrar um produto válido e retornar status 201', async () => {
    const novoProduto = {
      nome: 'Servidor Rack 1U',
      codigo_sku: 'SKU-TEST-01',
      preco: 4500.00,
      estoque: 10
    };

    const response = await request(app)
      .post('/api/produtos')
      .set('Authorization', `Bearer ${global.tokenAutenticado}`)
      .send(novoProduto);

    expect(response.status).toBe(201);
    expect(response.body).toHaveProperty('id');
    expect(response.body.nome).toBe(novoProduto.nome);
  });
});
⚠️ Atenção à Pirâmide de Testes: A base da pirâmide deve conter uma quantidade massiva de testes unitários (rápidos e baratos), seguidos por um número intermediário de testes de integração e um número menor e bem selecionado de testes funcionais/E2E (mais lentos e custosos).

📚 Glossário Técnico da Aula

Plano de Testes (Test Plan)

Documento formal que descreve o escopo, a abordagem, os recursos e o cronograma das atividades de teste planejadas para um software.

Teste Unitário (Unit Test)

Teste automatizado focado em verificar o funcionamento de pequenas unidades isoladas de código, como funções e métodos, sem dependências externas.

Teste de Integração

Teste que avalia a interação entre diferentes módulos ou camadas do sistema, como as rotas HTTP do Express comunicando-se com o banco de dados.

Cobertura de Código (Code Coverage)

Métrica percentual que indica a quantidade de linhas, rotas ou ramificações de código executadas durante a suíte de testes.

❓ Quiz Final de Fixação

1. Qual é o principal objetivo da elaboração de um Plano de Testes de Software antes da execução dos testes em uma API REST Node.js?
A) Impedir que os desenvolvedores escrevam código em arquivos JavaScript.
B) Estabelecer o escopo, ambiente, estratégias, critérios de aceitação e responsabilidades para garantir systematicamente a qualidade do software.
C) Substituir a necessidade de utilizar um banco de dados relacional PostgreSQL.
D) Converter a API REST em um site estático sem interatividade.
✅ Resposta Correta: B) Estabelecer escopo, ambiente, estratégias e critérios para garantir a qualidade do software.
Justificativa: O Plano de Testes serve como o mapa estratégico que organiza todas as atividades de validação, definindo o que, como e quando testar.
2. Qual a principal característica de um Teste de Integração em uma aplicação Back-End Node.js/Express?
A) Testar apenas funções matemáticas em isolamento total, sem utilizar bibliotecas externas.
B) Validar a comunicação e a resposta combinada de múltiplos componentes, como o envio de uma requisição HTTP via Express e a persistência/consulta no banco PostgreSQL.
C) Testar a velocidade de digitação do desenvolvedor no terminal do VS Code.
D) Verificar exclusivamente o design e a paleta de cores das páginas HTML.
✅ Resposta Correta: B) Validar a comunicação e a resposta combinada de múltiplos componentes (ex.: Express + PostgreSQL).
Justificativa: Diferente dos testes unitários, os testes de integração garantem que os componentes e camadas do back-end funcionam perfeitamente integrados.
3. Por que é fundamental utilizar um banco de dados isolado e dedicado exclusivamente para o ambiente de testes (ex.: `b2b_db_test`)?
A) Para evitar o risco de alterar, apagar ou corromper dados reais do ambiente de desenvolvimento ou produção durante a execução das suítes de teste.
B) Porque o PostgreSQL não aceita mais de uma tabela no mesmo banco de dados.
C) Para garantir que o Node.js não precise de tokens JWT durante os testes.
D) Porque as consultas SQL só funcionam em bancos chamados `test`.
✅ Resposta Correta: A) Para evitar alterar ou corromper dados reais do ambiente de desenvolvimento/produção.
Justificativa: A execução de testes insere, altera e remove dados frequentemente. Um banco exclusivo garante isolamento, previsibilidade e segurança da informação.
