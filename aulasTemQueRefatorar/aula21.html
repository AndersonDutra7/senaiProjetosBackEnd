01

Ferramentas de Teste para Node.js — Testes de Rotas e Funções

⏱️ Duração Estimada: 60 min

Para garantir que uma aplicação server-side se comporte conforme esperado, utilizamos ecossistemas automatizados de testes. No universo Node.js, a combinação entre Jest (test runner e assertions) e Supertest (requisições HTTP virtuais) é o padrão de mercado mais utilizado.

1. Comparativo das Ferramentas de Teste no Ecossistema Node.js

Ferramenta Papel Principal Vantagens e Recursos Integrados
Jest Test Runner, Asserções e Mocks Zero configuração inicial, relatórios de cobertura embutidos (--coverage), execução paralela e sintaxe limpa (describe, it, expect).
Supertest Testes de Integração HTTP Permite disparar requisições GET, POST, PUT, DELETE diretamente para a instância da aplicação Express sem precisar alocar uma porta de rede real.
Mocha + Chai Framework de Testes + Asserção Arquitetura modular clássica que exige montagem individual do test runner (Mocha), biblioteca de asserção (Chai) e biblioteca de mocks (Sinon).

2. Estrutura de Código: Teste Unitário vs Teste de Rota HTTP

1. TESTE UNITÁRIO (Função / Regra)

// services/calculadoraDesconto.test.js
const { calcularDesconto } = require('./descontoService');

describe('Serviço de Desconto', () => {
  it('Deve aplicar 10% de desconto para compras acima de R$ 500', () => {
    const resultado = calcularDesconto(600.00);
    expect(resultado).toBe(540.00);
  });
});

2. TESTE DE ROTA (Supertest + Express)

// routes/autenticacao.test.js
const request = require('supertest');
const app = require('../src/app');

describe('POST /api/auth/login', () => {
  it('Deve retornar 401 para credenciais inválidas', async () => {
    const res = await request(app)
      .post('/api/auth/login')
      .send({ email: 'errado@test.com', senha: '123' });

    expect(res.status).toBe(401);
    expect(res.body.error).toBe('Credenciais inválidas');
  });
});
💡 Configuração Recomendada no package.json: adicione a flag --runInBand ao script de testes caso seus testes de integração façam edições concorrentes no banco de dados PostgreSQL de testes, garantindo execução sequencial e evitando conflitos de chave primária.
02

Execução de Testes e Relatório de Cobertura (Code Coverage)

⏱️ Duração Estimada: 45 min

A execução automatizada dos testes não apenas verifica a aprovação das regras de negócio, mas também gera métricas de qualidade chamadas de Code Coverage (Cobertura de Código). Essa análise identifica exatamente quais linhas, funções e ramificações condicionais (if/else) foram atingidas pela suíte de testes.

1. Análise das Métricas de Cobertura do Jest

% Statements

Mede a porcentagem de instruções/declarações executadas no código-fonte durante a execução dos testes.

% Branches

Mede se todas as ramificações lógicas (ex: blocos if/else, switch, operadores ternários) foram testadas em ambos os caminhos.

% Functions

Verifica quantas das funções e métodos declarados no projeto foram efetivamente chamados ao menos uma vez.

% Lines

Indica a porcentagem de linhas de código executadas pelo Jest, apontando exatamente quais trechos ficaram descobertos.

2. Estrutura de um Relatório de Execução de Testes Formal

Após a execução da bateria de testes proposta no Plano de Testes (Aula 20), a equipe compila os resultados no **Relatório de Execução de Testes (Test Execution Report)**. Este documento deve contemplar:

A

Resumo Numérico de Execução

Total de Casos de Teste planejados vs executados, taxa de aprovação (Pass), falhas (Fail) e ignorados (Skipped).

B

Métricas de Cobertura Alcançadas

Apresentação da porcentagem total de cobertura gerada pelo comando npm test -- --coverage no terminal.

C

Log de Defeitos e Erros Encontrados (Bug Tracking)

Registro das falhas identificadas durante a execução, severidade do bug, responsável pela correção e status (Resolvido / Pendente).

D

Parecer Final de Qualidade

Declaratório informando se a versão testada está homologada e estável para ser submetida ao processo de implantação/deploy.

03

Desafio Prático — Execução dos Testes da API do Projeto e Geração do Relatório

⏱️ Duração Estimada: 45 min

As equipes irão executar a suíte completa de testes unitários e de integração desenvolvidos para a API Node.js/PostgreSQL, analisar o relatório de cobertura HTML gerado pelo Jest e formalizar o documento de **Relatório de Execução de Testes**.

Roteiro de Execução do Desafio

1

Preparação do Ambiente de Banco de Testes

Garantir que a variável de ambiente aponta para o banco de testes (NODE_ENV=test) e rodar os scripts de criação de tabelas (schema.sql).

2

Disparo da Suíte e Geração de Coverage

Executar no terminal o comando npm test -- --coverage. Inspecionar os relatórios gerados na pasta coverage/lcov-report/index.html.

3

Correção de Falhas e Refatoração

Caso algum teste falhe (status `FAIL`), depurar o Controller/Model correspondente, corrigir o código e reexecutar a suíte até obter 100% de sucesso.

4

Elaboração do Documento `docs/RELATORIO_DE_TESTES.md`

Preencher o documento consolidando os resultados reais obtidos no terminal para cada Caso de Teste definido na Aula 20.

Modelo da Tabela de Execução para o Relatório

ID Caso Módulo / Rota Testada Resultado Esperado Resultado Obtido Status

CT-02 POST /api/login Status 401 para senha incorreta Status 401 retornado conforme esperado APROVADO
CT-03 POST /api/produtos Status 400 para preço negativo (Zod) Status 400 retornado com array de erros do Zod APROVADO

Encerramento: Glossário da Aula + Quiz Final de Fixação

⏱️ Duração Estimada: 30 min

📚 Glossário Técnico da Aula

Jest

Framework de testes em JavaScript desenvolvido pelo Meta, com suporte nativo a asserções, mocks e relatórios de cobertura de código.

Supertest

Biblioteca de abstração de testes HTTP que permite simular requisições contra aplicações web Node.js sem a necessidade de escutar portas reais.

Code Coverage

Métrica que indica o percentual de código-fonte de uma aplicação que é efetivamente testado pelas suítes de testes automatizados.

Relatório de Execução

Documento técnico que consolida as evidências, estatísticas de aprovação/falha e o registro de bugs encontrados durante a execução dos testes.

❓ Quiz Final de Fixação

1. Qual é a grande vantagem prática de utilizar a biblioteca `Supertest` em conjunto com o `Jest` para testar uma API REST criada em Express?
A) O Supertest converte as rotas do Express diretamente para linguagens de banco de dados SQL.
B) O Supertest permite realizar requisições HTTP simuladas diretamente sobre a instância da aplicação Express sem precisar abrir uma porta de rede real no sistema operacional.
C) O Supertest elimina a necessidade de tratar erros assíncronos na aplicação.
D) O Supertest substitui o uso do PostgreSQL por arquivos de texto.
✅ Resposta Correta: B) Permite realizar requisições simuladas sem precisar abrir uma porta de rede real.
Justificativa: O Supertest consome a instância do servidor Express diretamente, tornando os testes de integração HTTP extremamente ágeis e isolados de conflitos de rede.
2. O que a métrica de "Branch Coverage" (Cobertura de Ramificações) indica no relatório do Jest?
A) Quantas branches do repositório Git foram mescladas com a branch `main`.
B) A porcentagem de funções matemáticas do código que foram exportadas.
C) Se todas as alternativas de estruturas condicionais (como `if/else` ou `switch/case`) foram testadas em ambos os caminhos possíveis.
D) Quantas rotas foram excluídas da documentação da API.
✅ Resposta Correta: C) Se todas as alternativas de estruturas condicionais foram testadas nos caminhos verdadeiro e falso.
Justificativa: A cobertura de ramificações garante que não existam caminhos decisórios no código que tenham ficado sem validação pelos testes.
3. Qual é a principal finalidade de elaborar um Relatório de Execução de Testes ao final do ciclo de validações do software?
A) Consolidar as evidências de testes, registrar o percentual de aprovação, listar os bugs encontrados e formalizar a aprovação da aplicação para o deploy.
B) Desabilitar a validação de tokens JWT no ambiente de produção.
C) Apagar o histórico de commits do repositório Git do projeto.
D) Substituir o arquivo `.env` do servidor por um script em HTML.
✅ Resposta Correta: A) Consolidar evidências, estatísticas, bugs encontrados e formalizar a aprovação para deploy.
Justificativa: O relatório de execução é o documento auditável que comprova que o software atingiu os parâmetros de qualidade exigidos para ir à produção.
