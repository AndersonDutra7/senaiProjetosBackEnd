Com base no contexto apresentado, essa solicitação deve ser classificada pela equipe de desenvolvimento como:

  2. Uma restrição de infraestrutura, que define o sistema operacional exigido para o servidor de aplicação.

Considerando a demanda relatada, a ação mais adequada para correlacioná-la a uma especificação técnica consiste em:

  2. Especificar um requisito funcional de visão única do histórico do beneficiário, integrando as fontes existentes.
  3. Criar uma tela de login com autenticação em dois fatores para todos os atendentes da operadora.
  4. Substituir os sistemas por planilhas compartilhadas, mantidas manualmente pela equipe.
Para atender à demanda de uma empresa de representação comercial, que precisa calcular a comissão de cada vendedor conforme a faixa de vendas atingida, um analista aplicou uma fórmula de busca aproximada em planilha. A célula B2 contém o valor 12500.
A fórmula inserida na célula C2 foi =PROCV(B2; E2:F5; 2; VERDADEIRO).
Considerando a fórmula aplicada para atender à demanda do cliente, o resultado exibido na célula C2 corresponde a:
  1. 8%, pois a busca aproximada sempre retorna a faixa de maior percentual cadastrada na tabela de comissões.
  2. 2%, pois a busca aproximada retorna a primeira faixa da tabela, independentemente do valor pesquisado.
  3. 5%, pois a busca aproximada retorna a maior faixa cujo limite mínimo não ultrapassa 12500.
  4. #N/D, pois 12500 não existe como valor exato na primeira coluna da tabela.

Uma seguradora precisa guardar apólices em formato PDF por 10 anos e, ao mesmo tempo, garantir consulta rápida aos dados cadastrais dos segurados.
Considerando os requisitos de armazenamento descritos, a arquitetura mais adequada para atender ao cenário consiste em:
  1. Banco relacional para os dados cadastrais e armazenamento de objetos com política de retenção para os PDFs.
  2. Banco relacional único, com os PDFs gravados em coluna de texto e sem política de retenção definida.
  3. Arquivos PDF em pasta de uma estação de trabalho, com cópia manual semanal para outro disco.
  4. Memória volátil do servidor de aplicação, com reinicialização periódica para liberar espaço.
Em um sistema de reservas de passagens aéreas, duas operações simultâneas tentaram reservar o último assento de um voo. O requisito de armazenamento estabelece que cada transação deve ser executada como se fosse a única em andamento, sem enxergar dados intermediários de outras.
Com base no requisito descrito, a propriedade do modelo ACID que o banco de dados deve garantir para esse comportamento é:
  1. Atomicidade, que garante a execução integral da transação ou o desfazimento completo de todas as suas operações.
  2. Isolamento, que impede que transações simultâneas enxerguem ou alterem os dados intermediários umas das outras.
  3. Consistência, que assegura que cada transação leve o banco de um estado válido para outro válido.
  4. Durabilidade, que preserva os dados confirmados mesmo após falhas de energia ou reinicialização.
Na modelagem conceitual de um sistema de controle de frota, identificou-se que cada veículo possui placa, chassi e modelo, e que a placa o identifica de forma única na empresa.
Considerando o modelo de dados descrito, a placa do veículo deve ser classificada, tecnicamente, como:
  1. Entidade, pois representa um objeto do negócio com atributos próprios e relacionamentos com outras tabelas.
  2. Relacionamento, pois descreve a associação entre o veículo e o motorista responsável pelo seu uso.
  3. Atributo identificador, pois diferencia cada veículo e será a chave primária da tabela no modelo lógico.
  4. Chave estrangeira, pois referencia o registro de outra tabela para manter a integridade.
Em uma indústria, cada ordem de produção utiliza vários insumos e cada insumo pode ser utilizado em várias ordens, sendo necessário registrar a quantidade consumida de cada insumo em cada ordem.
Na transformação do modelo conceitual para o modelo lógico relacional, a solução adequada para esse relacionamento consiste em:
  1. Uma coluna na tabela de insumo contendo a lista de ordens de produção separadas por vírgula em um único campo.
  2. Duas tabelas independentes, sem chaves em comum, repetindo o nome do insumo em cada ordem de produção registrada.
  3. A chave primária de insumo replicada na tabela de ordem de produção, limitando cada ordem a um único insumo.
  4. Uma tabela associativa com as chaves das duas entidades e a coluna de quantidade consumida.

Na especificação de um portal de atendimento corporativo, foram registradas duas declarações:
I. "As senhas dos usuários devem ser armazenadas com hash criptográfico."
II. "O sistema deve permitir a exportação de relatórios em formato PDF."
Considerando as técnicas de levantamento de requisitos, a classificação correta das declarações I e II é, respectivamente:
  1. Funcional e funcional, pois ambas descrevem comportamentos que o sistema deve executar para o usuário final.
  2. Não funcional e funcional, pois a primeira define um atributo de segurança e a segunda, uma função do sistema.
  3. Funcional e não funcional, pois a primeira descreve uma ação e a segunda, um critério de desempenho.
  4. Não funcional e não funcional, pois ambas tratam de atributos de qualidade.
Em entrevistas de levantamento de requisitos, usuários de um sistema de gestão de contratos relataram ter apagado registros por engano, pois o botão "Excluir" executa a ação imediatamente, sem confirmação e sem possibilidade de desfazer.
Com base no relato dos usuários, a heurística de usabilidade de Nielsen mais diretamente violada nessa situação é:
  1. Consistência e padronização, pois a exclusão deveria seguir o mesmo padrão visual dos demais botões do sistema.
  2. Reconhecimento em vez de memorização, pois o sistema exige que o usuário lembre os dados antes de excluí-los.
  3. Prevenção de erros, pois o sistema executa uma ação destrutiva sem confirmação nem opção de desfazer.
  4. Estética e design minimalista, pois a tela exibe elementos em excesso ao redor do botão de exclusão.
Em uma auditoria de acessibilidade com base na WCAG 2.1 nível AA, constatou-se que os formulários da intranet corporativa usam apenas o texto de placeholder para identificar cada campo, e os leitores de tela não anunciam a finalidade dos campos.
Diante da constatação da auditoria, a especificação de correção que atende às diretrizes de acessibilidade consiste em:
  1. Manter apenas o placeholder como identificação visual e reforçar o contraste de cor do texto de exemplo exibido.
  2. Substituir os campos de texto por imagens com o nome de cada campo e descrição genérica no atributo alt.
  3. Incluir o texto de orientação em comentários HTML próximos aos campos, ocultos para os leitores de tela.
  4. Associar cada campo a um rótulo programático, usando label com o atributo for correspondente ao id.

  1. CREATE TABLE fornecedor (id INT PRIMARY KEY, razao_social VARCHAR(120) NOT NULL);

A equipe de suporte de uma loja virtual precisa reduzir em 10% o preço de todos os produtos da categoria 'perifericos' na tabela produto, sem afetar os demais produtos.
Seguindo as recomendações da linguagem de manipulação de dados, o comando SQL que executa essa alteração corretamente é:
  1. ALTER TABLE produto SET preco = preco * 0.90 WHERE categoria = 'perifericos';
  2. UPDATE produto SET preco = preco * 0.90 WHERE categoria = 'perifericos';
  3. INSERT INTO produto (preco) VALUES (preco * 0.90) WHERE categoria = 'perifericos';
  4. UPDATE produto SET preco = 0.90 WHERE categoria = 'perifericos';
Em um sistema de gestão de contratos, a tabela contrato possui a coluna id_cliente, que aceita valores nulos, e a restrição de chave estrangeira abaixo foi criada na definição dos dados.
Ao executar o comando DELETE FROM cliente WHERE id_cliente = 7;, o comportamento esperado do banco de dados é:
  1. O comando é rejeitado com erro de integridade referencial, pois há contratos vinculados ao cliente excluído.
  2. O cliente e todos os contratos vinculados a ele são removidos automaticamente na mesma operação.
  3. O cliente é removido e o id_cliente dos contratos vinculados passa a armazenar NULL, preservando-os.
  4. Somente os contratos vinculados são excluídos, e o registro do cliente permanece intacto.
