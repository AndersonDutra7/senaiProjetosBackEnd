Um desenvolvedor iniciou a criação de um projeto web em sua máquina local e deseja começar a rastrear o histórico de alterações dos arquivos utilizando a ferramenta Git.
Qual comando do Git deve ser executado na pasta do projeto para inicializar um repositório local?
  1. git push origin main, que envia os commits locais já registrados para o repositório remoto chamado origin.
  2. git init, que cria o repositório local e a pasta oculta .git dentro da pasta do projeto.
  3. git commit -m "Inicial", que registra uma versão com a mensagem informada.
  4. git clone, que copia um repositório remoto.
Ao realizar o comando git merge feature/login na branch main, o Git reportou um conflito de integração no arquivo src/auth.js.
Qual é a sequência correta de comandos para resolver o conflito de forma segura?
  1. Executar git push --force imediatamente para sobrescrever o histórico do repositório remoto com a versão local da branch.
  2. Executar git reset --hard e excluir a branch feature/login, descartando todo o trabalho feito nela.
  3. Apagar o diretório .git local e clonar o repositório novamente.
  4. Editar o arquivo, usar git add e git commit.
Um commit contendo um erro crítico de produção já foi publicado na branch remota pública compartilhada pela equipe. É necessário desfazer as alterações mantendo a integridade do histórico público.
Qual é o procedimento recomendado no Git?
  1. Utilizar git revert <hash_do_commit>, que gera um novo commit desfazendo as alterações sem reescrever o histórico público.
  2. Executar git reset --hard HEAD~1 seguido de git push --force para apagar o commit do remoto.
  3. Remover o arquivo afetado manualmente do disco sem registrar commit.
  4. Utilizar git clean -fd no servidor.
Na arquitetura de sistemas web, o protocolo HTTP utiliza verbos para indicar a ação a ser realizada nos recursos do servidor.
Qual método HTTP é o padrão recomendado para submeter formulários que criam um novo registro no servidor?
  1. GET, método usado para consultar e recuperar recursos já existentes, sem criar novos registros no servidor.
  2. OPTIONS, método que informa ao cliente quais operações o servidor aceita para o recurso.
  3. POST, método usado para enviar dados e criar um novo recurso.
  4. DELETE, método que remove um recurso.
Na arquitetura de APIs RESTful, a idempotência garante que requisições múltiplas idênticas produzam o mesmo efeito no estado do servidor.
Quais métodos HTTP são originalmente idempotentes pela especificação do protocolo web?
  1. GET, PUT e DELETE, pois repetir a mesma requisição várias vezes não altera o estado do servidor além da primeira.
  2. GET, POST e PUT, pois os três apenas consultam ou substituem dados já existentes.
  3. POST e PATCH, pois ambos criam novos recursos.
  4. POST e DELETE.
Uma API REST precisa responder a uma requisição onde um cliente autenticado tenta acessar um recurso sem possuir o papel (role) de permissão necessário no sistema web.
Qual código de status HTTP deve ser retornado por essa rota para indicar falta de autorização de acesso?
  1. 401 (Unauthorized), pois indica que a credencial do usuário é inválida ou não foi informada na requisição.
  2. 404 (Not Found), pois o recurso solicitado não existe no servidor ou foi movido.
  3. 400 (Bad Request), pois o formato da requisição está inválido.
  4. 403 (Forbidden), pois o acesso é negado.

A eliminação de grupos repetidos e valores multivalorados atende às regras de qual Forma Normal?
  1. Forma Normal de Boyce-Codd (BCNF), que trata dependências em que um determinante não é chave candidata.
  2. Terceira Forma Normal (3FN), que elimina dependências transitivas entre atributos não chave.
  3. Segunda Forma Normal (2FN), que elimina dependências parciais da chave primária.
  4. Primeira Forma Normal (1FN).
