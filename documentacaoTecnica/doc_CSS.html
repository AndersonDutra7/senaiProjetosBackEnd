CSS — Referência de Propriedades

Documentação de consulta rápida para uso das propriedades CSS em qualquer projeto — independente do sistema que você estiver construindo.

Seletores Fundamentos

Determinam quais elementos HTML recebem um determinado estilo — a base de qualquer regra CSS.

O que é

Um seletor é o "alvo" da regra CSS: define para quais elementos da página aquele conjunto de estilos vai se aplicar. Podem ser combinados de várias formas — por tipo de elemento, classe, id, atributo, ou pela relação entre elementos (um dentro do outro, um logo depois do outro).

Sintaxe genérica

seletor {
  propriedade: valor;
}

Valores principais

Seletor Para que serve Exemplo
elemento Seleciona todos os elementos daquele tipo p { }
.classe Seleciona todos os elementos com aquela classe .cartao { }
#id Seleciona o único elemento com aquele id #topo { }
a b Seleciona todo b que esteja dentro de a, em qualquer nível nav a { }
a > b Seleciona b apenas quando é filho direto de a ul > li { }
a, b Aplica o mesmo estilo a a e a b h1, h2 { }

Quando usar

  • Use seletores de classe (.classe) como padrão para a maioria dos estilos — são reutilizáveis e fáceis de manter.
  • Use o seletor de descendência (a b) com moderação — ele aumenta a especificidade e pode dificultar sobrescrever o estilo depois.
  • Reserve #id para casos únicos, e não como prática padrão de estilização.

Exemplo

.cartao-produto {
  border: 1px solid #ccc;
}

.cartao-produto h3 {
  margin: 0;
}

.cartao-produto:hover {
  border-color: #333;
}

Boas práticas / erros comuns

Fazer

  • Preferir classes reutilizáveis em vez de ids para estilização geral
  • Nomear classes pelo papel do elemento, não pela aparência (.cartao-destaque, não .azul)

Evitar

  • Encadear seletores muito profundos (div div div .item) — fica frágil e difícil de sobrescrever depois
Cascata & especificidade Fundamentos

As regras que decidem qual estilo "vence" quando mais de uma regra CSS tenta afetar o mesmo elemento.

O que é

O "C" de CSS vem de Cascading (cascata): quando duas regras conflitam, o navegador decide qual aplicar com base em três fatores, nesta ordem de prioridade: origem/importância (ex.: !important vence), depois especificidade (quão "específico" é o seletor) e, por último, ordem no código (a regra escrita por último vence em caso de empate).

Sintaxe genérica

/* especificidade crescente: elemento < classe < id */
p { color: black; }
.destaque { color: blue; }
#titulo { color: red; }

Valores principais

Tipo de seletor Peso na especificidade
Seletor de elemento (p, div) Peso baixo
Classe (.destaque), atributo, pseudo-classe (:hover) Peso médio
Id (#titulo) Peso alto
Estilo inline (style="...") Peso muito alto
!important Sobrepõe tudo (evitar usar)

Quando usar

  • Entenda a cascata para saber por que um estilo "não está aplicando" — normalmente é outra regra com especificidade maior, ou escrita depois no arquivo.
  • Mantenha a especificidade baixa e consistente (majoritariamente classes) para que os estilos sejam fáceis de sobrescrever quando necessário.

Exemplo

/* Esta regra vence, mesmo vindo antes, por ter maior especificidade (id > classe) */
#botao-principal { background: black; }
.botao { background: gray; }

Boas práticas / erros comuns

Fazer

  • Resolver conflitos de estilo ajustando a especificidade do seletor, não empilhando !important

Evitar

  • Usar !important como solução padrão — isso quebra a cascata natural e dificulta manutenção futura
  • Misturar ids e classes de forma inconsistente na mesma base de código
Box model Fundamentos

O modelo que descreve como o navegador calcula o tamanho de qualquer elemento: conteúdo, espaçamento interno, borda e espaçamento externo.

O que é

Todo elemento HTML é tratado pelo navegador como uma caixa retangular, composta por quatro camadas, de dentro para fora: content (o conteúdo em si), padding (espaço interno, entre o conteúdo e a borda), border (a borda) e margin (espaço externo, entre a caixa e os elementos vizinhos).

Sintaxe genérica

.caixa {
  width: 200px;
  padding: 16px;
  border: 1px solid #ccc;
  margin: 24px;
}

Valores principais

Propriedade Para que serve Exemplo
padding Espaço interno, entre o conteúdo e a borda padding: 16px 24px;
border Borda da caixa (espessura, estilo, cor) border: 1px solid #333;
margin Espaço externo, entre a caixa e os elementos vizinhos margin: 24px auto;
box-sizing Define se width/height incluem ou não padding/border no cálculo box-sizing: border-box;

Quando usar

  • Use box-sizing: border-box como padrão do projeto (geralmente aplicado globalmente com * { box-sizing: border-box; }) — assim, padding e border não aumentam o tamanho final declarado em width.
  • Use margin para o espaço entre elementos diferentes, e padding para o espaço dentro de um mesmo elemento.

Exemplo

* {
  box-sizing: border-box;
}

.cartao {
  width: 300px;
  padding: 20px;
  border: 1px solid #ddd;
  margin-bottom: 16px;
}

Boas práticas / erros comuns

Fazer

  • Definir box-sizing: border-box globalmente logo no início do CSS do projeto

Evitar

  • Calcular width manualmente descontando padding/border, sem usar border-box — fica frágil a qualquer mudança futura
Unidades Fundamentos

As formas de medir tamanhos, espaçamentos e posições em CSS — cada uma se comporta de um jeito diferente conforme o contexto.

O que é

CSS oferece unidades absolutas (sempre o mesmo tamanho físico) e relativas (calculadas com base em outra referência, como o tamanho da fonte ou da tela). A escolha da unidade certa afeta diretamente o quão responsivo e acessível o layout se comporta.

Sintaxe genérica

.texto {
  font-size: 1rem;
  margin-bottom: 1.5em;
  width: 50%;
}

Valores principais

Unidade Se baseia em Uso comum
px Pixel fixo, não escala Bordas finas, detalhes que não devem mudar de tamanho
% Porcentagem do elemento pai Larguras fluidas dentro de um contêiner
rem Tamanho da fonte raiz (html) Tipografia e espaçamentos que escalam de forma previsível
em Tamanho da fonte do próprio elemento (ou do pai, em alguns casos) Espaçamentos proporcionais ao texto ao redor
vw / vh Largura/altura da janela do navegador (viewport) Elementos que ocupam uma fração da tela (ex.: seção de tela cheia)

Quando usar

  • Use rem como padrão para tipografia e espaçamentos — evita o efeito cascata inesperado do em em elementos aninhados.
  • Use % para larguras que devem se adaptar ao contêiner pai.
  • Use px para detalhes que realmente não devem escalar (bordas finas, sombras).
  • Use vw/vh com cautela — funcionam bem para seções de tela cheia, mas podem gerar textos ilegíveis em telas muito pequenas ou grandes se usados sem limites.

Exemplo

html {
  font-size: 16px; /* referência para todo rem da página */
}

.titulo {
  font-size: 2rem;      /* 32px, mas escalável */
  margin-bottom: 1.5rem;
}

.banner {
  width: 100%;
  height: 60vh;
}

Boas práticas / erros comuns

Fazer

  • Usar rem como unidade padrão de tipografia, garantindo que tudo escale junto se o usuário ajustar o tamanho de fonte do navegador

Evitar

  • Usar px para tamanho de fonte como prática padrão — dificulta a acessibilidade para usuários que aumentam a fonte do navegador
  • Usar vw/vh sem min/max de segurança, arriscando textos ilegíveis em telas extremas
width & height Visual

As propriedades que definem o tamanho de um elemento, e os limites mínimo e máximo que esse tamanho pode assumir.

O que é

width e height definem a largura e altura de um elemento (do conteúdo, ou da caixa inteira, dependendo de box-sizing — ver Box model). min-width/max-width e min-height/max-height impõem limites que a dimensão não pode ultrapassar, mesmo que width/height seja flexível (ex.: %) ou o conteúdo interno force um tamanho diferente.

Sintaxe genérica

.elemento {
  width: 100%;
  max-width: 600px;
  min-height: 200px;
}

Valores principais

Propriedade Para que serve Exemplo
width / height Tamanho declarado do elemento width: 300px;
max-width Impede que a largura ultrapasse um limite, mesmo com width flexível max-width: 100%;
min-width Impede que a largura fique abaixo de um limite min-width: 120px;
max-height / min-height Mesma lógica de max-width/min-width, na vertical min-height: 100vh;
auto Deixa o navegador calcular o tamanho com base no conteúdo ou no contexto (valor padrão) height: auto;

Quando usar

  • Use max-width em vez de width fixo para elementos que devem encolher em telas pequenas mas não crescer indefinidamente em telas grandes (ex.: max-width: 600px; width: 100%;).
  • Use min-height para garantir uma altura mínima (ex.: um cartão vazio não "colapsar"), sem impedir que cresça se o conteúdo for maior.
  • Evite fixar height em elementos com texto — prefira min-height, já que a quantidade de texto pode variar e um height fixo corta ou sobrepõe conteúdo.

Exemplo

.container {
  width: 100%;
  max-width: 1180px;
  margin: 0 auto;
}

.cartao {
  min-height: 160px;
  max-width: 320px;
}

Boas práticas / erros comuns

Fazer

  • Combinar width: 100% com max-width como padrão para containers responsivos
  • Usar min-height em vez de height fixo sempre que o conteúdo interno puder variar de tamanho

Evitar

  • Fixar height em elementos com texto dinâmico — gera overflow ou corte de conteúdo quando o texto é maior que o esperado
  • Usar apenas width fixo em px sem max-width em containers principais, quebrando o layout em telas menores que o valor definido
Tipografia Visual

As propriedades que controlam a aparência do texto: fonte, tamanho, peso, espaçamento e alinhamento.

O que é

Um conjunto de propriedades que define como o texto é renderizado na página — qual fonte usar, seu tamanho, peso (negrito/normal), espaçamento entre linhas e letras, e alinhamento. Uma boa base tipográfica afeta diretamente a legibilidade e a hierarquia visual do conteúdo.

Sintaxe genérica

.texto {
  font-family: Georgia, serif;
  font-size: 1rem;
  font-weight: 400;
  line-height: 1.6;
  letter-spacing: 0.01em;
  text-align: left;
}

Valores principais

Propriedade Para que serve Exemplo
font-family Define a(s) fonte(s), em ordem de preferência, com um fallback genérico ao final font-family: Charter, Georgia, serif;
font-size Tamanho do texto font-size: 1.125rem;
font-weight Peso/espessura da fonte font-weight: 600;
line-height Altura da linha, afeta o espaçamento vertical entre linhas de texto line-height: 1.5;
letter-spacing Espaçamento entre letras letter-spacing: 0.02em;
text-align Alinhamento horizontal do texto text-align: center;

Quando usar

  • Defina uma escala de tamanhos (ex.: --fs-sm, --fs-base, --fs-lg) em vez de valores soltos, para manter hierarquia consistente entre títulos e texto.
  • Use line-height sem unidade (ex.: 1.5) em vez de valor fixo em px, para que escale corretamente com o font-size de cada elemento.
  • Sempre inclua uma fonte de fallback genérica (serif, sans-serif, monospace) ao final de font-family, caso a fonte principal não carregue.

Exemplo

body {
  font-family: Charter, Georgia, serif;
  font-size: 1rem;
  line-height: 1.65;
}

h1 {
  font-family: 'Iowan Old Style', Georgia, serif;
  font-size: 2rem;
  font-weight: 600;
  line-height: 1.2;
}

.texto-discreto {
  font-size: 0.875rem;
  color: var(--text-muted);
}

Boas práticas / erros comuns

Fazer

  • Usar line-height proporcional (sem unidade) para manter o espaçamento coerente em qualquer tamanho de fonte
  • Limitar a largura do texto (ex.: max-width: 65ch) para manter linhas confortáveis de leitura

Evitar

  • Usar muitas famílias de fonte diferentes na mesma página — prejudica consistência visual e desempenho de carregamento
  • Definir line-height em px fixo — não escala bem quando o font-size muda em elementos filhos
Cores Visual

Os formatos que o CSS aceita para definir cor e as propriedades que os aplicam a elementos.

O que é

CSS permite declarar cores em diferentes formatos — palavra-chave, hexadecimal, rgb()/rgba() ou hsl()/hsla() — e aplicá-las a propriedades como color (texto), background-color (fundo) e border-color (borda). Cada formato representa a mesma informação de cor de um jeito diferente, e a escolha costuma depender do quanto você precisa ajustar transparência ou variar tons de forma programática.

Sintaxe genérica

.elemento {
  color: #1a1a1a;
  background-color: rgba(0, 0, 0, 0.05);
  border-color: hsl(210, 50%, 40%);
}

Valores principais

Formato Exemplo Quando é útil
Palavra-chave red, white, transparent Protótipos rápidos e valores especiais como transparent e currentColor
Hexadecimal #1a1a1a, #fff Cores fixas de um design system, fácil de copiar de ferramentas de design
rgb() / rgba() rgba(26, 26, 26, 0.5) Quando é preciso controlar opacidade junto com a cor
hsl() / hsla() hsl(210, 50%, 40%) Ajustar tonalidade, saturação ou luminosidade de forma previsível (ex.: variações de uma mesma cor)
currentColor border-color: currentColor; Herdar automaticamente o valor de color do próprio elemento

Quando usar

  • Centralize a paleta do projeto em custom properties (--cor-primaria: hsl(...)) em vez de repetir valores fixos em vários seletores.
  • Prefira hsl() quando precisar gerar variações (mais claro/mais escuro) de uma mesma cor base, ajustando só a luminosidade.
  • Use rgba()/hsla() para camadas semitransparentes (overlays, sombras suaves) em vez de criar uma cor sólida "parecida".

Exemplo

:root {
  --cor-primaria: hsl(210, 60%, 45%);
  --cor-primaria-clara: hsl(210, 60%, 92%);
}

.botao {
  background-color: var(--cor-primaria);
  color: white;
}

.botao:hover {
  background-color: hsl(210, 60%, 38%);
}

Boas práticas / erros comuns

Fazer

  • Definir a paleta como custom properties no :root, garantindo consistência e facilidade de tema (ex.: dark mode)
  • Verificar o contraste entre texto e fundo (mínimo recomendado 4.5:1 para texto normal) por acessibilidade

Evitar

  • Espalhar o mesmo valor hexadecimal "mágico" em dezenas de lugares — dificulta trocar a cor depois
  • Misturar formatos de cor sem padrão no mesmo projeto (hex em um lugar, rgb em outro) sem motivo
Background Visual

As propriedades que controlam o fundo de um elemento: cor, imagem, repetição, posição e tamanho.

O que é

Um conjunto de propriedades que define o que aparece atrás do conteúdo de um elemento — desde uma cor sólida simples até uma ou mais imagens, com controle de posição, repetição e tamanho. A propriedade abreviada background combina várias dessas em uma única declaração.

Sintaxe genérica

.elemento {
  background-color: #f1f0ec;
  background-image: url("fundo.jpg");
  background-repeat: no-repeat;
  background-position: center;
  background-size: cover;
}

Valores principais

Propriedade Para que serve Exemplo
background-color Cor de fundo sólida background-color: #fff;
background-image Imagem ou gradiente de fundo background-image: linear-gradient(to right, #000, #fff);
background-repeat Se e como a imagem se repete background-repeat: no-repeat;
background-position Posição da imagem dentro da caixa background-position: center top;
background-size Dimensionamento da imagem (cover preenche a caixa, contain encaixa inteira) background-size: cover;

Quando usar

  • Use background-size: cover para imagens de fundo que devem preencher toda a área sem distorcer, aceitando cortes nas bordas.
  • Use background-size: contain quando a imagem inteira precisa ficar visível, mesmo que sobre espaço vazio.
  • Combine background-color junto com background-image como fallback, caso a imagem não carregue.

Exemplo

.hero {
  background-color: #1a1a1a;
  background-image: url("banner.jpg");
  background-repeat: no-repeat;
  background-position: center;
  background-size: cover;
  min-height: 60vh;
}

Boas práticas / erros comuns

Fazer

  • Sempre definir uma background-color de fallback junto com background-image
  • Usar a abreviada background quando várias propriedades forem definidas juntas, para deixar o código mais enxuto

Evitar

  • Usar imagens de fundo muito pesadas sem otimização — impacta diretamente o tempo de carregamento da página
  • Esquecer background-repeat: no-repeat em imagens que não devem se repetir, gerando um efeito de "ladrilho" indesejado
Bordas Visual

As propriedades que desenham a borda de um elemento — espessura, estilo, cor — e que arredondam seus cantos.

O que é

border é uma propriedade abreviada que combina espessura (border-width), estilo de linha (border-style) e cor (border-color) em uma única declaração. Além disso, border-radius arredonda os cantos da caixa, independentemente de haver ou não uma borda visível.

Sintaxe genérica

.elemento {
  border: 1px solid #ccc;
  border-radius: 8px;
}

Valores principais

Propriedade Para que serve Exemplo
border-width Espessura da borda border-width: 2px;
border-style Estilo da linha (obrigatório para a borda aparecer) border-style: solid; / dashed / dotted
border-color Cor da borda border-color: #333;
border-radius Arredondamento dos cantos border-radius: 50%; (círculo, em elemento quadrado)
border-top / -right / -bottom / -left Define a borda de apenas um lado border-bottom: 2px solid black;

Quando usar

  • Use a abreviada border quando espessura, estilo e cor forem definidos juntos — é mais curto e comum na prática.
  • Use bordas em apenas um lado (ex.: border-bottom) para separadores visuais, sublinhados de abas ou indicadores de estado ativo.
  • Lembre que border-style é obrigatório: sem ele (o padrão é none), border-width e border-color não têm efeito visível.

Exemplo

.avatar {
  border-radius: 50%;
  border: 2px solid var(--cor-primaria);
}

.aba-ativa {
  border-bottom: 3px solid var(--cor-primaria);
}

Boas práticas / erros comuns

Fazer

  • Usar box-sizing: border-box (ver Box model) para que a borda não aumente o tamanho final do elemento
  • Usar valores relativos ou uma escala consistente de border-radius (ex.: 4px, 8px, 16px) para manter o visual coeso entre componentes

Evitar

  • Declarar border-color ou border-width sem border-style e esperar que a borda apareça
  • Usar border para criar espaçamento visual — isso é função do padding/margin, não da borda
Gradientes Visual

Transições suaves entre duas ou mais cores, usadas como valor de background-image — sem precisar de nenhum arquivo de imagem.

O que é

Um gradiente é uma função CSS que gera uma imagem de transição de cores "on the fly". Os três tipos principais são linear-gradient() (transição em linha reta, numa direção/ângulo), radial-gradient() (transição a partir de um ponto central, se espalhando em círculo ou elipse) e conic-gradient() (transição rotacionando em torno de um ponto, como um relógio). Por serem valores de background-image, aceitam as mesmas propriedades de repetição, posição e tamanho já vistas em Background.

Sintaxe genérica

.elemento {
  background-image: linear-gradient(to right, #000, #fff);
}

Valores principais

Função Direção/forma Exemplo
linear-gradient() Ângulo ou palavra-chave de direção (to right, 45deg) linear-gradient(45deg, red, blue);
radial-gradient() Forma (circle ou ellipse) e posição do centro radial-gradient(circle at center, white, gray);
conic-gradient() Ângulo de partida e posição do centro, rotacionando ao redor conic-gradient(from 0deg, red, yellow, green, red);
Paradas de cor (color stops) Posição percentual onde cada cor "trava" na transição linear-gradient(red 0%, blue 50%, red 100%);

Quando usar

  • Use linear-gradient para fundos de seções, botões e overlays de legibilidade sobre imagens (ex.: escurecer a parte de baixo de um banner).
  • Use radial-gradient para efeitos de "destaque" ou luz vindo de um ponto (ex.: spotlight, vinheta).
  • Combine múltiplos gradientes ou um gradiente com background-image de foto (separados por vírgula) para criar overlays de cor sobre imagens reais.

Exemplo

.banner-com-overlay {
  background-image:
    linear-gradient(to bottom, rgba(0,0,0,0) 0%, rgba(0,0,0,0.6) 100%),
    url("banner.jpg");
  background-size: cover;
  background-position: center;
}

.spotlight {
  background-image: radial-gradient(circle at top left, #fff, var(--cor-primaria));
}

Boas práticas / erros comuns

Fazer

  • Usar gradientes em vez de imagens estáticas para transições de cor simples — menos peso, escala perfeitamente e é fácil de ajustar via custom properties
  • Empilhar um gradiente sobre uma foto (via vírgula em background-image) para garantir contraste de texto sobre imagens

Evitar

  • Esquecer que gradiente é um valor de background-image, não de background-color — tentar usá-lo em background-color não funciona
  • Abusar de muitas paradas de cor ou ângulos aleatórios sem propósito — dificulta manutenção e pode gerar bandas visuais perceptíveis
display Layout

A propriedade que define como um elemento se comporta no fluxo do layout — se ocupa a linha toda, se fica lado a lado com outros, ou se vira um contêiner flexível/grid.

O que é

display determina o tipo de "caixa" que um elemento gera. Isso afeta duas coisas ao mesmo tempo: como o próprio elemento se posiciona em relação aos vizinhos (comportamento externo) e como ele organiza seus filhos internamente (comportamento interno). É a propriedade mais fundamental de layout em CSS — praticamente toda técnica de organização de página parte de um valor de display.

Sintaxe genérica

.elemento {
  display: block;
}

Valores principais

Valor Comportamento
block Ocupa toda a largura disponível e sempre começa em uma nova linha (ex.: div, p, h1)
inline Ocupa só o espaço do conteúdo, fica lado a lado com outros elementos; ignora width/height e margin vertical (ex.: span, a)
inline-block Fica lado a lado como inline, mas aceita width/height e margin vertical como block
flex Transforma o elemento em contêiner flexível de uma dimensão para seus filhos diretos
grid Transforma o elemento em contêiner de grade bidimensional para seus filhos diretos
none Remove o elemento do fluxo do layout completamente — ele deixa de ocupar espaço e de ser renderizado

Quando usar

  • Use flex para organizar itens em uma linha ou coluna (barras de navegação, cartões alinhados, centralização simples).
  • Use grid quando o layout precisa de linhas e colunas simultaneamente (páginas inteiras, galerias).
  • Use inline-block como alternativa simples quando só é preciso alinhar poucos elementos lado a lado sem virar um contêiner flex/grid completo.
  • Use none para esconder elementos que não devem ocupar espaço nem ser lidos por leitores de tela (diferente de visibility: hidden, que mantém o espaço reservado).

Exemplo

.menu {
  display: flex;
  gap: 16px;
}

.menu__item {
  display: inline-block;
  padding: 8px 12px;
}

.menu__badge--oculto {
  display: none;
}

Boas práticas / erros comuns

Fazer

  • Escolher flex ou grid de propósito conforme a dimensão do layout (uma direção vs. duas), em vez de recorrer a float ou hacks de posicionamento

Evitar

  • Tentar aplicar width/height ou margin vertical em um elemento inline esperando que funcione — nesses casos, ele precisa virar inline-block ou block
  • Usar display: none para animações de entrada/saída — como o elemento some do fluxo instantaneamente, não há transição possível (usar opacity/visibility nesse caso)
position Layout

A propriedade que tira um elemento do fluxo normal (ou não) e permite posicioná-lo usando top, right, bottom e left.

O que é

position define como um elemento é posicionado no documento. O valor escolhido muda o comportamento das propriedades top/right/bottom/left (offsets) e determina se o elemento continua ocupando espaço no fluxo normal do layout ou é removido dele.

Sintaxe genérica

.elemento {
  position: relative;
  top: 10px;
  left: 20px;
}

Valores principais

Valor Comportamento
static Padrão. Segue o fluxo normal; offsets (top, etc.) não têm efeito
relative Continua no fluxo normal (mantém o espaço original), mas pode ser deslocado visualmente com offsets a partir da própria posição
absolute Sai do fluxo (não ocupa espaço) e se posiciona em relação ao ancestral posicionado mais próximo (qualquer valor diferente de static)
fixed Sai do fluxo e se posiciona em relação à janela do navegador (viewport), permanecendo fixo mesmo com scroll
sticky Comporta-se como relative até atingir um limite de scroll definido por offset, quando passa a se comportar como fixed

Offsets: top, right, bottom, left

Essas quatro propriedades deslocam um elemento a partir de uma borda de referência, mas só têm efeito quando position é diferente de static (o padrão). O significado da referência muda conforme o valor de position: em relative, a referência é a própria posição original do elemento; em absolute/fixed/sticky, é a borda do contêiner de referência (ou da viewport, no caso de fixed).

Propriedade Desloca a partir de Exemplo
top Borda superior top: 0;
right Borda direita right: 16px;
bottom Borda inferior bottom: 0;
left Borda esquerda left: 16px;

Definir os quatro ao mesmo tempo com valor 0 (top: 0; right: 0; bottom: 0; left: 0;) faz o elemento esticar para preencher todo o contêiner de referência — um padrão comum para overlays em tela cheia.

Quando usar

  • Use relative no elemento pai apenas para servir de referência a um filho absolute — é o padrão mais comum ("contexto de posicionamento").
  • Use absolute para elementos decorativos ou sobrepostos dentro de um contêiner específico (badges, ícones sobre imagem, tooltips).
  • Use fixed para elementos que devem ficar sempre visíveis na tela, independente do scroll (cabeçalho fixo, botão flutuante).
  • Use sticky para elementos que devem "grudar" ao rolar a página até certo ponto, mas continuar fazendo parte do fluxo (o índice lateral deste próprio documento usa isso).

Exemplo

.cartao {
  position: relative;
}

.cartao__badge {
  position: absolute;
  top: 8px;
  right: 8px;
}

.cabecalho {
  position: sticky;
  top: 0;
}

Boas práticas / erros comuns

Fazer

  • Sempre definir position: relative no ancestral pretendido antes de usar absolute em um filho — senão ele se posiciona em relação a um ancestral mais distante (ou à página inteira)

Evitar

  • Usar position: absolute como substituto de Flexbox/Grid para organizar um layout inteiro — funciona melhor para elementos pontuais e sobrepostos, não para estruturar a página
  • Esquecer que sticky não funciona se algum elemento ancestral tiver overflow: hidden ou overflow: auto — o efeito é silenciosamente ignorado
Flexbox Layout

Um modelo de layout unidimensional que distribui e alinha itens em linha ou coluna dentro de um contêiner.

O que é

Flexbox organiza os filhos diretos de um contêiner (display: flex) ao longo de um único eixo — horizontal ou vertical. As propriedades se dividem em duas categorias: as que vão no contêiner (definem a direção e como distribuir/alinhar os itens) e as que vão nos itens (permitem que cada filho cresça, encolha ou se comporte de forma individual).

Sintaxe genérica

.container {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 16px;
}

Valores principais

Propriedade Onde vai Para que serve
flex-direction Contêiner Define o eixo principal: row (padrão, horizontal) ou column (vertical)
justify-content Contêiner Alinha/distribui os itens ao longo do eixo principal (center, space-between, flex-end...)
align-items Contêiner Alinha os itens no eixo transversal (perpendicular ao principal)
flex-wrap Contêiner Permite que os itens quebrem para a próxima linha quando não cabem
gap Contêiner Espaçamento entre os itens, sem precisar de margin manual
flex-grow Item Define o quanto o item pode crescer para ocupar espaço extra disponível
flex-shrink Item Define o quanto o item pode encolher quando falta espaço

Quando usar

  • Use Flexbox para organizar elementos em uma única direção: barras de navegação, grupos de botões, centralização vertical/horizontal simples.
  • Use gap em vez de margin nos itens para espaçamento — evita ter que remover a margem do último item manualmente.
  • Use flex-wrap: wrap quando o número de itens é variável e pode não caber em uma única linha (ex.: tags, chips).
  • Prefira Grid (próxima entrada) quando o layout precisar controlar linhas e colunas ao mesmo tempo — Flexbox foi pensado para uma dimensão.

Exemplo

.navbar {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 24px;
}

.card-grupo {
  display: flex;
  flex-wrap: wrap;
  gap: 16px;
}

.card-grupo > .cartao {
  flex: 1 1 240px; /* cresce, encolhe, base de 240px */
}

Boas práticas / erros comuns

Fazer

  • Usar a abreviada flex (flex: 1 1 240px;) em vez de declarar flex-grow, flex-shrink e flex-basis separadamente
  • Combinar flex-wrap: wrap com gap para grupos de tamanho variável, ao invés de calcular larguras manualmente

Evitar

  • Confundir justify-content com align-items — o primeiro sempre atua no eixo principal (que muda com flex-direction), o segundo no eixo transversal
  • Usar Flexbox para tentar alinhar itens em grade com linhas e colunas independentes — sem flex-wrap controlado isso gera desalinhamento entre linhas, que é justamente o problema que o Grid resolve
Flex items Layout

As propriedades que vão nos filhos de um contêiner flex, controlando o comportamento individual de cada item — diferente das propriedades do contêiner, que afetam o grupo todo.

O que é

Enquanto propriedades como justify-content e align-items ficam no contêiner e afetam todos os filhos de uma vez, existe um conjunto de propriedades que vai em cada item individualmente — permitindo que um item específico cresça mais que os outros, ignore o alinhamento geral, ou apareça em outra ordem visual sem alterar o HTML.

Sintaxe genérica

.item {
  flex: 1 1 200px;
  align-self: flex-end;
  order: -1;
}

Valores principais

Propriedade Para que serve Exemplo
flex-grow Quanto o item cresce para ocupar espaço extra, relativo aos outros itens flex-grow: 2; (cresce o dobro de um irmão com 1)
flex-shrink Quanto o item encolhe quando falta espaço flex-shrink: 0; (nunca encolhe)
flex-basis Tamanho inicial do item antes de crescer/encolher flex-basis: 200px;
flex Abreviada de flex-grow, flex-shrink e flex-basis flex: 1 1 200px;
align-self Sobrescreve o align-items do contêiner só para este item align-self: center;
order Muda a ordem visual do item, sem alterar a ordem no HTML order: -1; (aparece primeiro)

Quando usar

  • Use flex: 1; (atalho para flex-grow: 1) em itens que devem dividir igualmente o espaço restante do contêiner.
  • Use flex-shrink: 0 em elementos que não podem encolher (ex.: um ícone ou avatar de tamanho fixo ao lado de um texto flexível).
  • Use align-self com moderação, para exceções pontuais — se a maioria dos itens precisa do mesmo alinhamento, ajuste align-items no contêiner em vez de repetir align-self em todos os filhos.
  • Use order apenas para reordenação visual (ex.: responsivo), nunca como substituto da ordem lógica/semântica do HTML — leitores de tela seguem a ordem do documento, não a visual.

Exemplo

.card-grupo {
  display: flex;
}

.card-grupo__icone {
  flex-shrink: 0;
  width: 40px;
}

.card-grupo__texto {
  flex: 1; /* ocupa todo o espaço restante */
}

.card-grupo__destaque {
  order: -1; /* aparece primeiro, mesmo vindo depois no HTML */
  align-self: flex-start;
}

Boas práticas / erros comuns

Fazer

  • Usar a abreviada flex em vez das três propriedades separadas, para deixar a intenção mais clara e o código mais curto

Evitar

  • Usar order para reorganizar conteúdo de forma que a leitura por teclado/leitor de tela fique diferente da leitura visual — isso prejudica acessibilidade
  • Esquecer que flex-basis tem prioridade sobre width quando ambos são definidos no mesmo item
Grid Layout

Um modelo de layout bidimensional que organiza itens em linhas e colunas simultaneamente, com controle preciso sobre o tamanho de cada uma.

O que é

Grid transforma um elemento (display: grid) em um contêiner que divide o espaço em linhas e colunas explícitas, definidas pelo próprio desenvolvedor. Os filhos diretos são posicionados dentro dessa grade — seja automaticamente, seguindo a ordem, seja explicitamente, informando em qual linha/coluna cada item deve ficar. É a ferramenta certa quando o layout precisa alinhar elementos tanto na horizontal quanto na vertical ao mesmo tempo.

Sintaxe genérica

.container {
  display: grid;
  grid-template-columns: 1fr 2fr;
  grid-template-rows: auto 1fr;
  gap: 16px;
}

Valores principais

Propriedade Onde vai Para que serve
grid-template-columns Contêiner Define o número e o tamanho das colunas
grid-template-rows Contêiner Define o número e o tamanho das linhas
fr Valor Unidade de "fração" do espaço disponível na grade (ex.: 1fr 2fr = a segunda coluna tem o dobro da primeira)
gap Contêiner Espaçamento entre linhas e colunas da grade
grid-column / grid-row Item Posiciona ou expande um item por linhas/colunas específicas da grade
grid-template-areas Contêiner Nomeia regiões da grade visualmente no próprio CSS, e os itens se posicionam por nome

Quando usar

  • Use Grid para layouts de página inteira (cabeçalho, menu lateral, conteúdo, rodapé) ou galerias onde itens precisam se alinhar em linhas e colunas ao mesmo tempo.
  • Use a unidade fr para distribuir espaço proporcionalmente entre colunas/linhas, em vez de calcular porcentagens manualmente.
  • Use grid-template-areas quando o layout tem regiões nomeáveis (ex.: "cabecalho", "menu", "principal") — deixa a estrutura visualmente clara direto no CSS.
  • Combine Grid (estrutura geral da página) com Flexbox (alinhamento interno de cada região) — as duas técnicas se complementam.

Exemplo

.pagina {
  display: grid;
  grid-template-columns: 260px 1fr;
  grid-template-areas:
    "menu principal";
  min-height: 100vh;
}

.menu { grid-area: menu; }
.principal { grid-area: principal; }

.galeria {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(200px, 1fr));
  gap: 16px;
}

Boas práticas / erros comuns

Fazer

  • Usar repeat(auto-fit, minmax(...)) para grades responsivas que se ajustam sozinhas ao número de itens, sem media queries
  • Nomear áreas com grid-template-areas em layouts de página para tornar a estrutura autoexplicativa

Evitar

  • Usar Grid para alinhar um único grupo de itens em uma linha simples — Flexbox resolve isso com menos código
  • Misturar grid-template-columns em pixels fixos sem fr/minmax, perdendo a responsividade natural do Grid
Grid items Layout

As propriedades que vão nos filhos de um contêiner grid, posicionando cada item em linhas e colunas específicas da grade.

O que é

Assim como no Flexbox, o Grid separa propriedades de contêiner (que definem a grade como um todo) de propriedades de item (que posicionam cada filho dentro dela). Um item pode ocupar uma única célula, ou se estender por várias linhas/colunas usando span. O alinhamento dentro da própria célula também pode ser ajustado individualmente com justify-self/align-self.

Sintaxe genérica

.item {
  grid-column: 1 / 3;
  grid-row: 2;
  justify-self: center;
}

Valores principais

Propriedade Para que serve Exemplo
grid-column Define em qual(is) coluna(s) o item fica, por linha de grade ou por extensão grid-column: span 2; (ocupa 2 colunas)
grid-row Mesma lógica de grid-column, mas para linhas grid-row: 1 / 3;
grid-area Posiciona o item por nome, quando o contêiner usa grid-template-areas grid-area: cabecalho;
justify-self Alinha o item horizontalmente dentro da própria célula justify-self: end;
align-self Alinha o item verticalmente dentro da própria célula align-self: center;

Quando usar

  • Use grid-column: span N; em vez de calcular números de linha de grade manualmente, quando só interessa "quantas colunas esse item ocupa".
  • Use grid-area combinado com grid-template-areas no contêiner — deixa o posicionamento autoexplicativo, sem precisar contar linhas/colunas.
  • Use justify-self/align-self para ajustes pontuais de alinhamento dentro de uma célula, sem afetar os outros itens da grade.

Exemplo

.dashboard {
  display: grid;
  grid-template-columns: repeat(4, 1fr);
  gap: 16px;
}

.dashboard__destaque {
  grid-column: span 2; /* ocupa 2 das 4 colunas */
}

.dashboard__rodape {
  grid-column: 1 / -1; /* ocupa da primeira até a última coluna */
  justify-self: center;
}

Boas práticas / erros comuns

Fazer

  • Usar span em vez de números fixos de linha de grade sempre que o interesse for só "quantas células ocupar"
  • Usar 1 / -1 para um item ocupar a largura total da grade, independente do número de colunas definidas

Evitar

  • Confundir justify-self/align-self (alinhamento do item na própria célula) com justify-items/align-items (propriedades do contêiner, que afetam todos os itens de uma vez)
  • Sobrepor itens sem querer ao definir grid-column/grid-row manualmente sem revisar a grade completa — é fácil dois itens acabarem na mesma célula
--variavel Variáveis CSS

Valores nomeados e reutilizáveis, definidos uma vez e referenciados em qualquer lugar do CSS com var() — a base para temas, dark mode e manutenção centralizada.

O que é

Uma custom property (ou "variável CSS") é declarada com dois hífens no início do nome (ex.: --cor-primaria) e um valor qualquer — cor, tamanho, fonte, o que for. Diferente de variáveis de pré-processadores como Sass, custom properties existem de verdade no navegador: podem ser lidas e alteradas via JavaScript, e respeitam a cascata e a herança como qualquer outra propriedade CSS.

Sintaxe genérica

:root {
  --cor-primaria: #1a1a1a;
}

.elemento {
  color: var(--cor-primaria);
}

Valores principais

Sintaxe Para que serve Exemplo
--nome: valor; Declara a variável dentro de um seletor --espaco: 16px;
var(--nome) Lê o valor da variável em qualquer propriedade margin: var(--espaco);
var(--nome, fallback) Usa um valor alternativo caso a variável não exista/não esteja definida color: var(--cor-texto, black);
:root Seletor comum para declarar variáveis globais, acessíveis em toda a página :root { --gap: 24px; }

Quando usar

  • Declare variáveis globais (cores, espaçamentos, fontes) em :root, centralizando o design system do projeto em um só lugar.
  • Redeclare a mesma variável dentro de um seletor mais específico (ex.: uma classe de tema) para sobrescrever seu valor apenas naquele escopo — é assim que dark mode costuma ser implementado.
  • Use o segundo parâmetro de var() como fallback de segurança em componentes reutilizáveis que podem ser usados fora do contexto onde a variável foi definida.

Exemplo

:root {
  --cor-fundo: #ffffff;
  --cor-texto: #1a1a1a;
}

[data-tema="escuro"] {
  --cor-fundo: #1a1a1a;
  --cor-texto: #f1f0ec;
}

body {
  background: var(--cor-fundo);
  color: var(--cor-texto);
}

Boas práticas / erros comuns

Fazer

  • Nomear variáveis pelo papel que exercem (--cor-primaria), não pelo valor literal (--azul) — assim o nome continua fazendo sentido se o valor mudar
  • Aproveitar a cascata: redeclarar variáveis em seletores mais específicos para criar variações/temas sem duplicar todo o CSS

Evitar

  • Confundir custom properties com variáveis de Sass/Less — elas não são substituídas em tempo de compilação, existem de fato no navegador e podem mudar em tempo real
  • Esquecer que o nome é case-sensitive e precisa dos dois hífens (--nome, não -nome ou $nome)
@media Responsividade

A regra que aplica um bloco de CSS apenas quando certas condições sobre a tela ou o dispositivo são verdadeiras — a base do design responsivo.

O que é

@media é uma at-rule que envolve um bloco de CSS normal e só o aplica quando a condição especificada (chamada de media feature) é satisfeita — mais comumente a largura da tela. Fora dessa condição, o bloco inteiro é ignorado. É a ferramenta que permite que o mesmo HTML/CSS se comporte de forma diferente em celular, tablet e desktop.

Sintaxe genérica

@media (max-width: 768px) {
  .container {
    grid-template-columns: 1fr;
  }
}

Valores principais

Media feature Para que serve Exemplo
max-width Aplica o bloco quando a tela é igual ou menor que o valor — base do "mobile-first ao contrário" (desktop-first) @media (max-width: 600px) { ... }
min-width Aplica o bloco quando a tela é igual ou maior que o valor — base do mobile-first @media (min-width: 768px) { ... }
orientation Detecta orientação da tela @media (orientation: landscape) { ... }
prefers-color-scheme Detecta se o usuário prefere tema claro ou escuro no sistema operacional @media (prefers-color-scheme: dark) { ... }
and Combina múltiplas condições, que precisam ser todas verdadeiras @media (min-width: 600px) and (max-width: 900px)

Quando usar

  • Prefira a abordagem mobile-first: escreva o CSS base pensando em telas pequenas, e use min-width para adicionar/ajustar estilos conforme a tela cresce — geralmente resulta em menos código e menos sobreposição de regras.
  • Defina os breakpoints (valores de largura) com base no ponto onde o próprio layout começa a quebrar visualmente, não em tamanhos de dispositivos específicos (que mudam com o tempo).
  • Use prefers-color-scheme combinado com custom properties (ver Variáveis CSS) para implementar dark mode automático, respeitando a preferência do sistema do usuário.

Exemplo

.grid-cards {
  display: grid;
  grid-template-columns: 1fr; /* mobile: uma coluna */
  gap: 16px;
}

@media (min-width: 600px) {
  .grid-cards {
    grid-template-columns: repeat(2, 1fr); /* tablet: duas colunas */
  }
}

@media (min-width: 1000px) {
  .grid-cards {
    grid-template-columns: repeat(3, 1fr); /* desktop: três colunas */
  }
}

@media (prefers-color-scheme: dark) {
  :root {
    --cor-fundo: #1a1a1a;
    --cor-texto: #f1f0ec;
  }
}

Boas práticas / erros comuns

Fazer

  • Adotar mobile-first (min-width) como padrão do projeto, mantendo consistência na direção das media queries
  • Usar unidades relativas (em/rem) nos breakpoints em vez de px, para que respeitem o zoom/configuração de fonte do navegador

Evitar

  • Misturar min-width e max-width sem critério no mesmo projeto — dificulta prever qual regra vence em determinada largura
  • Criar breakpoints demais "para cada dispositivo" — na prática, poucos pontos de quebra (2 a 4) bem escolhidos cobrem a グrande maioria dos casos
