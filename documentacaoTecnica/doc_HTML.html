HTML — Referência de Elementos

Documentação de consulta rápida para uso dos elementos HTML em qualquer projeto — independente do sistema que você estiver construindo.

<html> Estrutura do documento

Elemento raiz que envolve todo o conteúdo de uma página HTML. Todo o resto do documento fica dentro dele.

O que é

É o elemento pai de todos os outros elementos da página — head e body ficam sempre dentro dele. Sem ele, o navegador não sabe onde o documento HTML começa e termina.

Sintaxe genérica

<!DOCTYPE html>
<html lang="pt-BR">
  ...
</html>

Atributos principais

Atributo Para que serve Exemplo
lang Declara o idioma principal do conteúdo. Usado por leitores de tela e navegadores (ex.: sugestão de tradução) lang="pt-BR"

Quando usar

  • Sempre presente, um único por página, logo após a declaração <!DOCTYPE html>.
  • Defina o lang corretamente — é um requisito básico de acessibilidade.

Exemplo

<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8" />
  <title>Minha Página</title>
</head>
<body>
  <h1>Olá, mundo</h1>
</body>
</html>

Boas práticas / erros comuns

Fazer

  • Sempre declarar o <!DOCTYPE html> antes do <html>
  • Usar o lang correspondente ao idioma real do conteúdo

Evitar

  • Esquecer o <!DOCTYPE html> — o navegador entra em "modo de compatibilidade" e o layout pode quebrar
  • Ter mais de um <html> no mesmo documento
<head> Estrutura do documento

Contém os metadados da página — informações que o navegador e os mecanismos de busca usam, mas que não aparecem diretamente na tela.

O que é

É a seção "de configuração" do documento: define a codificação de caracteres, o título exibido na aba do navegador, o comportamento em telas de celular (viewport) e os arquivos de CSS que a página vai usar. Nada dentro do head aparece visualmente na página.

Sintaxe genérica

<head>
  <meta charset="UTF-8" />
  <title>Título da página</title>
</head>

Atributos principais

O head em si não tem atributos de uso comum — o que importa é o que colocamos dentro dele. Os elementos mais usados são:

Elemento Para que serve Exemplo
<meta charset> Define a codificação de caracteres (evita bug de acentuação) <meta charset="UTF-8" />
<meta viewport> Controla a exibição em telas de celular <meta name="viewport" content="width=device-width, initial-scale=1.0" />
<title> Texto exibido na aba do navegador <title>Minha Loja</title>
<link> Conecta arquivos externos, como CSS ou ícone da aba <link rel="stylesheet" href="style.css" />

Quando usar

  • Um único head por página, sempre logo após a abertura do <html>.
  • Todo projeto deve ter, no mínimo, charset, viewport e title.

Exemplo

<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>AutoVision — Revenda de Carros</title>
  <link rel="stylesheet" href="estilo.css" />
</head>

Boas práticas / erros comuns

Fazer

  • Colocar o meta charset como primeira linha dentro do head
  • Escolher um title que descreva a página, não genérico ("Documento sem título")

Evitar

  • Colocar conteúdo visível (texto, imagens) dentro do head — ele não aparece e pode gerar comportamento inesperado
  • Esquecer o viewport — a página fica quebrada em celulares
<body> Estrutura do documento

Contém todo o conteúdo visível da página — textos, imagens, botões, formulários, tudo que o usuário efetivamente vê e interage.

O que é

É onde a interface da página é construída. Praticamente todos os outros elementos que você usa no dia a dia (h1, p, div, form, etc.) ficam dentro do body.

Sintaxe genérica

<body>
  ... todo o conteúdo visível da página ...
</body>

Atributos principais

O body aceita os atributos globais (como id e class), usados normalmente para estilizar a página inteira a partir do CSS.

Atributo Para que serve Exemplo
class Aplica um estilo CSS global à página (ex.: tema escuro) class="tema-escuro"

Quando usar

  • Um único body por página, logo depois do </head>.
  • Todo conteúdo que o usuário deve ver ou com o qual deve interagir vai aqui dentro — nunca no head.

Exemplo

<body>
  <header>
    <h1>AutoVision</h1>
  </header>

  <main>
    <p>Encontre o carro ideal para você.</p>
  </main>
</body>

Boas práticas / erros comuns

Fazer

  • Organizar o conteúdo com elementos semânticos (header, main, footer) quando fizer sentido

Evitar

  • Ter conteúdo de texto ou tags soltas fora do body (fora de head/body) — o navegador tenta corrigir sozinho, mas o resultado é imprevisível
<h1>–<h6> Estrutura & texto

Definem os títulos e subtítulos de uma página, organizando o conteúdo em uma hierarquia — do mais importante (h1) ao menos importante (h6).

O que é

Os elementos h1 a h6 representam níveis de título dentro do documento. Eles não servem apenas para deixar o texto grande — são usados por leitores de tela e mecanismos de busca para entender a estrutura da página, então a hierarquia precisa fazer sentido.

Sintaxe genérica

<h1>Título principal da página</h1>
<h2>Título de uma seção</h2>
<h3>Título de uma subseção</h3>

Atributos principais

Atributo Para que serve Exemplo
id Cria um ponto de âncora para navegação interna (ex.: menu que rola até a seção) id="sobre"
class Aplica estilos CSS reutilizáveis ao título class="titulo-destaque"

Quando usar

  • Use apenas um h1 por página — ele representa o assunto principal daquela tela.
  • Não pule níveis (de h2 direto para h4) só para deixar o texto menor — isso quebra a hierarquia. Para diminuir o tamanho da fonte, use CSS.
  • Use h2 para os títulos das grandes seções da página, e h3/h4 para as subdivisões dentro delas.

Exemplo

<h1>Painel de Vendas</h1>

<h2>Resumo do mês</h2>
<h3>Produtos mais vendidos</h3>

<h2>Histórico de pedidos</h2>

Boas práticas / erros comuns

Fazer

  • Escolher o nível pelo lugar na hierarquia, não pelo tamanho visual desejado
  • Manter a ordem lógica (h1 → h2 → h3...)

Evitar

  • Usar h1, h2... só porque "fica maior"
  • Ter mais de um h1 na mesma página
<p> Estrutura & texto

Define um parágrafo de texto — o elemento mais comum para blocos de texto corrido em uma página.

O que é

Representa um bloco de texto independente. Navegadores adicionam automaticamente um espaçamento vertical antes e depois de cada p, o que o diferencia de um texto solto sem tag.

Sintaxe genérica

<p>Texto do parágrafo aqui.</p>

Atributos principais

Atributo Para que serve Exemplo
id Identifica o parágrafo de forma única, para navegação ou manipulação via JS id="descricao-produto"
class Aplica um estilo CSS reutilizável class="texto-secundario"

Quando usar

  • Use para blocos de texto corridos (descrições, parágrafos de conteúdo).
  • Não use p para textos curtos que não são parágrafos de fato, como o rótulo de um campo de formulário — nesses casos use label ou span.
  • Não coloque outro elemento de bloco (como uma div ou outro p) dentro de um p — o HTML não permite e o navegador corrige de forma imprevisível.

Exemplo

<h2>Sobre o carro</h2>
<p>
  Este veículo está com revisão em dia e pneus novos,
  pronto para rodar.
</p>

Boas práticas / erros comuns

Fazer

  • Usar um p por ideia/parágrafo, em vez de um só p gigante com <br> no meio

Evitar

  • Usar <br><br> para simular espaçamento entre parágrafos em vez de abrir um novo p
  • Usar p só para "empurrar" o layout com espaço em branco
<ul>/<ol>/<li> Estrutura & texto

Criam listas de itens: ul para listas sem ordem definida, ol para listas em que a ordem importa, e li para cada item dentro delas.

O que é

ul ("unordered list") e ol ("ordered list") são os elementos que envolvem a lista. li ("list item") representa cada item e só faz sentido como filho direto de um ul ou ol.

Sintaxe genérica

<ul>
  <li>Item</li>
  <li>Item</li>
</ul>

<ol>
  <li>Primeiro passo</li>
  <li>Segundo passo</li>
</ol>

Atributos principais

Atributo Para que serve Exemplo
start (em ol) Define em qual número a contagem começa start="5"
reversed (em ol) Inverte a ordem da numeração (decrescente) reversed
type (em ol) Define o estilo da numeração: números, letras ou romanos type="A"

Quando usar

  • Use ul quando a ordem dos itens não muda o significado da lista (ex.: lista de recursos, ingredientes).
  • Use ol quando a ordem importa (ex.: passo a passo, ranking, instruções sequenciais).
  • li deve ficar sempre diretamente dentro de ul ou ol — nunca solto ou dentro de outra tag.

Exemplo

<h3>Documentos necessários</h3>
<ul>
  <li>RG</li>
  <li>CPF</li>
  <li>Comprovante de residência</li>
</ul>

<h3>Como finalizar a compra</h3>
<ol>
  <li>Escolha o veículo</li>
  <li>Registre interesse</li>
  <li>Aguarde contato do vendedor</li>
</ol>

Boas práticas / erros comuns

Fazer

  • Escolher entre ul e ol pelo significado da lista, não pela aparência
  • Usar CSS para remover as marcações visuais (bolinhas/números) quando necessário, mantendo a tag semanticamente correta

Evitar

  • Simular listas com <p>- item</p> ou <div> soltas
  • Colocar texto direto dentro de ul/ol sem envolver em li
<a> Estrutura & texto

Cria um link (hyperlink), levando o usuário a outra página, outra parte da mesma página, um e-mail, ou qualquer outro recurso.

O que é

O elemento a ("anchor") transforma um texto, imagem ou outro elemento em algo clicável que navega para um destino definido pelo atributo href.

Sintaxe genérica

<a href="destino">Texto do link</a>

Atributos principais

Atributo Para que serve Exemplo
href Define o destino do link (obrigatório para o link funcionar) href="/sobre.html"
target Define onde o destino será aberto target="_blank" (nova aba)
rel Define a relação com o destino; use noopener noreferrer junto de target="_blank" por segurança rel="noopener noreferrer"

Quando usar

  • Para navegação entre páginas, âncoras internas (href="#secao"), e-mail (href="mailto:...") ou telefone (href="tel:...").
  • Se a ação não leva a lugar nenhum e só dispara uma função (ex.: abrir um modal), use um <button> em vez de <a href="#">.

Exemplo

<a href="https://exemplo.com">Visitar site</a>
<a href="#contato">Ir para contato</a>
<a href="mailto:contato@exemplo.com">Enviar e-mail</a>

Boas práticas / erros comuns

Fazer

  • Usar um texto de link que descreva o destino ("Ver relatório completo")
  • Adicionar rel="noopener noreferrer" em links com target="_blank"

Evitar

  • Usar <a href="#"> como substituto de botão para ações via JavaScript
  • Textos genéricos como "clique aqui"

Nota: para ações que não navegam (abrir modal, enviar formulário, alternar um menu), o elemento correto é <button>, não <a>.

<div> Contêineres genéricos

Contêiner genérico de bloco, sem significado semântico próprio — usado para agrupar elementos e aplicar estilo ou comportamento via CSS/JS.

O que é

O div ("division") não comunica nada sobre o conteúdo que envolve — ao contrário de header, section ou article, que têm significado. Ele existe puramente para fins estruturais: agrupar elementos que devem ser estilizados ou manipulados juntos.

Sintaxe genérica

<div class="cartao">
  ... conteúdo agrupado ...
</div>

Atributos principais

Atributo Para que serve Exemplo
class Aplica um estilo CSS reutilizável ao bloco class="cartao-produto"
id Identifica o bloco de forma única, para navegação ou manipulação via JS id="modal-login"

Quando usar

  • Use quando precisar agrupar elementos apenas para fins de layout/estilo, e nenhum elemento semântico (section, article, aside etc.) descreve o papel daquele bloco.
  • Antes de usar div, pergunte-se: "esse bloco representa um cabeçalho, uma navegação, uma seção de conteúdo?" — se sim, prefira o elemento semântico correspondente.

Exemplo

<div class="grade-produtos">
  <div class="cartao-produto">
    <h3>Sedan XT</h3>
    <p>R$ 89.000</p>
  </div>
</div>

Boas práticas / erros comuns

Fazer

  • Usar nomes de classe descritivos para o que o bloco representa (cartao-produto, não bloco1)

Evitar

  • "Divitis": encher a página de div aninhadas quando um elemento semântico resolveria melhor
  • Usar div como botão ou link clicável em vez de button/a
<span> Contêineres genéricos

Contêiner genérico em linha (inline), sem significado semântico — o equivalente ao div, mas para trechos de texto dentro de um bloco maior.

O que é

Diferente do div, que quebra linha (elemento de bloco), o span não interrompe o fluxo do texto — ele serve para marcar um trecho específico dentro de um parágrafo, título ou outro elemento, geralmente para aplicar um estilo ou comportamento pontual.

Sintaxe genérica

<p>Texto normal e <span class="destaque">um trecho destacado</span> continuando.</p>

Atributos principais

Atributo Para que serve Exemplo
class Aplica um estilo CSS a um trecho específico de texto class="preco"
id Identifica o trecho de forma única, geralmente para manipulação via JS id="contador"

Quando usar

  • Use para estilizar ou selecionar via JS uma parte de um texto, sem afetar o fluxo do restante.
  • Se o trecho tem significado próprio (ênfase, texto de menor importância), prefira um elemento de texto semântico como strong, em ou small em vez de span.

Exemplo

<p>
  Valor: <span class="preco">R$ 45.900</span>
  <span class="badge-novo">Novo</span>
</p>

Boas práticas / erros comuns

Fazer

  • Usar span apenas quando nenhum elemento inline semântico se aplica

Evitar

  • Usar span para textos que deveriam ser um bloco (p, div) — isso quebra o fluxo visual esperado
<header> Estrutura semântica

Representa o cabeçalho de uma página ou de uma seção — geralmente contém logotipo, título e navegação introdutória.

O que é

É um elemento semântico: comunica ao navegador, leitores de tela e mecanismos de busca que aquele bloco é o cabeçalho do conteúdo que o envolve. Pode existir mais de um header na mesma página — um para o site inteiro e outros dentro de article/section.

Sintaxe genérica

<header>
  <h1>Nome do site</h1>
  <nav>...</nav>
</header>

Atributos principais

O header não tem atributos próprios de destaque — aceita apenas os atributos globais (id, class), usados para estilização.

Quando usar

  • Use um header no topo da página para o cabeçalho geral do site (logo, título, navegação principal).
  • Use também dentro de um article ou section quando aquele bloco específico precisar de seu próprio cabeçalho (ex.: título e data de um post).
  • Não confunda com o elemento <head> — são coisas completamente diferentes: head guarda metadados invisíveis, header é conteúdo visível dentro do body.

Exemplo

<header>
  <h1>AutoVision</h1>
  <nav>
    <a href="#estoque">Estoque</a>
    <a href="#contato">Contato</a>
  </nav>
</header>

Boas práticas / erros comuns

Fazer

  • Colocar o header como o primeiro elemento visível dentro do body (ou do article/section a que pertence)

Evitar

  • Confundir header (visível) com head (metadados)
  • Colocar um header dentro de outro header ou de um footer
<nav> Estrutura semântica

Agrupa os principais links de navegação de uma página — menu principal, menu de rodapé, sumário, paginação.

O que é

Marca um bloco de links como sendo de navegação, o que ajuda leitores de tela a pular diretamente para o menu (ou a ignorá-lo, se o usuário já conhece a página). Nem todo grupo de links precisa de um nav — apenas os blocos de navegação principais.

Sintaxe genérica

<nav>
  <a href="#secao-1">Seção 1</a>
  <a href="#secao-2">Seção 2</a>
</nav>

Atributos principais

Atributo Para que serve Exemplo
aria-label Descreve o propósito do menu quando há mais de um nav na página aria-label="Navegação principal"

Quando usar

  • Use para o menu principal do site, menu de rodapé, breadcrumbs (trilha de navegação) ou paginação.
  • Não use para todo e qualquer grupo de links da página — links soltos dentro do texto de um article, por exemplo, não precisam de nav.

Exemplo

<nav aria-label="Navegação principal">
  <a href="#estoque">Estoque</a>
  <a href="#financiamento">Financiamento</a>
  <a href="#contato">Contato</a>
</nav>

Boas práticas / erros comuns

Fazer

  • Usar aria-label quando a página tiver mais de um nav, para diferenciá-los

Evitar

  • Envolver todo grupo de links da página em nav, mesmo os que não são de navegação estrutural
<main> Estrutura semântica

Envolve o conteúdo principal e único da página — aquilo que não se repete em outras páginas do site, como cabeçalho e rodapé.

O que é

Indica, tanto para o navegador quanto para tecnologias assistivas, onde começa o conteúdo central da página. Leitores de tela costumam oferecer um atalho para "pular direto para o conteúdo principal", que depende da existência de um main.

Sintaxe genérica

<main>
  ... conteúdo central e único da página ...
</main>

Atributos principais

Aceita apenas os atributos globais (id, class) — não possui atributos próprios.

Quando usar

  • Use apenas um main por página, envolvendo o conteúdo que muda de página para página.
  • Nunca coloque header, nav ou footer globais do site dentro do main — eles ficam fora, pois se repetem em todas as páginas.

Exemplo

<body>
  <header>...</header>

  <main>
    <h1>Carros disponíveis</h1>
    <p>Confira nosso estoque atualizado.</p>
  </main>

  <footer>...</footer>
</body>

Boas práticas / erros comuns

Fazer

  • Garantir que só existe um main visível por vez na página

Evitar

  • Usar mais de um main na mesma página
  • Colocar o main dentro de article, aside, header ou footer
<section> Estrutura semântica

Agrupa um bloco temático de conteúdo, geralmente com seu próprio título — usado para dividir a página em partes com assunto próprio.

O que é

Representa uma seção genérica de conteúdo relacionado por tema. A regra prática mais usada: se o bloco tem (ou poderia ter) um título (h2, h3...) que resume seu conteúdo, provavelmente é uma section.

Sintaxe genérica

<section>
  <h2>Título da seção</h2>
  ... conteúdo relacionado a esse título ...
</section>

Atributos principais

Aceita apenas os atributos globais (id, class) — o id é útil aqui para criar âncoras de navegação (href="#secao").

Quando usar

  • Use para dividir a página em blocos temáticos: "Sobre nós", "Depoimentos", "Estoque em destaque".
  • Se o bloco não tem um tema/título próprio e existe só para fins de estilo/layout, use div em vez de section.

Exemplo

<section id="depoimentos">
  <h2>O que nossos clientes dizem</h2>
  <p>"Atendimento excelente, recomendo!"</p>
</section>

Boas práticas / erros comuns

Fazer

  • Dar a cada section um título (h2–h6) que resuma seu conteúdo

Evitar

  • Usar section apenas como substituto estilístico de div, sem um tema real
<article> Estrutura semântica

Representa um conteúdo autônomo e completo em si mesmo — que faria sentido mesmo se distribuído isoladamente, fora do contexto da página.

O que é

A diferença central em relação ao section: um article precisa fazer sentido sozinho — um post de blog, uma notícia, um card de produto, um comentário. Um article pode conter sections dentro dele, e vice-versa.

Sintaxe genérica

<article>
  <h2>Título do conteúdo</h2>
  <p>Conteúdo completo e independente.</p>
</article>

Atributos principais

Aceita apenas os atributos globais (id, class).

Quando usar

  • Use para posts de blog, notícias, cards de produto individuais, comentários de usuários — qualquer bloco que "se bastasse sozinho" se fosse copiado para outro lugar.
  • Pergunta prática: "isso faria sentido em um feed de RSS, isolado do resto da página?" Se sim, é um article.

Exemplo

<article>
  <h2>Sedan XT 2022</h2>
  <p>Único dono, revisões em dia, 42.000 km rodados.</p>
  <p>R$ 89.000</p>
</article>

Boas práticas / erros comuns

Fazer

  • Repetir um article para cada item de uma listagem (ex.: cada card de carro no estoque)

Evitar

  • Usar article para blocos que só fazem sentido dentro do contexto da página (ex.: o menu de navegação)
<aside> Estrutura semântica

Representa conteúdo relacionado, mas separado do fluxo principal — barras laterais, caixas de destaque, anúncios, links relacionados.

O que é

Marca um trecho como complementar: algo que enriquece o conteúdo principal, mas que poderia ser removido sem comprometer o entendimento do restante da página.

Sintaxe genérica

<aside>
  <h3>Você também pode gostar</h3>
  ...
</aside>

Atributos principais

Aceita apenas os atributos globais (id, class).

Quando usar

  • Use para barras laterais, boxes de "artigos relacionados", biografia do autor ao lado de um post, anúncios.
  • Pode ser usado tanto como barra lateral da página inteira quanto dentro de um article específico (ex.: uma nota lateral dentro de um post).

Exemplo

<aside>
  <h3>Carros semelhantes</h3>
  <ul>
    <li>Sedan XT 2021</li>
    <li>Sedan GT 2022</li>
  </ul>
</aside>

Boas práticas / erros comuns

Fazer

  • Usar para conteúdo que complementa, mas não é indispensável ao entendimento da página

Evitar

  • Usar aside para conteúdo essencial que deveria estar no fluxo principal
<footer> Estrutura semântica

Representa o rodapé de uma página ou de uma seção — geralmente contém informações de contato, direitos autorais, links secundários.

O que é

Assim como o header, o footer pode existir mais de uma vez na página: um para o rodapé geral do site, e outros dentro de articles específicos (ex.: data e autor ao final de um post).

Sintaxe genérica

<footer>
  <p>© 2026 Minha Empresa</p>
</footer>

Atributos principais

Aceita apenas os atributos globais (id, class).

Quando usar

  • Use no final da página para direitos autorais, links de contato, redes sociais, mapa do site.
  • Use dentro de um article para metadados do próprio conteúdo (autor, data de publicação, tags).

Exemplo

<footer>
  <p>© 2026 AutoVision. Todos os direitos reservados.</p>
  <nav aria-label="Links do rodapé">
    <a href="#privacidade">Política de Privacidade</a>
  </nav>
</footer>

Boas práticas / erros comuns

Fazer

  • Colocar o footer como último elemento visível da página (ou do article/section a que pertence)

Evitar

  • Colocar um footer dentro de outro footer ou de um header
<strong> Texto em linha

Dá ênfase forte a um trecho de texto — indica que aquele conteúdo tem importância séria, não apenas destaque visual.

O que é

Semanticamente, strong comunica que o trecho é importante (um aviso, uma palavra-chave crítica). Por padrão os navegadores o exibem em negrito, mas o significado é o que importa — leitores de tela costumam mudar o tom de voz ao ler um strong.

Sintaxe genérica

<p>Atenção: <strong>o prazo termina hoje</strong>.</p>

Atributos principais

Aceita apenas os atributos globais (id, class) — não possui atributos próprios.

Quando usar

  • Use quando o trecho realmente tiver importância de conteúdo (avisos, erros, palavras-chave essenciais).
  • Se você só quer texto em negrito por estilo visual, sem significado adicional, use CSS (font-weight: bold) em vez de strong.

Exemplo

<p>
  <strong>Importante:</strong> revise o contrato antes de assinar.
</p>

Boas práticas / erros comuns

Fazer

  • Reservar o strong para conteúdo genuinamente importante

Evitar

  • Usar strong só para deixar o texto visualmente mais grosso, sem relevância de conteúdo
<em> Texto em linha

Dá ênfase (tônica) a um trecho de texto — como se o leitor mudasse a entonação da voz naquela palavra ou frase.

O que é

Diferente do strong (importância), o em ("emphasis") marca ênfase de entonação — o tipo de destaque que mudaria o significado da frase se lida em voz alta. Por padrão os navegadores o exibem em itálico.

Sintaxe genérica

<p>Eu <em>realmente</em> preciso terminar isso hoje.</p>

Atributos principais

Aceita apenas os atributos globais (id, class).

Quando usar

  • Use para dar ênfase de entonação a uma palavra ou trecho dentro de uma frase.
  • Se o objetivo é apenas itálico por estilo (ex.: título de uma obra, termo estrangeiro), sem ênfase de fala, considere <i> ou CSS em vez de em.

Exemplo

<p>Este <em>é</em> o carro que você estava procurando.</p>

Boas práticas / erros comuns

Fazer

  • Usar em onde a ênfase mudaria a leitura em voz alta da frase

Evitar

  • Aninhar múltiplos em só para intensificar visualmente ("mais itálico") — isso não tem efeito semântico extra
<small> Texto em linha

Marca texto de "letras miúdas" — avisos legais, ressalvas, créditos, termos e condições, geralmente exibido em fonte menor.

O que é

Representa comentários secundários ao conteúdo principal — o tipo de texto que, em um documento impresso, apareceria em letra pequena no rodapé de um anúncio ou contrato.

Sintaxe genérica

<p>R$ 899/mês <small>sujeito a análise de crédito</small></p>

Atributos principais

Aceita apenas os atributos globais (id, class).

Quando usar

  • Use para ressalvas legais, direitos autorais, condições de uma oferta, créditos de imagem.
  • Não use apenas para deixar um texto visualmente menor sem esse significado de "letra miúda" — nesse caso use CSS.

Exemplo

<p>
  A partir de R$ 1.200/mês.
  <small>Valores sujeitos a alteração sem aviso prévio.</small>
</p>

Boas práticas / erros comuns

Fazer

  • Reservar o small para ressalvas, avisos legais e créditos

Evitar

  • Usar small apenas para reduzir o tamanho da fonte de qualquer texto, sem relação com "letra miúda"
<br> Texto em linha

Insere uma quebra de linha dentro de um bloco de texto — sem abrir um novo parágrafo.

O que é

É um elemento vazio (não tem conteúdo nem tag de fechamento) que força o texto a continuar na linha seguinte. Deve ser usado apenas quando a quebra de linha faz parte do próprio conteúdo — não para criar espaçamento visual.

Sintaxe genérica

<p>Linha 1<br />Linha 2</p>

Atributos principais

O br não possui atributos de uso comum além dos globais.

Quando usar

  • Use quando a quebra de linha for parte do significado do conteúdo — um endereço, os versos de um poema, o texto de uma placa.
  • Não use <br><br> para simular espaçamento entre parágrafos — abra um novo p e controle o espaçamento via CSS.

Exemplo

<p>
  Rua das Flores, 123<br />
  Bairro Centro<br />
  Palhoça — SC
</p>

Boas práticas / erros comuns

Fazer

  • Usar br apenas quando a quebra faz parte do conteúdo (endereços, versos)

Evitar

  • Empilhar vários br para "empurrar" o layout com espaço em branco
<hr> Texto em linha

Insere uma quebra temática — uma mudança de assunto dentro do conteúdo, geralmente exibida como uma linha horizontal.

O que é

Assim como o br, é um elemento vazio. Mas seu significado é diferente: hr ("horizontal rule") indica uma transição temática — como a separação entre capítulos de um livro, ou entre cenas de uma história.

Sintaxe genérica

<p>Fim do capítulo 1.</p>
<hr />
<p>Início do capítulo 2.</p>

Atributos principais

O hr não possui atributos de uso comum além dos globais.

Quando usar

  • Use para marcar uma mudança de assunto ou de cena dentro de um mesmo bloco de conteúdo.
  • Se você só quer uma linha visual separando seções de layout, sem significar mudança de assunto, prefira border via CSS.

Exemplo

<article>
  <p>Primeira parte da notícia...</p>
  <hr />
  <p>Atualização: novas informações chegaram...</p>
</article>

Boas práticas / erros comuns

Fazer

  • Usar hr para indicar mudança de assunto dentro de um mesmo conteúdo

Evitar

  • Usar hr apenas como recurso decorativo de separação visual entre seções não relacionadas por tema
<img> Imagens & mídia

Insere uma imagem na página — fotos, ilustrações, ícones, banners.

O que é

É um elemento vazio (sem conteúdo nem tag de fechamento) que embute uma imagem externa através do atributo src. O texto alternativo (alt) é o que descreve a imagem para quem não pode vê-la — leitores de tela, buscadores, ou quando a imagem falha ao carregar.

Sintaxe genérica

<img src="caminho/imagem.jpg" alt="Descrição da imagem" />

Atributos principais

AtributoPara que serveExemplo
srcCaminho do arquivo de imagem (obrigatório)src="carros/sedan-xt.jpg"
altTexto alternativo que descreve a imagem (obrigatório por acessibilidade)alt="Sedan XT prata visto de frente"
width / heightDimensões da imagem — ajudam o navegador a reservar espaço antes de carregar, evitando "pulos" de layoutwidth="600" height="400"
loadingControla o carregamento adiado (lazy) de imagens fora da tela inicialloading="lazy"

Quando usar

  • Sempre forneça um alt descritivo — se a imagem for puramente decorativa (sem informação), use alt="" (vazio, mas presente).
  • Declare width e height sempre que souber as dimensões, para evitar que o layout "pule" enquanto a imagem carrega.

Exemplo

<img
  src="carros/sedan-xt.jpg"
  alt="Sedan XT prata, visto de frente, estacionado na loja"
  width="600"
  height="400"
  loading="lazy"
/>

Boas práticas / erros comuns

Fazer

  • Escrever um alt que descreva o conteúdo/função da imagem, não o nome do arquivo
  • Usar loading="lazy" em imagens que ficam fora da primeira tela visível

Evitar

  • Deixar o alt vazio em imagens que carregam informação (isso torna a imagem invisível para leitores de tela)
  • Repetir no alt o texto que já aparece do lado da imagem — gera repetição desnecessária
<figure>/<figcaption> Imagens & mídia

Agrupa uma imagem (ou outro conteúdo autocontido, como um gráfico) junto de sua legenda — mantendo os dois associados semanticamente.

O que é

figure envolve o conteúdo ilustrativo e sua legenda; figcaption é a própria legenda, e pode vir antes ou depois da imagem dentro do figure. O conjunto pode ser referenciado no texto principal, mas continua fazendo sentido mesmo se movido para outro lugar da página (como uma figura de artigo).

Sintaxe genérica

<figure>
  <img src="imagem.jpg" alt="Descrição" />
  <figcaption>Legenda da imagem</figcaption>
</figure>

Atributos principais

Nenhum dos dois elementos possui atributos próprios além dos globais (id, class).

Quando usar

  • Use sempre que uma imagem precisar de uma legenda visível associada a ela.
  • Se a imagem não tem legenda, um img sozinho (sem figure) já é suficiente.

Exemplo

<figure>
  <img src="carros/sedan-xt.jpg" alt="Sedan XT prata visto de frente" />
  <figcaption>Sedan XT 2022, único dono, 42.000 km</figcaption>
</figure>

Boas práticas / erros comuns

Fazer

  • Usar figcaption para o texto de legenda visível, mantendo o alt da imagem como descrição para acessibilidade — os dois têm papéis diferentes

Evitar

  • Usar figure sem nenhuma legenda — nesse caso, um img ou div simples já resolve
<audio> Imagens & mídia

Incorpora um player de áudio na página — músicas, podcasts, efeitos sonoros, narrações.

O que é

Cria um player nativo do navegador para reproduzir arquivos de áudio, sem precisar de plugins externos. O conteúdo entre a tag de abertura e fechamento (geralmente uma ou mais tags source) só é exibido caso o navegador não suporte o elemento — serve como mensagem de fallback.

Sintaxe genérica

<audio controls>
  <source src="audio.mp3" type="audio/mpeg" />
  Seu navegador não suporta áudio.
</audio>

Atributos principais

AtributoPara que serveExemplo
srcCaminho do arquivo (alternativa a usar source interno, quando há apenas um formato)src="podcast-ep1.mp3"
controlsExibe os controles padrão do navegador (play, pausa, volume)controls
autoplayInicia a reprodução automaticamente ao carregar a páginaautoplay
loopRepete o áudio ao terminarloop
mutedInicia sem sommuted

Quando usar

  • Sempre inclua controls, para que o usuário tenha como pausar, ajustar volume e controlar a reprodução.
  • Use múltiplas tags source com formatos diferentes (ex.: .mp3 e .ogg) quando precisar de compatibilidade ampla entre navegadores.
  • Evite autoplay — a maioria dos navegadores bloqueia áudio automático com som, e é uma experiência ruim para o usuário.

Exemplo

<audio controls>
  <source src="depoimento-cliente.mp3" type="audio/mpeg" />
  <source src="depoimento-cliente.ogg" type="audio/ogg" />
  Seu navegador não suporta reprodução de áudio.
</audio>

Boas práticas / erros comuns

Fazer

  • Sempre exibir controls, dando autonomia ao usuário sobre a reprodução
  • Fornecer um texto de fallback para navegadores muito antigos

Evitar

  • Usar autoplay com som — costuma ser bloqueado pelo navegador e incomoda o usuário
<video> Imagens & mídia

Incorpora um player de vídeo nativo na página — demonstrações de produto, tutoriais, vídeos institucionais.

O que é

Funciona de forma parecida com o audio, mas para conteúdo de vídeo. Também aceita tags source internas para oferecer múltiplos formatos, e um atributo poster para definir a imagem exibida antes do vídeo começar a tocar.

Sintaxe genérica

<video controls width="640">
  <source src="video.mp4" type="video/mp4" />
  Seu navegador não suporta vídeo.
</video>

Atributos principais

AtributoPara que serveExemplo
srcCaminho do arquivo (alternativa a source interno)src="tour-veiculo.mp4"
controlsExibe os controles padrão (play, pausa, volume, tela cheia)controls
posterImagem exibida antes do vídeo começar a tocarposter="capa-video.jpg"
width / heightDimensões do player, evitando "pulos" de layoutwidth="640" height="360"
mutedInicia sem som — geralmente combinado com autoplaymuted
autoplayInicia a reprodução automaticamente (navegadores só permitem sem som, em geral com muted)autoplay muted
loopRepete o vídeo ao terminarloop

Quando usar

  • Sempre inclua controls, a menos que o vídeo seja puramente decorativo (ex.: fundo animado em loop, sem som).
  • Defina um poster para evitar que a tela fique preta antes do carregamento.
  • Só use autoplay combinado com muted — a maioria dos navegadores bloqueia autoplay com som.

Exemplo

<video controls width="640" height="360" poster="capa-tour.jpg">
  <source src="tour-sedan-xt.mp4" type="video/mp4" />
  <source src="tour-sedan-xt.webm" type="video/webm" />
  Seu navegador não suporta vídeo. Assista <a href="tour-sedan-xt.mp4">aqui</a>.
</video>

Boas práticas / erros comuns

Fazer

  • Definir width/height ou poster para evitar saltos de layout durante o carregamento
  • Combinar autoplay sempre com muted

Evitar

  • Usar autoplay com som — a reprodução é bloqueada pela maioria dos navegadores
  • Esquecer o texto/link de fallback para quando o formato não é suportado
<iframe> Imagens & mídia

Embute outra página HTML dentro da página atual — usado para incorporar mapas, vídeos do YouTube, formulários externos e outros conteúdos de terceiros.

O que é

Cria uma "janela" dentro da página que carrega, de forma independente, o conteúdo de outra URL. É a forma padrão de incorporar conteúdo de serviços externos (Google Maps, YouTube, players de terceiros) sem sair da página atual.

Sintaxe genérica

<iframe src="https://exemplo.com/embed" title="Descrição do conteúdo"></iframe>

Atributos principais

AtributoPara que serveExemplo
srcURL do conteúdo a ser embutido (obrigatório)src="https://www.youtube.com/embed/ID"
titleDescreve o conteúdo do iframe para leitores de tela (obrigatório por acessibilidade)title="Vídeo institucional AutoVision"
width / heightDimensões do iframewidth="560" height="315"
allowfullscreenPermite que o conteúdo embutido entre em modo tela cheiaallowfullscreen
loadingControla carregamento adiado (lazy) do iframeloading="lazy"

Quando usar

  • Use para incorporar mapas, vídeos de plataformas externas (YouTube, Vimeo) ou qualquer widget de terceiros que forneça um código de "embed".
  • Sempre inclua um title descritivo — sem ele, leitores de tela anunciam apenas "iframe sem título", o que não ajuda o usuário.
  • Evite usar iframe para incorporar suas próprias páginas internas — nesse caso normalmente é melhor reestruturar o conteúdo diretamente na página.

Exemplo

<iframe
  src="https://www.google.com/maps/embed?..."
  title="Localização da loja AutoVision no mapa"
  width="600"
  height="400"
  loading="lazy"
></iframe>

Boas práticas / erros comuns

Fazer

  • Sempre definir um title descritivo
  • Usar loading="lazy" em iframes fora da primeira tela visível

Evitar

  • Embutir conteúdo de fontes não confiáveis — o iframe carrega código de outro domínio, o que tem implicações de segurança
  • Deixar o iframe sem title

Nota: por segurança, evite embutir sites de terceiros não confiáveis via iframe — o conteúdo carregado roda em um contexto separado, mas ainda pode expor o usuário a riscos dependendo da origem.

<form> Formulários

Agrupa os campos que o usuário preenche e define o que acontece quando esses dados são enviados.

O que é

É o elemento que envolve todos os campos relacionados a um envio de dados (input, select, textarea, button). Ele controla para onde os dados vão (action) e como são enviados (method) quando o formulário é submetido.

Sintaxe genérica

<form action="/enviar" method="post">
  ... campos do formulário ...
</form>

Atributos principais

AtributoPara que serveExemplo
actionURL para onde os dados são enviados ao submeteraction="/cadastro"
methodComo os dados são enviados: get (na URL, para buscas/filtros) ou post (no corpo da requisição, para criar/alterar dados)method="post"
novalidateDesativa a validação automática do navegador (útil quando a validação é feita por JS)novalidate

Quando usar

  • Sempre que precisar coletar dados do usuário (cadastro, login, contato, filtros de busca).
  • Use method="get" para buscas/filtros que não alteram dados no servidor (o resultado pode ser compartilhado por URL); use method="post" para envio de dados sensíveis ou que criam/alteram algo.
  • Não aninhe um form dentro de outro form — o HTML não permite.

Exemplo

<form action="/contato" method="post">
  <label for="nome">Nome</label>
  <input type="text" id="nome" name="nome" />

  <button type="submit">Enviar</button>
</form>

Boas práticas / erros comuns

Fazer

  • Escolher get/post pelo que a ação faz, não por hábito
  • Garantir que todo campo dentro do formulário tenha um name, para que o valor seja enviado

Evitar

  • Enviar dados sensíveis (senha, dados pessoais) usando method="get" — eles ficam visíveis na URL
  • Aninhar um form dentro de outro
<label> Formulários

Associa um texto descritivo a um campo de formulário — essencial para acessibilidade e usabilidade.

O que é

Conecta um texto ao campo que ele descreve, através do atributo for (que deve corresponder ao id do campo). Isso permite que clicar no texto do rótulo foque/ative o campo, e que leitores de tela anunciem corretamente o que cada campo representa.

Sintaxe genérica

<label for="email">E-mail</label>
<input type="email" id="email" name="email" />

Atributos principais

AtributoPara que serveExemplo
forAponta para o id do campo que este rótulo descrevefor="email"

Quando usar

  • Use um label para todo campo de formulário — mesmo quando o campo tem um placeholder, o placeholder não substitui o rótulo (ele some ao digitar e não é lido de forma confiável por leitores de tela).
  • Alternativa: envolver o próprio campo dentro do label, o que dispensa o atributo for/id combinado, mas é menos flexível para estilização.

Exemplo

<label for="telefone">Telefone</label>
<input type="tel" id="telefone" name="telefone" placeholder="(00) 00000-0000" />

Boas práticas / erros comuns

Fazer

  • Garantir que o valor de for seja idêntico ao id do campo correspondente

Evitar

  • Usar apenas placeholder no lugar de um label de verdade
  • Reutilizar o mesmo id em mais de um campo na página (quebra a associação do for)
<input> Formulários

Campo de entrada de dados — o elemento mais versátil de formulário, cujo comportamento muda de acordo com o atributo type.

O que é

É um elemento vazio (sem tag de fechamento) que representa um campo editável pelo usuário. O atributo type é o que define se ele vira uma caixa de texto, um campo de e-mail, um checkbox, um seletor de data, e assim por diante — cada tipo já vem com validação e teclado apropriados no celular.

Sintaxe genérica

<input type="text" id="campo" name="campo" />

Atributos principais

AtributoPara que serveExemplo
typeDefine o tipo de campotype="email"
nameNome usado para identificar o valor enviado ao servidor (obrigatório para o dado ser enviado)name="email"
idIdentificador único, usado pelo label (for) para associaçãoid="email"
placeholderTexto de exemplo exibido dentro do campo vazio (não substitui o label)placeholder="seu@email.com"
requiredTorna o campo obrigatório para enviar o formuláriorequired
valueValor inicial/pré-preenchido do campovalue="0"
disabledDesativa o campo (não editável e não enviado)disabled

Principais valores de type:

ValorUso
textTexto genérico de uma linha
emailE-mail, com validação básica de formato
passwordSenha — o texto digitado é ocultado
numberValores numéricos, com setas de incremento
telTelefone — no celular, exibe teclado numérico
dateData, com seletor de calendário nativo
checkboxCaixa de marcação (sim/não, múltipla escolha independente)
radioOpção única dentro de um grupo (mesmo name em todas as opções do grupo)
fileEnvio de arquivos do dispositivo do usuário
submitBotão que envia o formulário (alternativa ao button type="submit")

Quando usar

  • Escolha o type mais específico possível para o dado — isso melhora a validação automática e o teclado exibido em dispositivos móveis (ex.: email em vez de text para e-mails).
  • Para radio, use o mesmo name em todas as opções do grupo, para que apenas uma seja selecionável por vez.

Exemplo

<label for="email">E-mail</label>
<input type="email" id="email" name="email" required />

<label for="km">Quilometragem</label>
<input type="number" id="km" name="km" min="0" />

<label>
  <input type="checkbox" name="aceite" /> Aceito os termos
</label>

Boas práticas / erros comuns

Fazer

  • Usar o type semanticamente correto para cada dado (email, tel, date, number...)
  • Sempre incluir name, ou o valor não será enviado ao servidor

Evitar

  • Usar type="text" para tudo, ignorando tipos mais específicos e sua validação nativa
  • Esquecer o label associado a cada input
<select>/<option> Formulários

Cria uma lista suspensa de opções, das quais o usuário escolhe uma (ou várias, se configurado).

O que é

select é o contêiner da lista; cada option representa uma alternativa selecionável dentro dele. É a alternativa nativa a um grupo de radio quando há muitas opções — economiza espaço na tela.

Sintaxe genérica

<select id="campo" name="campo">
  <option value="a">Opção A</option>
  <option value="b">Opção B</option>
</select>

Atributos principais

AtributoPara que serveExemplo
nameNome usado para identificar o valor enviado ao servidorname="estado"
multiplePermite selecionar mais de uma opçãomultiple
requiredTorna a seleção obrigatóriarequired
value (em option)Valor enviado ao servidor quando essa opção é escolhidavalue="sc"
selected (em option)Marca essa opção como selecionada por padrãoselected

Quando usar

  • Use quando houver muitas opções (mais de 4-5) e apenas uma (ou poucas) precisar ser selecionada — para poucas opções visíveis, um grupo de radio costuma ser mais claro.
  • Sempre associe um label ao select, assim como faria com um input.

Exemplo

<label for="estado">Estado</label>
<select id="estado" name="estado">
  <option value="">Selecione...</option>
  <option value="sc">Santa Catarina</option>

Fazer

Evitar

  • Usar select para 2-3 opções apenas — nesse caso radio costuma ser mais rápido de usar

Cria um botão clicável — para enviar formulários, disparar ações em JavaScript, ou resetar campos.

É o elemento correto para qualquer ação que não seja navegação (para isso, existe o a). Seu comportamento dentro de um form depende do atributo type.

<table> Tabelas

Elemento raiz que envolve uma tabela de dados — organiza informações em linhas e colunas.

O que é

É o contêiner de toda a estrutura tabular: cabeçalho, corpo e, opcionalmente, rodapé. Uma tabela existe para apresentar dados que têm relação entre linhas e colunas — não deve ser usada para controlar o layout visual da página (isso é papel do CSS).

Sintaxe genérica

<table>
  <thead>...</thead>
  <tbody>...</tbody>
</table>

O table aceita apenas os atributos globais (id, class) — a estilização (bordas, espaçamento) deve ser feita via CSS, não por atributos antigos como border ou cellpadding.

Quando usar

  • Use apenas para dados genuinamente tabulares — comparações, listas de preços, resultados, históricos.
  • Não use table para organizar o layout geral da página (menus, colunas de conteúdo) — para isso, use CSS (grid, flexbox) com div/elementos semânticos.

Exemplo

<table>
  <thead>
    <tr><th>Modelo</th><th>Ano</th><th>Preço</th></tr>
  </thead>

Fazer

  • Reservar tabelas para dados que realmente têm estrutura de linhas/colunas

Evitar

  • Usar tabelas para posicionar elementos de layout na página — prática antiga e problemática para acessibilidade e responsividade
<thead>/<tbody>/<tfoot> Tabelas

Dividem a tabela em cabeçalho, corpo e rodapé — dando estrutura semântica clara a cada parte dos dados.

O que é

thead agrupa a(s) linha(s) de cabeçalho (títulos das colunas); tbody agrupa as linhas de dados propriamente ditas; tfoot agrupa uma linha de rodapé, geralmente usada para totais ou resumos. Uma tabela pode ter várias tbody, mas apenas um thead e um tfoot.

Sintaxe genérica

<table>
  <thead>
    <tr><th>Coluna 1</th><th>Coluna 2</th></tr>
  </thead>
  <tbody>
    <tr><td>Dado 1</td><td>Dado 2</td></tr>
  </tbody>
  <tfoot>
    <tr><td>Total</td><td>100</td></tr>
  </tfoot>
</table>

Atributos principais

Nenhum dos três possui atributos próprios além dos globais (id, class).

Quando usar

  • Use thead sempre que a tabela tiver uma linha de títulos de coluna — isso ajuda leitores de tela a anunciar o cabeçalho ao navegar pelas células.
  • Use tfoot apenas quando houver uma linha de resumo/total real — não é obrigatório em toda tabela.

Exemplo

<table>
  <thead>
    <tr><th>Mês</th><th>Vendas</th></tr>
  </thead>
  <tbody>
    <tr><td>Janeiro</td><td>12</td></tr>
    <tr><td>Fevereiro</td><td>15</td></tr>
  </tbody>
  <tfoot>
    <tr><td>Total</td><td>27</td></tr>
  </tfoot>
</table>

Boas práticas / erros comuns

Fazer

  • Sempre envolver as linhas de dados em tbody, mesmo em tabelas simples

Evitar

  • Colocar linhas de dados soltas, direto dentro de table, sem tbody

Representam, respectivamente, uma linha da tabela, uma célula de cabeçalho e uma célula de dado comum.

O que é

tr ("table row") é cada linha da tabela. Dentro dela, th ("table header") marca uma célula como título de coluna ou linha, e td ("table data") marca uma célula de dado comum. A diferença não é só visual: th tem significado semântico de cabeçalho, associando aquela célula às demais da coluna/linha para leitores de tela.

Sintaxe genérica

<tr>
  <th>Título da coluna</th>
  <td>Valor da célula</td>
</tr>

      <td>R$ 89.000</td>
    </tr>

Fazer

  • Usar scope="col"/scope="row" em th, especialmente em tabelas com cabeçalhos em ambas as direções

Evitar

  • Usar td em negrito via CSS só para "parecer" um cabeçalho, em vez de usar th de verdade
  • Deixar uma linha com número de células diferente das demais, sem usar colspan para justificar a diferença
<blockquote> Citação & código

Marca uma citação longa, retirada de outra fonte — geralmente exibida com recuo em relação ao texto normal.

O que é

Representa um trecho de texto citado de outro documento ou pessoa, quando a citação ocupa um bloco inteiro (um ou mais parágrafos), e não apenas uma frase em meio ao texto corrido — nesse caso o elemento correto é o q.

Sintaxe genérica

<blockquote>
  <p>Texto citado aqui.</p>
</blockquote>

AtributoPara que serveExemplo
citeURL da fonte original da citação (não exibida visualmente, é metadado)cite="https://exemplo.com/artigo"

  • Use para reproduzir um trecho de texto de outra fonte, com ou sem indicação visual de aspas.
  • Para indicar quem disse a frase, combine com o elemento cite, geralmente logo após o blockquote.
  • Não use blockquote apenas para recuar um parágrafo visualmente sem que o conteúdo seja de fato uma citação — para isso, use CSS.

Exemplo

</blockquote>

Boas práticas / erros comuns

Fazer

  • Usar blockquote apenas para conteúdo genuinamente citado de outra fonte

Evitar

  • Usar blockquote só pelo efeito visual de recuo, sem que o texto seja uma citação real

O que é

É a versão "em linha" do blockquote: usada quando a citação é curta o suficiente para ficar no meio de uma frase, sem quebrar o parágrafo. O navegador insere as aspas visualmente — você não precisa digitá-las no HTML.

AtributoPara que serveExemplo

  • Use para citações curtas dentro de uma frase — não digite as aspas manualmente, deixe o navegador inseri-las.
  • Para citações longas (parágrafos inteiros), use blockquote em vez de q.

Exemplo

<p>O vendedor afirmou que o carro <q>está em perfeito estado</q>.</p>

Fazer

  • Deixar o navegador inserir as aspas — não digitá-las manualmente dentro do q

Evitar

<cite> Citação & código

Marca o título de uma obra ou o nome de uma fonte referenciada — um livro, um artigo, uma peça, um autor citado.

O que é

Representa a referência à fonte de uma citação ou obra — geralmente exibido em itálico por padrão. É comum aparecer ao lado de um blockquote ou q, indicando de onde veio o trecho citado.

Sintaxe genérica

<p>Como descrito em <cite>Manual do Proprietário</cite>.</p>

Atributos principais

Aceita apenas os atributos globais (id, class).

Quando usar

  • Use para o título de uma obra (livro, filme, artigo, música) ou o nome de quem está sendo citado.
  • Não use cite para o texto da citação em si — isso é papel do blockquote/q; o cite é só a referência à fonte.

Exemplo

<blockquote>
  <p>A simplicidade é o último grau de sofisticação.</p>
</blockquote>

Fazer

  • Usar cite apenas para o nome da fonte/obra, não para o texto citado inteiro

Evitar

  • Confundir cite (referência) com o atributo cite do blockquote/q (URL da fonte) — são coisas diferentes com o mesmo nome
<code>/<pre> Citação & código

Marcam trechos de código-fonte — code para um trecho em linha, pre para preservar a formatação (espaços e quebras de linha) de um bloco inteiro.

O que é

code sozinho exibe um trecho curto de código no meio do texto, com fonte monoespaçada. pre ("preformatted") preserva exatamente os espaços, tabulações e quebras de linha do conteúdo — por padrão, o navegador ignora espaços extras e quebras de linha em qualquer outro elemento. Juntos (pre>code), formam a forma padrão de exibir um bloco de código.

Sintaxe genérica

Em linha: <code>const x = 1;</code>

Em bloco:
<pre><code>function soma(a, b) {
  return a + b;
}</code></pre>

Atributos principais

Nenhum dos dois possui atributos próprios além dos globais (id, class) — a linguagem do código, quando indicada, costuma ir em uma class convencionada por alguma ferramenta de destaque de sintaxe (ex.: class="language-js").

Quando usar

  • Use code sozinho para nomes de variáveis, comandos ou trechos curtos mencionados no meio do texto.
  • Use pre>code juntos para blocos de código completos, preservando indentação e quebras de linha.

Exemplo

<p>Use a variável <code>precoTotal</code> para calcular o valor final.</p>

<pre><code>let precoTotal = precoBase + taxa;
console.log(precoTotal);</code></pre>

Boas práticas / erros comuns

Fazer

  • Usar pre>code juntos para blocos de código, e code sozinho para menções pontuais

Evitar

  • Usar pre sem code dentro (o significado semântico de "isto é código" se perde)
  • Tentar formatar código com múltiplos <br> e espaços em branco (&nbsp;) em vez de pre

Fazer

<mark> Elementos adicionais

O que é

Indica que aquele trecho é relevante para a situação específica em que aparece — por exemplo, os termos de busca destacados dentro de um resultado, ou um ponto-chave em um trecho copiado de outro lugar. Não deve ser confundido com strong (importância geral do conteúdo).

  • Se o destaque é apenas estético, sem relação com relevância contextual, use span com CSS em vez de mark.

Exemplo

<p>Encontramos 3 resultados para "<mark>sedan automático</mark>".</p>

Boas práticas / erros comuns

Fazer

  • Reservar mark para relevância contextual real (resultados de busca, trechos citados de interesse)

Evitar

  • Usar mark apenas como sinônimo estilístico de "fundo colorido" sem relação com relevância
class / id Atributos globais

Os dois atributos mais usados de qualquer elemento HTML — identificam elementos para aplicar CSS ou manipular via JavaScript.

O que é

class é reutilizável: vários elementos podem compartilhar a mesma classe, e um mesmo elemento pode ter várias classes separadas por espaço. id é único: só pode existir um elemento com determinado id em toda a página, e é usado tanto para âncoras (href="#id") quanto para associar rótulos (label for) e selecionar via JS.

Sintaxe genérica

<div class="cartao destaque" id="produto-42">...</div>

AtributoPara que serveExemplo
classAplica um ou mais estilos CSS reutilizáveis; um elemento pode ter várias classesclass="cartao destaque"
idIdentifica um único elemento na página, para âncoras, formulários ou JSid="produto-42"

Quando usar

  • Use class sempre que o estilo/comportamento se repetir em mais de um elemento.
  • Use id quando precisar de uma referência única — um alvo de âncora, a associação de um label, ou um elemento específico manipulado via JS.

Exemplo

<nav>
  <a href="#estoque">Estoque</a>
</nav>

  <div class="cartao-produto destaque">...</div>
</section>

Boas práticas / erros comuns

Fazer

  • Usar nomes de classe descritivos do papel do elemento, não da aparência (cartao-produto, não caixa-azul)

Evitar

  • Repetir o mesmo id em mais de um elemento na página — isso quebra âncoras, formulários e seletores JS que dependem de unicidade

Permite armazenar dados customizados diretamente em um elemento HTML, para serem lidos e usados via JavaScript.

O que é

É um "prefixo livre": qualquer atributo que comece com data- é válido e não afeta a exibição da página. Serve para guardar informações que o JavaScript vai ler depois — como o ID de um produto, um estado, ou uma configuração associada àquele elemento.

Sintaxe genérica

<div data-produto-id="42" data-categoria="sedan">...</div>

Atributos principais

Não há uma lista fixa — o nome depois de data- é definido livremente por quem escreve o código, de acordo com a necessidade do projeto.

Quando usar

  • Use para guardar dados que o JavaScript vai consumir (ex.: o ID de um item em um card, para filtrar ou favoritar).
  • Não use data-* para guardar informação que deveria estar visível ao usuário — isso é conteúdo, não metadado.

Exemplo

<article class="cartao-produto" data-produto-id="42" data-categoria="sedan">
  <h3>Sedan XT</h3>
</article>

<script>
  const cartao = document.querySelector('.cartao-produto');
  console.log(cartao.dataset.produtoId); // "42"
</script>

Boas práticas / erros comuns

Fazer

  • Usar nomes descritivos após o data-, em minúsculas e com hífen (data-produto-id)

Evitar

  • Armazenar dados sensíveis em data-* — o atributo fica visível no HTML enviado ao navegador, então qualquer pessoa pode inspecioná-lo
aria-* Atributos globais

Complementam o HTML com informações de acessibilidade para leitores de tela, quando a semântica nativa não é suficiente.

O que é

Fazem parte do padrão WAI-ARIA. Servem para descrever papel, estado e propriedades de um elemento a tecnologias assistivas — especialmente úteis quando você constrói componentes de interface (menus, abas, modais) que não têm um elemento HTML nativo equivalente.

Sintaxe genérica

<button aria-label="Fechar" aria-expanded="false">×</button>

Atributos principais

AtributoPara que serveExemplo
aria-labelFornece um texto acessível quando não há texto visível suficiente (ex.: um botão só com ícone)aria-label="Fechar modal"
aria-hiddenEsconde o elemento de leitores de tela, mesmo que continue visível (ex.: ícones puramente decorativos)aria-hidden="true"
aria-expandedIndica se um componente expansível (menu, accordion) está aberto ou fechadoaria-expanded="true"
aria-describedbyAssocia um elemento a um texto de descrição adicional, pelo id desse textoaria-describedby="ajuda-senha"

Quando usar

  • Use quando um elemento HTML nativo já resolveria o problema semântico — a primeira regra do ARIA é "não use ARIA se um elemento HTML nativo já faz o trabalho" (prefira button a div role="button").
  • Use aria-label em botões/links que só têm ícone, sem texto visível.
  • Use aria-expanded/aria-hidden em componentes interativos personalizados (menus, modais, accordions feitos com JS).

Exemplo

<button aria-label="Abrir menu" aria-expanded="false">
  ☰
</button>

Boas práticas / erros comuns

Fazer

  • Preferir sempre o elemento HTML semântico nativo antes de recorrer a atributos ARIA

Evitar

  • Usar ARIA para "consertar" uma estrutura HTML que deveria simplesmente usar a tag correta
  • Declarar um aria-expanded ou aria-hidden e esquecer de atualizá-lo dinamicamente via JS quando o estado muda
tabindex Atributos globais

Controla se um elemento pode receber foco pelo teclado (tecla Tab) e em que ordem, dentro da navegação da página.

O que é

Elementos interativos nativos (a, button, input) já recebem foco automaticamente. O tabindex permite alterar esse comportamento — tornar focável um elemento que normalmente não seria, ou remover um elemento da navegação por Tab.

Sintaxe genérica

<div tabindex="0">Agora esse div pode receber foco</div>

Atributos principais

ValorEfeito
tabindex="0"Torna o elemento focável, seguindo a ordem natural do documento
tabindex="-1"Torna o elemento focável apenas via JavaScript (não pelo Tab), útil para mover o foco programaticamente
tabindex positivo (ex.: 1)Define uma ordem manual de foco — geralmente desaconselhado

Quando usar

  • Use tabindex="0" apenas quando precisar tornar focável um elemento não interativo por natureza (raro — normalmente prefira button/a nativos).
  • Use tabindex="-1" para mover o foco via JS para um elemento (ex.: título de uma seção após navegação), sem incluí-lo na ordem normal do Tab.

Exemplo

<div class="cartao-clicavel" role="button" tabindex="0">
  Ver detalhes
</div>

Boas práticas / erros comuns

Fazer

  • Preferir elementos nativamente focáveis (button, a) em vez de adicionar tabindex a uma div

Evitar

  • Usar valores positivos de tabindex para forçar uma ordem manual — isso costuma confundir a navegação por teclado e é considerado má prática

Nota: sempre que possível, resolva a acessibilidade usando o elemento HTML correto (button, a) em vez de recriar o comportamento com div + tabindex + aria-*.

<picture>/<source> Elementos avançados

Permite servir versões diferentes de uma imagem dependendo do tamanho da tela ou do formato suportado pelo navegador.

O que é

picture envolve várias tags source, cada uma apontando para uma versão diferente da imagem, e um img obrigatório como último filho (usado como alternativa, caso nenhum source se aplique). O navegador escolhe automaticamente qual source usar, com base nas condições declaradas.

Sintaxe genérica

<picture>
  <source srcset="imagem-grande.jpg" media="(min-width: 800px)" />
  <img src="imagem-pequena.jpg" alt="Descrição" />
</picture>

Atributos principais

AtributoPara que serveExemplo
srcset (em source)Arquivo de imagem a ser usado por esse sourcesrcset="foto-hd.webp"
media (em source)Condição de largura de tela para esse source ser escolhidomedia="(min-width: 1024px)"
type (em source)Formato do arquivo, para o navegador escolher o primeiro que suportartype="image/webp"

Quando usar

  • Use quando quiser servir imagens diferentes conforme o tamanho de tela (evitando baixar uma imagem grande desnecessariamente no celular).
  • Use também para oferecer formatos modernos (como webp) com fallback automático para formatos mais antigos (jpg/png) via img.
  • O img dentro do picture continua obrigatório — ele carrega o alt e serve de alternativa final.

Exemplo

<picture>
  <source srcset="sedan-xt-mobile.webp" media="(max-width: 600px)" type="image/webp" />
  <source srcset="sedan-xt-desktop.webp" type="image/webp" />
  <img src="sedan-xt.jpg" alt="Sedan XT prata visto de frente" />
</picture>

Boas práticas / erros comuns

Fazer

  • Sempre incluir um img com alt como último filho, garantindo compatibilidade e acessibilidade

Evitar

  • Usar picture apenas para redimensionar visualmente uma imagem — isso é papel do CSS; picture serve para servir arquivos diferentes de fato
<canvas> Elementos avançados

Cria uma área em branco na página onde é possível desenhar gráficos, formas, imagens e animações via JavaScript.

O que é

Diferente de uma imagem estática, o canvas é uma "tela" vazia por padrão — todo o conteúdo visual dentro dele é desenhado dinamicamente por código (normalmente usando a API CanvasRenderingContext2D ou WebGL). Sem JavaScript, o canvas aparece vazio.

Sintaxe genérica

<canvas id="grafico" width="400" height="200"></canvas>

Atributos principais

AtributoPara que serveExemplo
widthLargura da área de desenho, em pixels (não confundir com largura via CSS)width="400"
heightAltura da área de desenho, em pixelsheight="200"

Quando usar

  • Use para gráficos gerados dinamicamente, jogos simples, editores de desenho ou visualizações de dados que exigem controle pixel a pixel.
  • Se o gráfico é estático (uma imagem só, sem interação), um img ou SVG é mais simples e mais acessível do que um canvas.

Exemplo

<canvas id="grafico-vendas" width="400" height="200"></canvas>

<script>
  const ctx = document.getElementById('grafico-vendas').getContext('2d');
  ctx.fillStyle = '#1a1a1a';
  ctx.fillRect(10, 10, 100, 150);
</script>

Boas práticas / erros comuns

Fazer

  • Definir width/height como atributos do próprio canvas, não apenas via CSS (evita distorção do desenho)

Evitar

  • Usar canvas para conteúdo que poderia ser uma imagem estática ou SVG — o conteúdo do canvas não é acessível a leitores de tela por padrão

Nota: o conteúdo desenhado dentro de um canvas não é lido por leitores de tela — se a informação for essencial, ofereça uma alternativa textual (ex.: uma tabela com os mesmos dados do gráfico).

<map>/<area> Elementos avançados

Transforma regiões específicas de uma imagem em links clicáveis — um "mapa de imagem", com cada área levando a um destino diferente.

O que é

map define o conjunto de áreas clicáveis, associado a uma imagem através do atributo usemap no img. Cada area dentro do map descreve uma forma geométrica (retângulo, círculo, polígono) e o link correspondente àquela região.

Sintaxe genérica

<img src="planta.jpg" usemap="#mapa-planta" alt="Planta do imóvel" />

<map name="mapa-planta">
  <area shape="rect" coords="0,0,100,100" href="#sala" alt="Sala" />
</map>

Atributos principais

AtributoPara que serveExemplo
name (em map)Nome que conecta o map ao usemap da imagemname="mapa-planta"
shape (em area)Formato da região clicável: rect, circle ou polyshape="circle"
coords (em area)Coordenadas em pixels que definem a posição/tamanho da região, de acordo com o shapecoords="50,50,30"
href (em area)Destino do link para aquela regiãohref="#quarto-1"
alt (em area)Texto alternativo da região, para acessibilidadealt="Quarto principal"

Quando usar

  • Use quando precisar que diferentes partes de uma única imagem levem a destinos diferentes — plantas de imóveis, mapas geográficos, diagramas interativos.
  • Se as áreas clicáveis puderem ser blocos retangulares simples sobre a imagem, considere alternativas mais modernas com CSS (posicionamento absoluto sobre a imagem) antes de recorrer a map/area.

Exemplo

<img src="planta-casa.jpg" usemap="#mapa-casa" alt="Planta baixa da casa" />

<map name="mapa-casa">
  <area shape="rect" coords="0,0,200,150" href="#sala" alt="Sala de estar" />
  <area shape="rect" coords="200,0,400,150" href="#cozinha" alt="Cozinha" />
</map>

Boas práticas / erros comuns

Fazer

  • Sempre incluir alt em cada area, descrevendo a região

Evitar

  • Calcular as coordenadas manualmente sem testar — regiões mal calibradas quebram a usabilidade do mapa
<template> Elementos avançados

Guarda um trecho de HTML que não é renderizado na página até ser clonado e inserido via JavaScript — um "molde" reutilizável.

O que é

Todo o conteúdo dentro de um template fica inerte: imagens não carregam, scripts não executam, e nada aparece na tela. Ele só ganha vida quando o JavaScript acessa .content, clona esse conteúdo e o insere em outro lugar do documento — útil para gerar repetidamente a mesma estrutura (ex.: um item de lista) sem duplicar HTML manualmente.

Sintaxe genérica

<template id="modelo-item">
  <li class="item"></li>
</template>

Atributos principais

Aceita apenas os atributos globais (id, class) — o id costuma ser usado para localizar o modelo via JavaScript.

Quando usar

  • Use quando precisar criar repetidamente o mesmo bloco de HTML via JavaScript (itens de uma lista carregada dinamicamente, linhas de uma tabela, cards de produto).
  • Evita a prática de montar HTML como texto concatenado em JS ("<li>" + item + "</li>"), que é mais propensa a erros.

Exemplo

<template id="modelo-produto">
  <article class="cartao-produto">
    <h3></h3>
    <p class="preco"></p>
  </article>
</template>

<script>
  const modelo = document.getElementById('modelo-produto');
  const clone = modelo.content.cloneNode(true);
  clone.querySelector('h3').textContent = 'Sedan XT';
  document.querySelector('.grade-produtos').appendChild(clone);
</script>

Boas práticas / erros comuns

Fazer

  • Usar template para qualquer estrutura repetida que será populada dinamicamente via JS

Evitar

  • Esperar que o conteúdo do template apareça sozinho na página — ele precisa ser explicitamente clonado e inserido via JavaScript
