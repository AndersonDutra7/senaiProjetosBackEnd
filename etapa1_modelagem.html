ETAPA 1.1 — LEITURA DO DESAFIO E ARQUITETURA
1. LEVANTAMENTO DAS REGRAS DE NEGÓCIO
  • RN01 – Gestão Unificada de Usuários: O sistema deve permitir o cadastro e gerenciamento tanto dos funcionários migrados do protótipo quanto dos novos clientes externos.
  • RN02 – Registro de Práticas Esportivas: Cada usuário pode registrar suas atividades informando tipo de exercício, distância (km), duração (minutos), data e uma descrição opcional.
  • RN03 – Arquitetura Dinâmica (SPA): A interface deve permitir a interação do usuário, listagem e persistência de dados sem necessidade de recarregar a página.
  • RN04 – Interatividade Social: Permite que os usuários curtam e comentem nas atividades publicadas. Cada usuário pode dar no máximo uma curtida por atividade.
  • RN05 – Migração e Integridade Legada: Importação obrigatória dos arquivos usuarios.csv e atividades.csv para o banco relacional sem perda do histórico.
  • RN06 – Padrão Visual Estrito: Uso exclusivo da fonte Segoe UI e da paleta homologada (#FFFFFF, #000000, #333333, #483DAD e #FF0000).
2. DEFINIÇÃO DA ARQUITETURA DA SOLUÇÃO

A aplicação adota uma arquitetura em 3 Camadas (3-Tier Architecture) para garantir escalabilidade, integridade das regras de negócio e facilidade na manutenção contínua:

Camada Tecnologia Função na Solução SAEPSaúde
Apresentação (Frontend) HTML5, CSS3, JavaScript (Vanilla ES6+) Interface Single Page Application (SPA). Faz a renderização dinâmica, consumo da API REST via fetch() e aplicação dos padrões visuais da marca.
Negócio (Backend) Node.js + Express.js Provedor de API RESTful. Responsável pela autenticação, validação dos dados de entrada, rotas de curtidas/comentários e regra de negócio.
Dados (Persistence) PostgreSQL Banco de dados relacional. Mantém a integridade referencial via Chaves Primárias e Estrangeiras e executa a carga inicial dos CSVs.

3. SCRIPT SQL DDL — CRIAÇÃO DO BANCO DE DADOS (POSTGRESQL)
-- 1. Tabela de Usuários (Funcionários + Clientes)
CREATE TABLE usuarios (
    id SERIAL PRIMARY KEY,
    nome VARCHAR(150) NOT NULL,
    email VARCHAR(150) UNIQUE NOT NULL,
    tipo_usuario VARCHAR(20) NOT NULL CHECK (tipo_usuario IN ('funcionario', 'cliente')),
    data_cadastro DATE DEFAULT CURRENT_DATE
);

-- 2. Tabela de Atividades
CREATE TABLE atividades (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER NOT NULL REFERENCES usuarios(id) ON DELETE CASCADE,
    tipo_atividade VARCHAR(50) NOT NULL,
    distancia_km NUMERIC(5,2) DEFAULT 0.00,
    duracao_min INTEGER NOT NULL,
    data_atividade DATE NOT NULL,
    descricao TEXT
);

-- 3. Tabela de Curtidas
CREATE TABLE curtidas (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER NOT NULL REFERENCES usuarios(id) ON DELETE CASCADE,
    atividade_id INTEGER NOT NULL REFERENCES atividades(id) ON DELETE CASCADE,
    data_curtida TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_usuario_atividade_curtida UNIQUE (usuario_id, atividade_id)
);

-- 4. Tabela de Comentários
CREATE TABLE comentarios (
    id SERIAL PRIMARY KEY,
    usuario_id INTEGER NOT NULL REFERENCES usuarios(id) ON DELETE CASCADE,
    atividade_id INTEGER NOT NULL REFERENCES atividades(id) ON DELETE CASCADE,
    texto TEXT NOT NULL,
    data_comentario TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
