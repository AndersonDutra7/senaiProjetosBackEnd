01

Setup do Projeto

~10 min

1. Sua arquitetura está correta — use exatamente essa

Para uma prova offline de 3 horas, essa é a estrutura mais simples possível que ainda atende 100% do enunciado. Não adicione TypeScript, build tools, frameworks de frontend (React/Vue) ou ORMs (Prisma/Sequelize) — cada camada extra é tempo que você não tem. pg puro com queries SQL diretas é mais rápido de escrever e de debugar sob pressão. 

saepvision/
├── node_modules/
├── public/
│   ├── assets/         // ícones fornecidos: coracao.svg, lupa.svg, lixeira.svg, instagram.svg...
│   ├── uploads/         // pasta vazia — onde o multer vai salvar as fotos enviadas
│   ├── index.html
│   ├── style.css
│   └── app.js
├── package.json
├── schema.sql
└── server.js

2. Comandos iniciais (rodar em ordem)

Copie e cole no terminal, dentro da pasta do projeto. 

# inicializa o projeto
npm init -y

# dependências mínimas: servidor, banco, upload de imagem
npm install express pg multer

# pastas que o Express/multer vão precisar
mkdir public
mkdir public/assets
mkdir public/uploads
Decisão que economiza tempo: não implemente login com sessão de servidor (express-session) nem hash de senha (bcrypt). Como o enunciado não exige recarregar a página, guarde o usuário logado em uma variável no app.js (memória do navegador) e envie o usuario_id junto de cada requisição que precisar dele (curtir, cadastrar, ver perfil). Isso ainda atende 100% da especificação funcional e corta ~30 minutos de implementação.
